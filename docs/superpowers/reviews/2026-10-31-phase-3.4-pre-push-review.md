The plan's text was departed from in two places. Both are documented.

- **Info: `ZeroAllocAuthorizationDisableBundledAnalyzer` in the Sentinel csproj.**
  - AI.Sentinel's dependency on ZeroAlloc.Authorization carries `exclude="Analyzers"`, but the bundled generator from that package still reaches this project transitively. Without the switch, it would add a public `GeneratedAuthorizationRegistration` to this package's API, where it would collide with a host's own generated registration.
  - The switch is the package's own documented opt-out, not a suppressed warning. The upstream fix is tracked as ZeroAlloc-Net/ZeroAlloc.Authorization#181.
- **Info: plan Review Focus #2 assumed a host could register only a named AI.Sentinel pipeline. AI.Sentinel 4.1.1 does not support that.**
  - Its README requires the default pipeline as well, because the shared detector pool resolves the unkeyed `SentinelOptions`.
  - The test therefore registers the default pipeline with SEC-02 off, plus the named pipeline, together with a reverse test.
  - The package README states the requirement.

The final review also changed the docs and added tests.

- A detector that throws is skipped by AI.Sentinel and counts as clean, so it does not fail closed. The README and the XML remarks now say so, a test pins the current behaviour, and the upstream gap is tracked as MarcelRoozekrans/AI.Sentinel#550.
- AI.Sentinel rates email, phone and date of birth as Medium. At the default High threshold they pass. This is documented, and tests cover both thresholds.
