# Phase 4.1 Design — Test and sample hygiene

**Date:** 2026-11-06
**Phase:** 4.1
**Surface:** Refactor
**Stage:** phase (one phase, implementation-ready)
**Status:** approved 2026-11-06

## Goal

Close #55 and #57: one shared copy of the PostgreSQL test stubs, and one shared copy of the sample self-check runner, so a fix is made once.

## Approach

**#55, test stubs.** Add `tests/Mnemosyne.NET.PostgreSql.Tests/Stubs.cs` with an internal `ScriptedModel` and an internal `ConstantEmbeddings`. Five classes carry a private `ConstantEmbeddings` with the same vector `[1, 0.5, -0.25]`: `AgentContextProviderTests`, `CaptureGuardTests`, `TelemetryTests`, `TranscriptCaptureTests`, `UseReasonletsTests`. Two carry a `ScriptedModel`: `AgentContextProviderTests` records each request's `ChatOptions.Instructions`, `UseReasonletsTests` records each request's messages. The shared `ScriptedModel` records both, with `Requests` and `Instructions` lists, and keeps the `Script` array and the reset after a plain-text answer. The classes delete their private copies and use the shared ones. Test behaviour does not change.

**#57, sample runner.** Add `samples/Shared/SampleRunner.cs`: the `SampleFailure` exception, `Require`, `RequireEqual`, `RequireSuccess`, `TryEraseAsync`, `EraseAfterAsync`, and a `RunAsync` entry that holds the main try and catches. It prints `FAILED:` to stderr and returns exit code 1 and enforces the 2 minute cap. `EraseAfterAsync` runs a walkthrough and erases the scope in its finally. Each of the four samples links the file the way it links `ScriptedChatClient` and drops its own copy.

Decisions the user took: an unreachable or failing database ends as `FAILED:` with exit 1, in all four samples; and a capture timeout names the run or act in all four, as the Agent Framework and chat pipeline samples already do.

The runner's contract: `RunAsync` takes a body delegate that receives a cancellation token and returns the exit code. Each sample builds its own memory and scope inside the body, after its setup, and keeps its own checks. It then passes the memory, the scope and its walkthrough to `EraseAfterAsync`, which erases the scope in its finally.

## Files / Modules Touched

- `tests/Mnemosyne.NET.PostgreSql.Tests/Stubs.cs` — new, shared `ScriptedModel` and `ConstantEmbeddings`
- `tests/Mnemosyne.NET.PostgreSql.Tests/{AgentContextProviderTests,CaptureGuardTests,TelemetryTests,TranscriptCaptureTests,UseReasonletsTests}.cs` — drop private stubs
- `samples/Shared/SampleRunner.cs` — new
- `samples/Mnemosyne.Samples.{StoreAndRecall,Evaluation,ChatPipeline,AgentFramework}/Program.cs` and `.csproj` — use the runner, link the file
- `tests/Mnemosyne.NET.Tests` — a unit test of the runner next to the existing tests of `ScriptedChatClient` and `CaptureRunWatcher`, under `Samples`

## Tests

- Unit: the runner returns 0 on success, 1 and `FAILED:` on a `SampleFailure`, on a timeout, on a database exception, and erases in every case; a failing erase does not hide the original failure.
- Integration: the PostgreSQL test project passes unchanged with the shared stubs, run by its test exe class by class, since `--filter` is refused.
- Regression: the four samples run in CI and still pass; run one locally if Docker is available, otherwise rely on CI and say so.

## Open Questions

- None.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Shared `ScriptedModel` changes what a test sees | A test passes for the wrong reason | Keep the call-id and reset logic byte for byte; run all five classes |
| Samples are AOT or trim sensitive | Runner reflection breaks them | The runner uses no reflection; CI builds the samples |
| Exit code change surprises a CI step | Red CI where it was a crash before | A crash already failed CI; the new exit is 1 with a message |
