# Phase 4.5 Design — Docs completeness

**Date:** 2026-11-06
**Phase:** 4.5
**Surface:** Docs
**Stage:** phase (one phase, implementation-ready)
**Status:** approved 2026-11-06

**Builds on:** Phase 4.2 — `LineageId` (`required ReasonletId`) on `ReasonletCandidate` and `ReasonletMatch`, and the test-only `LineageVariantSelector`. Phase 4.4 — `docs/concepts/compatibility.md`, which the overview and the variants page may link.

## Goal

The docsite explains the whole model for a reader who has not seen the code: one overview page with the package map, a variants page that says what 1.0 already supports and what comes after, and a guide for hosts such as Daedalus and Thalos. This closes the milestone 4 criterion "The docsite is complete: concepts, the variants vision, the Daedalus and Thalos guide".

## Why

The docsite grew phase by phase. Today `index.md` explains the loop, and five concept pages and nine guides each cover one part. Nothing ties the packages together, nothing mentions variants, and Daedalus and Thalos do not appear. The roadmap promises that 1.0 makes the whole idea clear, variants included, so that variants are an addition and not a redesign.

## Approaches considered

| Decision | Choice | Rejected |
|---|---|---|
| Host guide scope | **The contract from our side.** What a host needs from Mnemosyne: install order, the Agent Framework provider, a scope and subject per agent, the capture and review gate, the lifecycle. Daedalus and Thalos are named as the two reference hosts with links, and no code that lives only in their unmerged PRs is described. By the user. | A full wiring walkthrough per host (goes stale with the host repos); a generic guide with no product names (weak against the roadmap title). |
| Variants page | **A concept page with a 1.0 / post-1.0 split.** What a variant is, what 1.0 ships (versions, `LineageId`, the selector seam), what is post-1.0 (a selection strategy, exploration), the post-1.0 parts in a marked admonition with no promised API names. By the user. | Fold into `versions.md` (buries the vision); a roadmap-style page with sketched interfaces (readers take unfrozen names as promises right before the freeze). |
| Overview | **Add `concepts/overview.md`** with the package map, the flow of one call through the packages, and a start-here table. By the user. | Extend `index.md` only. |

## The pieces

Three new pages and edits to three existing ones. Prose follows the repository's style, concrete first and limits last, and the `anti-slop` skill runs on every page.

1. **`docs/concepts/overview.md`** (`sidebar_position: 0`, so it leads the concepts folder).
   - A table of the six packages (`Mnemosyne.NET.Abstractions`, `Mnemosyne.NET`, `Mnemosyne.NET.PostgreSql`, `Mnemosyne.NET.Minos`, `Mnemosyne.NET.Sentinel`, `Mnemosyne.NET.AgentFramework`): what each holds and when a host references it.
   - One Mermaid diagram of a call through the packages: recall, the host's run, capture, the guard, the store, evaluation. It uses names that exist today.
   - A start-here table: a goal ("recall in a chat app", "judge runs", "scope per tenant", "erase a person") mapped to the concept page and the guide.
2. **`docs/concepts/variants.md`.**
   - What a variant is: a sibling version of a procedure that answers the same question another way. The lineage groups them; `LineageId` names the group on every candidate and match.
   - Ships in 1.0: versions with parent links, a lineage id on every recall result, version labels documented as opaque, results that can grow, and the selector seam (`IReasonletSelector`) with the default ranking selector.
   - Post-1.0 in an admonition marked as not part of 1.0: a selection strategy that chooses between siblings, and exploration of new versions before the best one dominates. No interface names, because they are not frozen.
   - A short "what you can do today" with `LineageId`, for a host that wants to group results itself. It links `versions.md`, `ranking.md` and `compatibility.md`.
3. **`docs/guides/daedalus-and-thalos.md`.**
   - Who the two hosts are, in a sentence each with a link, and that Mnemosyne never executes a procedure: the host decides how to run it.
   - What a host wires, in order: store, embeddings, `AddMnemosyne`, capture, the Agent Framework provider with a `ScopeResolver`, then the review gate and the lifecycle jobs. It links the existing guides for each step instead of repeating them.
   - How the two reference hosts map onto it: the Daedalus wiring and the Thalos adapter live in those repos, the Thalos adapter sources the provider through its `IAgentContextProviderSource`, and the packages here are what they reference. The page states the contract the packages offer; it quotes no host code.
   - A checklist for a new host: scope and subject per run, a judge, a capture guard, retention, telemetry, erasure.
4. **Edits:** `docs/index.md` gains a link to the overview and the package table is not duplicated there; `docs/getting-started.md` gets a "where next" pointer to the overview; `docs/concepts/versions.md` links the variants page.

## Files / Modules Touched

- Create `docs/concepts/overview.md`, `docs/concepts/variants.md`, `docs/guides/daedalus-and-thalos.md`.
- Modify `docs/index.md`, `docs/getting-started.md`, `docs/concepts/versions.md`.
- No code, no package change, no sample.

## Tests

- The docsite build is the test: `npm run build` uses `onBrokenLinks: 'throw'` and `onBrokenAnchors: 'throw'`, so a bad link or anchor fails it.
- A fact check of every claim about the code against the source and the existing guides: package names, type names, the `LineageId` property, the selector interface. No page names a type that does not exist.
- The Daedalus and Thalos statements are checked against those repos' public READMEs, and anything unconfirmed is dropped or phrased as "see the host's repository".

## Anti-goals

- **A promise of an API that is not frozen.** The post-1.0 part names no interface and sets no date.
- **A guide that drifts from the host repos.** It describes the contract here and links out for the wiring.

## Open Questions

- None. The Thalos adapter's exact interface name is confirmed from its README in the plan's first task, not assumed.
