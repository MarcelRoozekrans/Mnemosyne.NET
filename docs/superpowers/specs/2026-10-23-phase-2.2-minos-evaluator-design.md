# Phase 2.2 Design: Minos.NET evaluator

**Date:** 2026-10-23
**Phase:** 2.2
**Surface:** Backend
**Stage:** phase (one phase, implementation-ready)

This phase builds on the [phase 2.1 evaluator contract](2026-10-23-phase-2.1-evaluator-contract-design.md). Decisions are marked **user** or **my call**.

## Goal

Ship the default `IReasonletEvaluator`. It judges a run through Minos.NET, the user's client for decision models. Minos asks typed questions and gets calibrated probabilities back, so no free-text reply needs parsing (**user**: Minos first, and the chat-model judge moves to phase 2.3).

## Non-goals

- **The `IChatClient` judge.** It is phase 2.3.
- **Choosing or configuring a decision-model provider.** The host does that with Minos.NET's own packages, such as `Minos.NET.SystemOne` (TypeSafe, OpenRouter or a server you run) or `Minos.NET.OpenAI`.
- **Calibration datasets and threshold tuning tools.** Minos.NET.Evaluation and its `minos calibrate` tool already cover these, and the docs point to them.

## Approach

### What the judge asks (user)

The judge asks one Noul:

> Does the answer resolve the question by following the procedure?

- **Score.** `ReasonletEvaluation.Score` is the Noul's `Probability`.
- **Success.** `ReasonletEvaluation.Success` is `Probability >= SuccessThreshold`. The default threshold is 0.5, the same as Minos's own `Noul.Value` (**my call**).
- **Evaluator name.** It is the configured `EvaluatorName`, default `minos`.

The question set is a `[Questions]` record in the new package, so Minos's source generator writes the request and the parsing at compile time, and the package stays AOT-safe.

### What the judge sees (my call)

The state is a typed JSON object, passed through `EvaluateAsync<T, TState>` with a source-generated `JsonTypeInfo`, which keeps it AOT-safe. It has these fields:

| Field | Value |
|---|---|
| `question` | the run's question |
| `intent` | the Reasonlet's intent |
| `procedure` | the procedure graph as its canonical JSON (`ReasonletGraphJson.Serialize`), nested as a JSON value (`JsonElement`), not as an escaped string (**my call**): a decision model reads structure better than an escaped string |
| `answer` | the run's answer |

**What the judge does not see:**
- The **agent's own success flag**. It would bias the judge towards the agent's view, and the judge exists to give an independent one.
- The **Reasonlet's name**. It adds nothing that the intent and the procedure don't already carry.

**A future change, deferred.** A readable step-by-step rendering of the graph might judge better than JSON. That's a tuning question for real data, and Minos.NET.Evaluation can measure it later.

### Failures (my call)

Minos has 13 `DecisionErrorKind`s. They split two ways (**my call**).

**When the judge can't judge, the result is `MnemosyneErrorCode.Unavailable`.** Phase 2.1 then stores the run with the agent's own verdict. These kinds count:
- Unauthorized
- Validation, which means the provider rejected the request, for example because it is too long
- RateLimited
- Overloaded
- Server
- Http
- Network
- Timeout
- InvalidResponse
- Refused
- Unsupported, which means the provider can't answer a Noul
- Disposed, which Minos documents as the client being disposed while the call was in flight, a shutdown race
- A probability outside [0, 1] or NaN, reported as `minos: InvalidResponse`. Minos doesn't range-check probabilities read off the wire, so this is a trust boundary: an invalid `ReasonletEvaluation` would make the facade throw and fail the agent's call.

**When there is a bug, the result is `MnemosyneErrorCode.Validation`.** Only this kind counts:
- InvalidQuestions, which means Mnemosyne's own question set is invalid

Phase 2.1 makes the facade throw `InvalidOperationException` for it, so a bug surfaces instead of hiding as a judge outage.

Either way, the error's message is fixed. Its detail names only the kind, for example `minos: RateLimited`, never Minos's message text, which could quote the request.

The unavailable kinds keep the phase 2.1 promise that a judge which can't judge never fails the agent's call. An unauthorized key or an oversized request shows up in telemetry as a stream of `Unavailable` outcomes, and the docs say so.

**Exceptions and cancellation:**
- An exception thrown by the Minos client propagates to the facade, which treats it as the judge being down.
- Cancellation propagates.
- The facade already applies `EvaluationTimeout`.

### Package and registration (my call)

**New package:** `Mnemosyne.NET.Minos`, in `src/Mnemosyne.NET.Minos`.
- It depends on `Mnemosyne.NET.Abstractions` and on the `Minos.NET` core package only, so it stays provider-neutral.
- It references Minos.NET 1.3.0 or the latest stable version at least two weeks old.
- Minos needs ZeroAlloc.Results 1.4.5, and the repo pins 1.4.4. The central pin moves to 1.4.5 in a `chore(deps)` commit first (**my call**). It is a patch bump, and no package is released yet.
- It is AOT-compatible and packable, and the AOT smoke roots it.

**Public types:**
- `MinosReasonletEvaluator : IReasonletEvaluator`. Its constructor takes `IDecisionClient` and `MinosEvaluatorOptions`.
- `MinosEvaluatorOptions`, with these init properties:
  - `SuccessThreshold`, in [0, 1], default 0.5;
  - `EvaluatorName`, non-blank and at most 100 characters, default `minos`;
  - `DecisionClientKey`, an `object?` that is null by default. When set, it selects a keyed `IDecisionClient`, so a host can give the judge its own client.
- `ServiceCollectionExtensions.AddMnemosyneMinosEvaluator(this IServiceCollection, MinosEvaluatorOptions? options = null)`.
  - It registers the evaluator as a singleton, resolving `IDecisionClient`, keyed or not.
  - Invalid options throw `ArgumentException`.
  - The host registers the client with Minos.NET.DependencyInjection.

### Privacy (my call)

**The provider sees the run.** The run's question and answer leave the process, because they go to the decision-model provider the host chose. That is inherent in judging with a remote model. The docs say so plainly, next to Mnemosyne's own guarantee, which still holds: nothing is stored, logged or sent to telemetry.

**Recording.** Minos.NET.Recording records each decision's state. The docs say not to add the recording stage to the client used for judging, unless its state redaction is configured. The evaluator can't check the host's pipeline.

**Minos's own telemetry.** It never records the state; Minos's docs say so. The page links Minos's observability page.

### Telemetry

There are no new Mnemosyne signals. The phase 2.1 `mnemosyne.evaluate` activity wraps this judge, and its evaluator tag is `minos`. Minos.NET's own spans nest inside it, because they share the ambient activity.

## Tests

- **The verdict:**
  - The probability maps to the score.
  - At the default threshold 0.5, a probability of 0.49 fails and 0.5 passes.
  - A custom threshold applies.
  - The evaluator name comes from the options.
- **The state:** the fake client receives `question`, `intent`, `procedure` (a JSON value equal to the canonical graph JSON when both are parsed) and `answer`. It never receives the agent's outcome or the name.
- **Failures:**
  - Each of the 13 `DecisionErrorKind`s maps as listed above: 12 to `Unavailable`, and InvalidQuestions to `Validation`. The detail carries only the kind.
  - A probability of 1.2, -0.01 or NaN returns `Unavailable` with `minos: InvalidResponse`.
  - A sentinel in Minos's error message never appears.
  - Exceptions propagate.
  - Cancellation propagates.
- **Options:** validation of every bad value. Keyed resolution picks the keyed client.
- **End to end, through the facade:** with a fake `IDecisionClient`, a recorded run with an answer is stored with source `Evaluator` and the judge's verdict. With the fake failing, it is stored with source `Agent`.
- **AOT:** the smoke judges a run through the generated questions under Native AOT.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| The JSON procedure is hard for a decision model to judge | Poor verdicts | Measurable with Minos.NET.Evaluation; a readable rendering is a later tuning change behind the same contract |
| A misconfigured key turns every run into "judge down" | Verdicts silently fall back to the agent | Telemetry shows the `Unavailable` stream; the guide names this case |
| A provider's limit rejects long answers | Long runs unjudged | Mapped to Unavailable, so the run is still stored; documented |
