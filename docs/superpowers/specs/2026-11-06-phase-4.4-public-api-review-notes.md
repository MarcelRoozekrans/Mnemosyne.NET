# Phase 4.4 public API review notes

Review of every line in the six `PublicAPI.Shipped.txt` baselines, taken at the 0.7.0 surface plus the changes of phases 4.1 to 4.4. Entries are `kept`, `changed` (done in this phase, breaking) or `proposed` (needs the operator, not done).

## How the baselines were generated

`dotnet format analyzers <project> --diagnostics RS0016 RS0036 RS0037 --severity info` wrote the lines into `PublicAPI.Unshipped.txt` for each project. Run once on the solution it filled only the Abstractions file, so it was run per project. The files start with `#nullable enable`, so nullable annotations are tracked. The result was moved to `Shipped.txt` and `Unshipped.txt` was reset to the header.

## Changed

- changed: `Mnemosyne.NET.ReasonletPromptFormatter` is now internal. It is the default suggestion renderer, nothing outside `Mnemosyne.NET` and its tests uses it, and no guide, README, sample, benchmark or AOT smoke code mentions it. Callers customise rendering through the `Formatter` option.
- changed: `Mnemosyne.NET.Sentinel` no longer exposes the generated `AddMnemosyneNETSentinelServices` extension. The ZeroAlloc.Inject generator arrives transitively through AI.Sentinel and emitted a public, undocumented registration type. `ZeroAllocGeneratedAccessibility=Internal` in the csproj fixes it at the source. Nothing in the repo called it; `AddMnemosyneSentinel` is the registration entry point.

## Mnemosyne.NET.Abstractions

- kept: ports `ICaptureGuard`, `IIntentExtractor`, `IReasonletEvaluator`, `IReasonletMemory`, `IReasonletSelector`, `IReasonletStore` - the extension points other packages and hosts implement.
- kept: records and record structs for the model (`ReasonletDefinition`, `ReasonletCapture`, `ReasonletCandidate`, `ReasonletMatch`, `ReasonletReceipt`, `ReasonletReview`, `ReasonletRun`, `ReasonletRunReceipt`, `ReasonletStoreEntry`, `ReasonletQuery`, `ReasonletRetention`, `ReasonletPruneResult`, `ReasonletErasure`, `ReasonletErasureResult`, `ReasonletEvaluationRequest`, `ReasonletProvenance`, `ReasonletGraph`, `ReasonletNode`, `ReasonletEdge`) - exchanged across package boundaries; sealed, with the init-only shape fixed in this phase.
- kept: value types `CaptureVerdict`, `ExecutionId`, `ReasonletId`, `ReasonletIntent`, `ReasonletMetrics`, `ReasonletOutcome`, `ReasonletScope`, `ReasonletScore`, `ReasonletEvidence`, `ReasonletEvaluation`, `ReasonletFeedback`, `MnemosyneError` - small readonly record structs used in every signature.
- kept: enums `MnemosyneErrorCode`, `ReasonletCaptureKind`, `ReasonletStatus`, `ReasonletVerdictSource` - part of the data contract.
- kept: `ReasonletGraphJson` - the documented, pinned graph schema v1 serializer.
- kept: `MnemosyneTelemetry` - the documented meter and activity source names that hosts subscribe to; also used by the samples and the AOT smoke app.
- kept: `EvaluationLimits` and `ReasonletGraphLimits` - limits shared by every package and quoted in the guides.
- kept: `Validation.Check` - used by the options validation of every package, so it cannot be internal.
- proposed: make `Validation.Check`, `EvaluationLimits` and `ReasonletGraphLimits` internal and give the other packages their own copies or an InternalsVisibleTo, or move `Check` to a `Mnemosyne.NET.Abstractions.Validation` namespace documented as for implementers only. They are implementation helpers, but they are used across five packages, so hiding them is a breaking design change for the operator.

## Mnemosyne.NET

- kept: `ReasonletMemory`, `ReasonletSelector`, `ChatReasonletEvaluator` - the default implementations, constructed by hosts and in the benchmarks; sealed.
- kept: options (`MnemosyneOptions`, `ReasonletRankingOptions`, `ReasonletCaptureOptions`, `ReasonletChatOptions`, `ReasonletSuggestionOptions`, `ChatEvaluatorOptions`) - sealed init-only options, each with `Validate`.
- kept: `ServiceCollectionExtensions`, `ReasonletChatClientBuilderExtensions`, `ReasonletChatOptionsExtensions` - the documented entry points.
- kept: `IReasonletCaptureSink`, `ReasonletCaptureRun`, `TranscriptCaptureDetails`, `TranscriptSkipReason`, `ReasonletCallScope`, `ReasonletSuggestion` - the capture and suggestion hand-offs; the sink and run are used by `Mnemosyne.NET.AgentFramework`.
- kept: `ReasonletTools`, `FindProcedureFunction`, `ReasonletTranscript` - documented, and used by the AgentFramework package and the AOT smoke app.
- proposed: make `ReasonletCaptures` and `ReasonletSuggestions` internal and share them with the AgentFramework package through InternalsVisibleTo. They are telemetry and recall helpers whose only outside caller is `ReasonletContextProvider`; their string constants and `CountFailed`, `CountSkipped`, `RecallAsync` are plumbing. Not changed because it needs a cross-package friend declaration.

## Mnemosyne.NET.PostgreSql

- kept: `ReasonletPostgreSqlStore` (sealed, the `IReasonletStore` implementation, with `MigrateAsync`), `MnemosynePostgreSqlOptions` (sealed options), `ServiceCollectionExtensions.AddMnemosynePostgreSql` - the package entry points.

## Mnemosyne.NET.Minos

- kept: `MinosReasonletEvaluator`, `MinosEvaluatorOptions`, `ServiceCollectionExtensions.AddMnemosyneMinosEvaluator` - sealed; the Minos `IDecisionClient` in the constructor is the intended dependency.

## Mnemosyne.NET.Sentinel

- kept: `SentinelCaptureGuard`, `SentinelCaptureGuardOptions`, `ServiceCollectionExtensions.AddMnemosyneSentinel` - sealed; the baseline is taken at AI.Sentinel 4.2.0 because the 5.x move (#58) is parked. AI.Sentinel types appear in the constructor signature, so a later Sentinel major is a surface change here.

## Mnemosyne.NET.AgentFramework

- kept: `ReasonletContextProvider` (sealed, the Agent Framework context provider), `ReasonletAgentOptions` (sealed options, including the static `DefaultScope`), `ReasonletAgentScope` (positional on purpose).

## Cross-cutting

- kept: the class name `ServiceCollectionExtensions` repeats in four packages, each in its own namespace. The extension method names are unique, so callers never see an ambiguity; a rename would be breaking for no gain.
- kept: positional records `ReasonletSuggestion`, `ReasonletAgentScope`, `ReasonletCallScope`, `ReasonletErasure` stay positional by decision; their `Deconstruct` and `<Clone>$` lines are compiler-generated members of the record and appear in the baseline as the analyzer requires.
