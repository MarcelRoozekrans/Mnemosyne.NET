# Phase 4.4 Design — Public API review and freeze

**Date:** 2026-11-06
**Phase:** 4.4
**Surface:** Refactor
**Stage:** phase (one phase, implementation-ready)
**Status:** approved 2026-11-06

**Builds on:** Phase 4.2 — `LineageId` (`required ReasonletId`) on `ReasonletCandidate` and `ReasonletMatch`, and `ReasonletCandidate`, `ReasonletMatch` and `ReasonletEvidence` as init-only records.

## Goal

Settle the public API in one pass, then lock it: close #58 so a capture guard fails closed on an incomplete scan, make the result and entry records that will grow init-only, record the reviewed surface in `PublicAPI.Shipped.txt` per package, and publish a compatibility policy for the graph schema.

## Why

After 1.0.0 a changed public signature costs a major version. This is the last cheap moment to break the shape of a record, and the first moment a mechanical gate can hold the line. #58 changes shipped behaviour, so it settles before the freeze rather than after.

## Approaches considered

| Decision | Choice | Rejected |
|---|---|---|
| Positional records | **Convert the ones that will grow** (`ReasonletReceipt`, `ReasonletReview`, `ReasonletStoreEntry`, `ReasonletRunReceipt`) to `required` init properties. Keep `ReasonletSuggestion`, `ReasonletAgentScope`, `ReasonletCallScope` and `ReasonletErasure` positional and document why: they are small keys, not results. By the user. | Convert all eight (churn on types that will not grow); leave all (any new member after 1.0 is a major bump or a second constructor). |
| Lock | **`PublicApiAnalyzers` with `PublicAPI.Shipped.txt` and `PublicAPI.Unshipped.txt` per packable `src` project, enforced as errors in CI. `EnablePackageValidation` is turned on in 4.7 with `PackageValidationBaselineVersion` 1.0.0**, once a baseline exists. By the user. | Validate against 0.7.0 with a suppression file (hides the breaks the gate exists to show); analyzers only (misses binary-level breaks). |
| Graph schema policy | **v1 is frozen.** Within `schemaVersion` 1 nothing is added, removed, tightened or given a new meaning; any such change is a `schemaVersion` 2 with its own schema file, and a minor release reads both for at least one major. A golden-document test pins it. My call, to be checked. | Additive-only inside v1 (the schema has `additionalProperties: false`, so an old reader rejects a new field: not additive in practice). |

## Approach

**#58 first.** Bump AI.Sentinel in `Directory.Packages.props` to the latest 5.x that restores. In `SentinelCaptureGuard.InspectAsync`, read `PipelineResult.IsComplete` and `Failures`; when the scan is incomplete, return the existing `Unavailable` error (`MnemosyneErrorCode.Unavailable`, which `ICaptureGuard` already allows) instead of a verdict. A detection that reaches the block severity still blocks even when the scan is incomplete: a known bad capture is never allowed because another detector failed. The error detail names only the count of failed detectors, never a detector's message, since it can quote the capture. Update `AThrowingDetectorIsSkippedAndTheCaptureIsAllowed` to expect the closed result, add the block-wins case, replace the stale `4.1.1` references, rewrite the two "known gap" paragraphs, and re-check the named-pipeline rule on the new version.

**Records.** The four types lose their positional constructor and `Deconstruct` and gain `required` init properties, declared as `ReasonletDefinition` does. Every construction site moves to an object initialiser; the compiler is the checklist. `ReasonletStoreEntry` keeps its two optional members optional. `Validate()` bodies do not change.

**API baseline.** Add `Microsoft.CodeAnalysis.PublicApiAnalyzers` to the packable `src` projects through `Directory.Build.targets`, conditioned on `IsPackable`, as a private-asset package pinned in `Directory.Packages.props`. Generate each `PublicAPI.Shipped.txt` from the reviewed surface with the analyzer's code fix, leave `PublicAPI.Unshipped.txt` empty, and make RS0016, RS0017, RS0022, RS0025, RS0026, RS0027 and RS0036 errors. The review itself is a pass over each generated baseline: anything public that should not be (a helper, a type in the wrong namespace, a missing `sealed`) is fixed before the baseline is written, and each decision is a line in the impact analysis. Benchmarks, samples and tests are not packable and are not analysed.

**CI.** `ci.yml` needs no new job: the analyzers run in the existing `dotnet build`, so a surface change fails the build. A workflow step in the pack job asserts every packable project has a non-empty `PublicAPI.Shipped.txt`, so a new package cannot skip the gate.

**Policy.** A new `docs/concepts/compatibility.md` states the rules: the SemVer promise per package, what counts as public, how a change moves through `Unshipped` to `Shipped`, how a breaking change is made (a major release, with the baseline diff in the pull request), and the v1 schema policy above. `schemas/` gets a README line pointing to it. A test loads a set of golden v1 graph documents from `tests/Mnemosyne.NET.Tests/Graph/GoldenV1/` and asserts each deserializes and round-trips; changing the graph format breaks it.

**Benchmarks stay compiling.** `benchmarks/Mnemosyne.NET.Benchmarks` is in the solution, so the record conversion must leave it building. Every task ends with `dotnet build Mnemosyne.NET.slnx -c Release`, which covers it, and the final task checks it by name.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| AI.Sentinel 5.x changes more than `IsComplete` | A wider adapter change than planned | Bump first, in its own commit, and fix what the compiler names before any other work |
| The generated baseline records something that should not be public | A mistake locked in at 1.0 | The review pass reads every baseline line before the first commit of it |
| Fail-closed blocks captures a deployer relied on | A behaviour change in a minor release | Documented as a fix in the release notes and the guide; the guard timeout and `Unavailable` handling already exist |
| The converted records break out-of-tree callers | A compile break for them | Accepted before 1.0 and called out in a `BREAKING CHANGE:` footer |
