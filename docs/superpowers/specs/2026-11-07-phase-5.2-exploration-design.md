# Phase 5.2 Design — Exploration

**Date:** 2026-11-07
**Phase:** 5.2
**Surface:** Backend
**Stage:** phase (one phase, implementation-ready)
**Status:** approved 2026-11-07

**Builds on:** Phase 5.1 — `VariantSelector(IReasonletSelector inner)`, `ServiceCollectionExtensions.AddMnemosyneVariantSelection(IServiceCollection)`, the recall tag constants in `RecallTelemetry`.

## Goal

With exploration switched on, a new version that has few runs is sometimes chosen over the best known variant of its lineage, so it can prove itself. The switch is separate from variant selection (Marcel, 2026-11-07), and a seed makes the choice reproducible.

## Approach

`VariantSelectionOptions` is a new public sealed class with init-only members:

- `Exploration`: enum `VariantExploration { None, Thompson }`, default `None`. With `None` the selector behaves exactly as in 5.1.
- `Seed`: `int?`, default null.
- `MinTrials`: `int`, 0 to 1000, default 0. Off by default.
- `Validate()` returning a `UnitResult<MnemosyneError>`, like the other options.

`VariantSelector` gets a second constructor taking the inner selector, the options and the `ReasonletRankingOptions`. The first constructor stays and means `None`. `AddMnemosyneVariantSelection` gets an overload taking the options; the parameterless one stays. Both read the ranking options from the registered `MnemosyneOptions`.

With `Thompson` the selector changes step 1 of 5.1. It groups the candidates by lineage first, picks one candidate per lineage, and then passes only those to the inner selector, which scores and orders them as before.

The pick per lineage:

1. **Minimum trials.** If any variant has fewer than `MinTrials` runs, the one with the fewest runs wins, ties by id ascending. This is a forced exploration.
2. **Thompson sampling.** Otherwise each variant draws `Beta(a, b)`. The prior is the one `ReasonletSelector` already uses: `SuccessRate` gives the smoothed rate `r`, which includes the parent's head start, and `a = r * k + weightedSuccesses`, `b = (1 - r) * k + weightedFailures`, with `k = PriorWeight` and the agent-verdict weighting from the ranking options. The highest draw wins, ties by id ascending.
3. **Explored.** A pick counts as an exploration when it is not the variant with the highest smoothed rate (ties by id). The recall activity gets `mnemosyne.recall.variant.explored`, the number of lineages whose pick was an exploration.

Randomness: with a `Seed` the draws are reproducible and stateless: each lineage's generator is seeded from the seed, the query's question and the lineage id through a hash (FNV-1a over UTF-16 code units, written inline, no new dependency), so concurrent recalls cannot disturb one another and the same query on the same data always picks the same variants. Without a seed the selector uses `Random.Shared`. A beta draw is two gamma draws (Marsaglia and Tsang, with a Box-Muller normal); all of it is plain arithmetic, so Native AOT is unaffected.

Exploration is not forced by anything but the policy: a variant that was once explored and failed gets a lower draw next time because its failure now counts.

## Decisions

| Decision | Detail | By |
|---|---|---|
| Separate switch for exploration | Adopting grouping must not bring randomness along | user, 2026-11-07 |
| Seeded mode is per-query deterministic | A fixed seed with a stateful generator would give different picks on repeated queries and break test reproducibility | my call |
| Minimum trials forces the least-run variant | Simple, bounded, and easy to explain; off by default | my call |
| The prior reuses `ReasonletSelector.SuccessRate` | One definition of "how good is this version", already documented in the ranking page | my call |

## Tests

- Options: defaults, each bound, `Validate` paths.
- Sampler: with fixed seeds the mean of many draws is near `a / (a + b)`; draws stay in [0, 1]; the same seed gives the same sequence; degenerate parameters are handled.
- Selector: `None` equals 5.1; seeded repeats are identical; a different question can differ; `MinTrials` forces the least-run variant and then lets go; the explored count is right; an unseeded run does not throw.
- Simulation: an incumbent with 200 runs at a true rate of 0.7 and a new version at 0.9 with no runs. Over a seeded loop of recalls with outcomes drawn at the true rates and the metrics updated each round, the new version is chosen at least once in the first 20 rounds and in most of the last 100, while with `None` it is never chosen. The test states its thresholds and the seed.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Exploration serves a worse variant | Lower success while exploring | The prior and `MinTrials` bound it; the simulation measures the cost and the guide states it |
| Hash seeding makes every user of one question explore the same way | Less variety | Only in seeded mode, which is for tests and replays |
| The simulation is flaky | Red CI | Fixed seed, no wall clock, thresholds with margin |
