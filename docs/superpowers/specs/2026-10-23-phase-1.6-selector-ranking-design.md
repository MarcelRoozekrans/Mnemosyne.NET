# Phase 1.6 Design: Selector and ranking

**Date:** 2026-10-23
**Phase:** 1.6
**Surface:** Backend
**Stage:** phase (one phase, implementation-ready)

This design builds on the [phase 1.4 store](2026-10-22-phase-1.4-postgres-store-design.md),
the [phase 1.5 telemetry and retention](2026-10-22-phase-1.5-telemetry-retention-design.md),
and the [roadmap](2026-10-21-roadmap-design.md). Decisions are marked **user**
or **my call**.

## Goal

An agent asks a question and gets back the few Reasonlets most worth trying,
best first, each with a score breakdown. The agent still makes the final call;
Daedalus decides for itself (**user**, from the roadmap).

This phase builds:

- the default `IReasonletSelector`;
- the `IReasonletMemory` facade that ties the store, the selector, an
  embedding generator and an optional intent extractor together;
- recall telemetry;
- an `AddMnemosyne()` registration.

## Non-goals

- **An LLM intent extractor.** Milestone 3 can add one on `IChatClient`.
- **Evaluator feedback in ranking.** That is milestone 2. The success-rate
  term uses execution outcomes only.
- **The off-the-shelf integrations:** middleware, the `find_procedure` tool and
  the Agent Framework provider. These are milestone 3.
- **Docs site and sample.** Those are phase 1.7.

## Approach

### Recall, step by step

1. **Validate** the query.
2. **Resolve the intent filter.**
   - If the query carries `Intent`, that value is the filter.
   - If it carries none and an `IIntentExtractor` is registered, the facade
     asks the extractor. It uses the answer as the filter only when the
     confidence is at least `MinIntentConfidence`. The default is 0.7.
   - Otherwise recall searches all intents (**user**: caller or optional
     extractor).
   - An extractor that is down also means no filter; see
     [Failures](#failures).

   **Why the confidence threshold (my call):** a wrong filter hides every
   right answer, so recall only filters on an intent it is confident about.
3. **Embed** the question with the host's
   `IEmbeddingGenerator<string, Embedding<float>>` from
   Microsoft.Extensions.AI (**my call**). It belongs to the same abstraction
   family as `IChatClient`, so any model a host already uses works.
4. **Search** the store for a candidate pool larger than `Top`, so that
   reliability and freshness can reorder results that similarity alone would
   cut. The pool size is `CandidatePool`, default 20, raised to `Top` when
   `Top` is larger (**my call**). The store returns only Active Reasonlets.
5. **Rank** the pool with the selector, then return up to `Top` matches.

### Relevance cut-off (user)

- A candidate with similarity below the cut-off is dropped before ranking. If
  nothing passes, recall returns an empty list, and the agent works from
  scratch. A NaN similarity never passes, so a direct caller of the selector
  cannot sneak one past the cut-off.
- The cut-off is `MinSimilarity` on the selector options, with a default of
  0.5. A query can override it with `ReasonletQuery.MinSimilarity`, which
  ranges from 0 to 1.
- Similarity scales differ between embedding models, so the docs say to tune
  the cut-off for your model (**my call** on the default).

### Score

The weights sum to 1, and the defaults come from the roadmap: similarity 0.50,
success rate 0.30, freshness 0.20. They are configurable, and the options
validate that each weight is in [0, 1] and that the three sum to 1 within
1e-9.

```
total = wSimilarity * similarity + wSuccess * successRate + wFreshness * freshness
```

**Success rate** (**my call**). A smoothed rate means a handful of runs can't
swing it to 0 % or 100 %:

```
successRate = (successes + k * prior) / (runs + k)
```

- `k` is `PriorWeight`, worth that many pseudo-runs. The default is 5.
- `prior` is 0.5 for a Reasonlet without a parent.
- **New versions inherit, upward only** (**user**). For a Reasonlet with a
  parent, `prior` is `max(parentSmoothedRate, 0.5)`, where the parent's rate is
  its own, smoothed with the neutral prior. A version of a proven procedure
  therefore starts from its parent's record, and its own runs take over as they
  accumulate. A fix to a failing procedure starts at 0.5, like any new
  procedure. Inheritance only ever lifts: given the same own runs, a version
  never scores below a root.
- Inheritance goes **one level**, to the parent only (**my call**). The parent
  is the version this one replaced, so it is the most relevant record. Pooling
  every ancestor would also count the failures that led to the replacements.
- When the parent has been erased, the parent link is cut (pruning deletes whole idle subtrees, so it never cuts one) and the
  version is treated as a root.

**Freshness** (**my call**). An exponential decay since the last run:

```
freshness = 0.5 ^ (age / FreshnessHalfLife)
```

- `age` is now minus `LastExecutedAt`, which phase 1.5 maintains on every
  execution. It is never null, because every Reasonlet has its remember run.
- The default half-life is 30 days.
- `age` below zero, which clock skew between the host and the database can
  cause, counts as zero.
- "Now" comes from an injected `TimeProvider`, so tests control it.

**Order.** Results sort by total descending, then by similarity descending,
then by id ascending. That makes the order deterministic.

**Breakdown.** `ReasonletScore` already carries `Similarity`, `SuccessRate`,
`Freshness` and `Total`, all in [0, 1].

### Contract changes (pre-1.0, so allowed)

- **`ReasonletQuery`:**
  - Remove `Provenance` (**user**). It existed for the dropped audit trail:
    recall stores nothing, and telemetry excludes the subject.
  - Add `double? MinSimilarity`, validated to [0, 1] when present.
  - Fix the `RecallAsync` remarks, which still mention persisted recall
    provenance.
- **`ReasonletMetrics`** gains `DateTimeOffset LastExecutedAt`. The default
  value stays valid.
- **`IReasonletStore`** gains `int Dimensions { get; }` (**user**): the
  length every stored and queried embedding must have, fixed when the store is
  configured. The PostgreSQL store returns `MnemosynePostgreSqlOptions.Dimensions`.
  The facade checks a generated embedding against it before the store call.
- **`ReasonletCandidate`** gains `ReasonletMetrics? ParentMetrics`. It is the
  parent's metrics when the Reasonlet has a parent in its scope, and null
  otherwise.
- **`IReasonletStore.SearchAsync`** fills both, and its remarks require it.
  A store that leaves `ParentMetrics` null disables inheritance, and one that
  leaves `LastExecutedAt` at its default makes freshness zero. The PostgreSQL search
  left-joins the parent's metrics row through `parent_id` and adds
  `last_executed_at`. A Reasonlet without a metrics row, which the store never
  leaves, reads as `created_at` (**my call**). This is one more primary-key probe per candidate (**my
  call**).

### Remember through the facade

1. Validate the capture.
2. Resolve the intent:
   - use the capture's `Intent` if it has one;
   - else use the extractor's answer, whatever its confidence, because a stored
     intent is better than none;
   - else use `unspecified`.
3. Resolve the name: the capture's `Name`, else the question's first line
   that is non-empty once trimmed, trimmed, cut to 200 code points without
   splitting a surrogate pair, and trimmed again (**my call**).
4. Embed the question, build the `ReasonletStoreEntry`, and call the store.

### The other facade members

`RecordExecutionAsync`, `RecordFeedbackAsync` and `EraseAsync` validate and
delegate to the store.

### Failures

- **A dependency is down** when it throws, or times out: an
  `OperationCanceledException` while the caller's token is not cancelled. An
  extractor `Unavailable` result also counts. The error carries the exception
  type in the detail but never its message, which can contain the question.
  A real cancellation propagates.
- **The generator is down:** `Unavailable`, at recall and at remember.
- **The extractor is down** (**user**): recall searches without an intent
  filter and succeeds, with `intent_filtered` false and the tag
  `mnemosyne.recall.intent_fallback` set to true. A missing filter only widens
  the search. Remember still answers `Unavailable`, so a wrong intent is never
  stored. Any other extractor error code, or an invalid intent, throws
  `InvalidOperationException` at both, because it is an adapter bug.
- **Embeddings the store cannot use** (**user**): `Unavailable`, not
  `Validation`, at recall and at remember, because the generator made the
  embedding, not the caller. The facade checks before the store call, so the
  store is never called with one: the embedding must have the store's
  `IReasonletStore.Dimensions` values, hold only finite values and have a
  nonzero norm, summed in single precision as pgvector does. The message is
  fixed, "The embedding generator returned an embedding the store cannot
  use.", and the detail gives only the reason, `length`, `non-finite` or
  `norm`, with the two lengths for a wrong length. It never holds text.
- **Store errors**, `Validation` included, pass through unchanged.
- **Selector failures** pass through unchanged.

### Recall telemetry

The facade emits a `mnemosyne.recall` activity, plus `mnemosyne.operations`
and `mnemosyne.operation.duration` with operation `recall`, on the same
`Mnemosyne.NET` source and meter. The spans the store already emits nest
inside it.

**Tags:**

| Tag | Set when |
|---|---|
| `mnemosyne.recall.top` | always |
| `mnemosyne.recall.intent_filtered` | always (bool) |
| `mnemosyne.recall.intent_fallback` | only when the extractor was down and recall searched every intent (`true`) |
| `mnemosyne.recall.candidates` | after search |
| `mnemosyne.recall.returned` | on success |
| `mnemosyne.recall.chosen.id` | on success, when at least one match is returned |
| `mnemosyne.recall.chosen.version` | on success, when at least one match is returned |
| `mnemosyne.recall.chosen.score` | on success, when at least one match is returned (the total) |

**Instruments:**

- `mnemosyne.recall.returned`: a histogram;
- `mnemosyne.recall.empty`: a counter of recalls that returned nothing.

**Privacy.** The rule from phase 1.5 holds: no question, intent, scope,
subject or tag text, and no error or exception message. The facade emits only
recall; remember and the rest are already instrumented by the store, and
wrapping them again would double-count.

### Packaging and registration

The selector, the facade, their options and their telemetry live in the core
`Mnemosyne.NET` package, which gains a dependency on
`Microsoft.Extensions.AI.Abstractions`.

The PostgreSQL store depends on Abstractions only (**user**). It has no
reference to the core package, so a host that only stores does not pull in
`Microsoft.Extensions.AI.Abstractions`. A host that recalls references both
packages.

The options validate with `Check` from Abstractions. `Check` is public API in
`Mnemosyne.NET.Abstractions.Validation` (**user**), exposing only the helpers
another package needs: `Fail`, `UnitInterval`, `Range`, `NotDefault`,
`NotNull`, `Nested` and `All`. Abstractions grants `InternalsVisibleTo` to its
test project only.

`services.AddMnemosyne(MnemosyneOptions? options = null)` registers the
following. The options are an object, not a configure delegate, because their
members are init-only; null means the defaults.

- `IReasonletMemory`;
- the default `IReasonletSelector`, with `TryAdd` so a host can replace it;
- `MnemosyneOptions`;
- `TimeProvider.System`, also with `TryAdd`.

The host registers an `IReasonletStore`, for example with
`AddMnemosynePostgreSql`, and an embedding generator. `IIntentExtractor` is
optional and resolved if present. `MnemosyneOptions` holds `CandidatePool`,
`MinIntentConfidence` and a nested `Ranking` for the selector options, and is
validated at registration.

## Tests

- **Selector, unit level:**
  - every formula term, with exact values;
  - the cut-off, including per-query override and empty result;
  - inheritance: a parent with 100/100 lifts a 0-run child; a child's own
    failures pull it down; a root uses 0.5; a failing parent, 0/20, leaves a
    1/1 child at `(1 + 5 * 0.5) / 6`, not below neutral;
  - freshness half-life and negative age;
  - weights validation;
  - deterministic order on ties;
  - `Top` truncation;
  - the example from the brainstorm: a fresh version of a proven procedure
    ranks above the proven original and above a close match that fails half
    its runs.
- **Facade:**
  - intent resolution: caller, confident extractor, unconfident extractor,
    none;
  - remember defaults for intent and name;
  - generator failures, and extractor failures at remember, map to
    `Unavailable` without the message;
  - an extractor outage at recall searches unfiltered and sets the fallback
    tag;
  - a wrong-length or NaN embedding gives `Unavailable` at recall and
    remember, while query validation still gives `Validation`;
  - cancellation propagates;
  - the candidate pool size;
  - delegation of the other members.
- **Telemetry:**
  - recall tags on success, empty and failure;
  - a sentinel privacy scan, as in phase 1.5;
  - store spans nest under recall.
- **PostgreSql:** search returns the parent metrics and null for a root or a
  cut link, plus `last_executed_at`.
- **Integration:** the facade over the real store with a deterministic fake
  embedding generator, end to end, including the brainstorm example.
- **AOT:** a recall through `AddMnemosyne` under native AOT.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| The default `MinSimilarity` is wrong for a given embedding model | Recall returns too much or nothing | Per-query override; docs say to tune it; recall telemetry shows candidate and returned counts |
| One-level inheritance misses a long proven lineage behind a weak parent | A new version starts lower than its history deserves | Documented; revisit with evaluator data in milestone 2 |
| Host and database clocks differ | Freshness is slightly off | Negative age clamps to 0; skew of seconds is negligible against a 30-day half-life |
