# Phase 1.2 Design — Abstractions

**Date:** 2026-10-22
**Phase:** 1.2
**Surface:** Backend
**Stage:** phase (one phase, implementation-ready)

Builds on the [Reasonlets design](2026-10-21-mnemosyne-reasonlets-design.md) and the
[roadmap design](2026-10-21-roadmap-design.md), which fix scope, provenance, a
Mnemosyne-owned graph schema, AOT compatibility and "no answer caching".
Decisions are marked **user** or **my call**.

## Goal

`Mnemosyne.NET.Abstractions` holds the public contract every other package and
every caller builds on: the records, the scope and provenance model, the
caller-facing `IReasonletMemory` facade, and the two ports underneath it,
`IReasonletStore` and `IReasonletSelector`. It contains types only, no behaviour
beyond validation.

## Approach

### House style (my call, matching Thalos.NET)

- Async members return `ValueTask<Result<T, MnemosyneError>>`, or
  `ValueTask<UnitResult<MnemosyneError>>` when there is no value. Both come
  from `ZeroAlloc.Results`, the same package Thalos.NET and Daedalus.NET use.
  Pin the version Daedalus pins (`1.4.4`). Expected failures are results;
  exceptions are reserved for bugs.
- Every async member takes a `CancellationToken ct` as its last parameter,
  with no default value, as in Thalos's store ports.
- IDs are `readonly record struct` wrappers: `ReasonletId(Guid)`,
  `ExecutionId(Guid)`. New IDs come from a static `New()` factory using
  `Guid.CreateVersion7()`, so they sort by time. Members that take an ID
  return a `Validation` error for a `default` ID.
- Errors are `readonly record struct MnemosyneError(MnemosyneErrorCode Code,
  string Message, string? Detail = null)`. `MnemosyneErrorCode` has the values
  `Validation`, `NotFound`, `Conflict` and `Unavailable`. Each value gets a
  doc comment saying when it is returned:
  - `Validation`: an input broke an invariant.
  - `NotFound`: the ID doesn't exist **in the caller's scope**. An ID that
    exists in another scope also answers `NotFound`, never a separate
    "wrong scope" code, so IDs can't be probed across scopes (**my call**,
    the same rule Thalos.NET applies to sessions).
  - `Conflict`: the write lost a race the store detected, such as the parent
    being erased between lookup and insert.
  - `Unavailable`: the backing store or the embedding generator failed.
- All types are AOT-safe: no reflection, and any JSON goes through
  source-generated contexts. Phase 1.1's AOT gate enforces this.

### The caller-facing facade: `IReasonletMemory`

There is one storing call (**user**: "one RememberAsync").

```csharp
ValueTask<Result<ReasonletReceipt, MnemosyneError>> RememberAsync(ReasonletCapture capture, CancellationToken ct);
ValueTask<Result<IReadOnlyList<ReasonletMatch>, MnemosyneError>> RecallAsync(ReasonletQuery query, CancellationToken ct);
ValueTask<Result<ExecutionId, MnemosyneError>> RecordExecutionAsync(ReasonletScope scope, ReasonletId id, ReasonletOutcome outcome, ReasonletProvenance provenance, CancellationToken ct);
ValueTask<UnitResult<MnemosyneError>> RecordFeedbackAsync(ReasonletScope scope, ExecutionId execution, ReasonletFeedback feedback, CancellationToken ct);
ValueTask<Result<int, MnemosyneError>> EraseAsync(ReasonletErasure erasure, CancellationToken ct);
```

`RememberAsync` covers three cases, decided by `ParentId` (**user**):

| `ParentId` | Graph compared with the parent's | Result |
|---|---|---|
| absent | n/a | A new Reasonlet at version `1.0` |
| set | equal | No new version; an execution is recorded on the parent |
| set | different | A new version: a child Reasonlet with lineage to the parent |

What "equal" means for graphs is defined in phase 1.3, which owns the graph
schema. In the `ExecutionOnly` case, the capture's `Outcome` and `Provenance`
are recorded on the new execution, so nothing the caller sent is lost and
erasure by subject also finds executions (**my call**). For the same reason `RecordExecutionAsync` takes a `ReasonletProvenance`: every execution carries the run and subject that produced it. Two concurrent
captures with the same parent but different graphs create two sibling
versions. That is legitimate lineage, not an error, and variant selection
after 1.0 is built for exactly that. The facade's three-way decision runs as
one atomic store operation (see ports), so it never sees a half-written
state (**my call**). This phase defines only the contract. The version numbers for
children (minor bump or otherwise) belong to phase 1.4. The receipt reports
the version that was actually assigned.

Embeddings are **not** part of the capture. Mnemosyne computes them from the
question through the configured `IEmbeddingGenerator<string, Embedding<float>>`
(**user** accepted). The answer is never part of the capture, because answer
caching is an anti-goal.

### Records

- `ReasonletScope`: `readonly record struct ReasonletScope(string Value)`.
  - It is an opaque, caller-defined partition key, such as `"tenant-a"` or
    `"tenant-a/app-x"`. Recall, execution, feedback and erasure only ever
    see records in exactly that scope. There is no hierarchy, so a parent
    scope does not see its children (**my call**: the simplest model that is
    safe, and a hierarchy can be added without breaking anything).
  - Construction rejects an empty or whitespace value. A scope can't be
    `default`-constructed by accident and then used: members that take a
    scope return a `Validation` error for a `default` scope.
- `ReasonletProvenance`: `(string Source, string? RunId, string? SubjectId,
  IReadOnlyDictionary<string, string>? Tags)`.
  - `Source` names the caller, such as `"daedalus"`.
  - `SubjectId` names the data subject, so the record can be erased by
    subject (GDPR, AI Act data governance).
- `ReasonletOutcome`: `(bool Success, TimeSpan Duration, double? Score)`.
  - `Duration` is not negative.
  - `Score`, when present, is in `[0, 1]`.
- `ReasonletFeedback`: `(double Utility, double Correctness, double Reusability)`.
  - Each value is in `[0, 1]`.
- `ReasonletCapture`:
  - `required` members: `Scope`, `Question`, `Graph`, `Outcome`, `Provenance`.
  - Optional members: `Intent`, `Name`, `ParentId`.
  - When `Intent` is absent, it is derived (see ports). When `Name` is absent,
    it is derived from the intent.
- `ReasonletReceipt`: `(ReasonletId Id, string Version, ExecutionId Execution,
  ReasonletCaptureKind Kind, ReasonletStatus Status)`.
  - `ReasonletCaptureKind` is `NewReasonlet`, `NewVersion` or `ExecutionOnly`.
  - `ReasonletStatus` is `Active` or `PendingReview`. Nothing produces
    `PendingReview` until the review gate in phase 3.3, but the value exists
    now so the receipt does not change shape.
- `ReasonletQuery`: `(ReasonletScope Scope, string Question, string? Intent,
  int Top = 3)`.
  - `Top` is in `[1, 50]`.
- `ReasonletMatch`: `(ReasonletDefinition Reasonlet, ReasonletScore Score)`.
- `ReasonletMetrics`: `(int Runs, int Successes, DateTimeOffset? LastSuccessAt)`.
  - It is computed from executions, not stored, as the Reasonlets design says.
- `ReasonletCandidate`: `(ReasonletDefinition Reasonlet, double Similarity,
  ReasonletMetrics Metrics)`. This is what the store's search returns and the
  selector ranks. The store joins the metrics in the same query, so the
  selector never calls the store (**my call**).
- `ReasonletScore`: `(double Similarity, double SuccessRate, double Freshness,
  double Total)`.
  - Every component is in `[0, 1]`. This is the score breakdown (AI Act
    transparency).
  - The weights 0.50, 0.30 and 0.20 belong to the selector in phase 1.6, not
    to this record.
- `ReasonletDefinition`: `(ReasonletId Id, ReasonletScope Scope, string Name,
  string Intent, string Version, ReasonletGraph Graph, ReasonletId? ParentId,
  ReasonletProvenance Provenance, ReasonletStatus Status, DateTimeOffset CreatedAt)`.
- `ReasonletErasure`: `(ReasonletScope Scope, string? SubjectId)`.
  - With no `SubjectId`, the whole scope is erased; with one, only that
    subject's records. The return value is the number of Reasonlets removed.
- `ReasonletGraph`: the record type for the procedure. Its exact shape
  (nodes, edges, schema version, extension properties) is **phase 1.3's**
  job. This phase declares it with the minimum the rest needs:
  `IReadOnlyList<ReasonletNode> Nodes`, `IReadOnlyList<ReasonletEdge> Edges`
  and `int SchemaVersion`. Phase 1.3 fills in the JSON schema, serialization,
  equality and validation without renaming these members (**my call**: 1.2
  and 1.3 would otherwise be circular).

Records validate their own invariants through an instance method
`UnitResult<MnemosyneError> Validate()` (**my call**). It checks ranges and
required strings (non-blank `Question`, `Source`, `Version`, and `Name` or
`Intent` when present, plus non-blank tag keys) instead of constructors, so
deserialization can't throw. Validation is recursive: `ReasonletCapture.Validate()`
validates its `Scope`, `Outcome`, `Provenance` and `Graph`. In this phase,
`ReasonletGraph.Validate()` checks only that its lists are not null and
`SchemaVersion` is positive; phase 1.3 extends it. The error message names
the failing field by its path, for example `Outcome.Score`. The facade
implementation calls `Validate()` first.

There is no JSON serialization in this phase. Records holding collections
(`Tags`, graph lists) do **not** get value equality from `record`; nothing
may rely on `==` for them. Graph equality is phase 1.3's to define.

### Ports underneath (implemented in later phases)

- `IReasonletStore` holds persistence and is implemented in phase 1.4. It
  takes embeddings as `ReadOnlyMemory<float>`, so Abstractions does not
  depend on `Microsoft.Extensions.AI`; the facade implementation in core
  calls the embedding generator (**my call**). It has members to:
  - remember atomically: given a capture with its precomputed embedding,
    insert a new Reasonlet, or under a parent compare graphs and either
    record an execution or insert a child with lineage, in one transaction,
    returning the receipt;
  - get a definition by id within a scope;
  - append an execution;
  - append feedback;
  - run a scoped vector search that returns `ReasonletCandidate`s, with
    metrics joined;
  - erase by scope or subject.

  The members take a scope wherever they read or write user data.
- `IReasonletSelector`: `RankAsync(ReasonletQuery query, IReadOnlyList<ReasonletCandidate> candidates, CancellationToken ct)`
  returns ranked `ReasonletMatch`es. It is implemented in phase 1.6.
- `IIntentExtractor`: `ExtractAsync(string question, CancellationToken ct)`
  returns `Result<ReasonletIntent, MnemosyneError>`, where `ReasonletIntent`
  is `(string Intent, double Confidence)` with confidence in `[0, 1]`. Its default lives in phase 1.6;
  the Reasonlets design calls for "a simple, swappable default".

The exact member names and parameter lists of `IReasonletStore` are left to
the builder, within the list above. They must follow the house style, and the
facade's needs decide them. Phase 1.4 may add members it needs; this phase
only fixes the contract callers depend on.

### What this phase does not do

- No implementation of the facade or the ports. A facade implementation
  arrives with the store (1.4) and the selector (1.6). No DI registration
  either, since there is nothing to register yet.
- No audit events. Those belong to phase 1.5, which adds them to the store
  port.

- The package README describes the contract in a few lines.

## Tests

Unit tests only:
- Every `Validate()` rejects each invalid input listed above, with a
  `Validation` error naming the field:
  - an empty or whitespace scope, and a `default` scope;
  - a score outside `[0, 1]`;
  - feedback outside `[0, 1]`;
  - `Top` outside `[1, 50]`;
  - a blank question;
  - a negative duration;
  - a `default` ID;
  - a blank `Source`, `Version`, tag key, or present-but-blank `Name` or `Intent`;
  - an invalid nested record, reported by its path, such as `Outcome.Score`.
- Every `Validate()` accepts the boundary values.
- `ReasonletId` and `ExecutionId` created through their `New()` factory are
  version-7 GUIDs and sort by creation order.
- The AOT smoke publish stays clean with the new types; phase 1.1's CI gate
  covers this.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| The facade is fixed before the store and selector exist, so later phases find it awkward | Rework in 1.4 or 1.6 | It is pre-1.0. Breaking it before the M4 API review is allowed, and the ports may grow |
| Phase 1.3 needs a different graph shape | Renames across packages | 1.3 may extend `ReasonletGraph` but not rename its three members; if it truly must, it changes them in 1.3 before anything else uses them |
| ZeroAlloc.Results versions differ across the family (Thalos 1.2.4, Daedalus 1.4.4) | A consumer gets a version conflict | Pin Daedalus's newer version; Renovate keeps it current |
