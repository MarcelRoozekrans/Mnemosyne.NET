**Date:** 2026-10-22

**Surface:** Backend
**Stage:** phase (one phase, implementation-ready)

[roadmap design](2026-10-21-roadmap-design.md): "Mnemosyne owns a minimal,

validation without renaming `Nodes`, `Edges` or `SchemaVersion`.

## Goal

A procedure has one well-defined shape that Mnemosyne stores and compares.
That shape is a versioned JSON format with a published JSON Schema, an
AOT-safe serializer, stricter validation, and a content hash. The hash decides
whether two graphs are "the same procedure". `RememberAsync` uses that answer
to choose between "another execution" and "a new version".

## Approach

### Shape (v1)

```json
{
  "schemaVersion": 1,
  "nodes": [
    { "id": "check-endpoint", "type": "tool", "name": "Check the endpoint", "tool": "http_get" },
    { "id": "decide", "type": "decision" }
  ],
  "edges": [ { "from": "check-endpoint", "to": "decide", "condition": "status != 200" } ],
  "properties": { "daedalus.process": "azure-troubleshooting" }
}
```

- **`ReasonletNode`** keeps `Id` and `Type`, and gains three members:
  - `Name`: an optional human label.
  - `Tool`: the tool name for tool steps, optional.
  - `Properties`: optional, see Extension properties.

  `Type` is a free string. Doc comments list the well-known values `tool`,
  `retrieve`, `decision`, `agent` and `answer`, but other values are valid,
  because the schema is expected to change fast.
- **`ReasonletEdge`** keeps `From` and `To`, and gains two members:
  - `Condition`: an optional label for a branch.
  - `Properties`.
- **`ReasonletGraph`** keeps `Nodes`, `Edges` and `SchemaVersion`, and gains
  `Properties`.
- **Tool arguments are not part of the schema.** A procedure is the steps,
  not the values one run passed. Arguments often carry user data, and the
  roadmap puts redaction before capture in phase 3. A caller that wants an
  argument *template* can put it in `Properties`.
- **The positional records become init-only.** `ReasonletNode`,
  `ReasonletEdge` and `ReasonletGraph` change from positional records to
  `sealed record`s with `required` init members. This is the same rule
  phase 1.2's final review applied to records that will grow, and these
  three just gained members. It changes construction syntax only, never
  member names.

### Extension properties

- `Properties` is `IReadOnlyDictionary<string, JsonElement>?` on the graph,
  on nodes and on edges. It holds caller-defined data that Mnemosyne stores
  and returns but never interprets.
- **Keys are namespaced.** A key must be two or more non-empty segments
  separated by dots, such as `daedalus.process`. So `"."`, `"a."` and `".a"`
  are invalid. Plain-named keys stay free for later schema versions without
  colliding with caller data. A key must be valid UTF-16, and no key may
  repeat in one dictionary under ordinal comparison, which a custom
  `IReadOnlyDictionary` could otherwise do.
- **Property values.** A value must:
  - not be an undefined `JsonElement` (`default`);
  - not belong to a disposed `JsonDocument`;
  - hold only valid UTF-8 and valid UTF-16 in its strings and member names,
    including `\uXXXX` escapes, which must not leave a lone surrogate;
  - have no duplicate member name in any object, compared after unescaping,
    so `"a"` and `"\u0061"` clash;
  - nest at most 32 levels deep.

  JSON `null` is a valid value, and it is distinct from an absent key.
- A null `Properties` and an empty one are the same: both serialize as
  absent and hash the same.
- **Limits** are constants on a static `ReasonletGraphLimits` class:
  - **Size.** The **sum, over every `Properties` dictionary in the graph**
    (graph, nodes and edges), of the UTF-8 byte length of its canonical JSON
    object must be at most 64 KiB (65,536 bytes). The canonical object is
    what `CanonicalGraphWriter` writes for the hash: compact, with the fixed
    RFC 8785 escape set, so a supplementary character counts as its 4 raw
    bytes. The measure does not depend on the runtime's Unicode tables.
  - **Count.** A single graph may have up to 500 nodes and 2,000 edges.
  - **Depth.** Property values may nest at most 32 levels deep
    (`MaxPropertyDepth`). A scalar, an empty array or an empty object is
    level 1. The serializer's `MaxDepth` is 36: the 32 property levels plus
    the 4 structural levels a property value can sit under (root object,
    `edges` array, edge object, `properties` object).
  - **String length**, counted in Unicode code points to match JSON Schema
    `maxLength`, so a surrogate pair counts once:
    `MaxIdentifierLength = 256` for node `Id`, `Type` and `Tool` and edge
    `From` and `To`; `MaxTextLength = 1024` for node `Name` and edge
    `Condition`.
- These limits keep a graph a procedure, not a data dump. Hitting one is a
  `Validation` error.
- Every string in the graph must be valid UTF-16, with no lone surrogate, so
  it survives UTF-8 storage and hashing unchanged.

### Validation (extends 1.2's `Validate()`)

In order, first failure wins:
1. `Nodes` and `Edges` are not null.
2. `SchemaVersion` equals a supported version. Today only `1` is supported:
   any other value, including 0 or a negative one, gives `Validation` with
   "unsupported schema version", not a crash.
3. At least one node.
4. The node and edge counts are within their limits, so an oversized graph
   is rejected before any per-element work.
5. Each node, then each edge, is not null and passes its own `Validate()`,
   field by field: `Id`, `Type`, `From` and `To` are not blank; `Name`,
   `Tool` and `Condition` are not blank when present (a `null` `Condition`
   means unconditional); every string is valid UTF-16; every string is
   within its length limit. For `Condition` the order is UTF-16, then
   non-blank, then length.
6. Node IDs are unique (ordinal comparison), reported at `Nodes[i].Id`.
7. Every edge's `From` and `To` name an existing node, reported at
   `Edges[i].From` or `Edges[i].To`.
8. No duplicate edges with the same `From`, `To` and `Condition`.
9. Every `Properties` dictionary follows the key and value rules above.
   Failures are reported as `Properties["k"]`, `Nodes[i].Properties["k"]`
   and so on, with the same key escaping as phase 1.2.
10. The combined canonical size of all properties is within the limit.

Cycles are **allowed**, since a retry loop is a real procedure. Self-loops are
allowed too. These rules keep the order from phase 1.2: the first failure
wins.

### Serialization

- A source-generated `System.Text.Json` context lives inside Abstractions.
  `System.Text.Json` is in-box, so the "only ZeroAlloc.Results" package rule
  still holds.
- `ReasonletGraphJson` is a public static class with two members:
  - `string Serialize(ReasonletGraph graph)`
  - `Result<ReasonletGraph, MnemosyneError> Deserialize(string json)`
- JSON names are camelCase. Null optional members, and null or empty
  `properties`, are omitted. On input, an explicit `null` on an optional
  member (`name`, `tool`, `condition`, `properties`) means the same as
  leaving it out, and hashes the same.
- `Serialize` writes strings with `JavaScriptEncoder.UnsafeRelaxedJsonEscaping`.
  The output is for storage, not for embedding in HTML. Neither the hash nor
  the size limit uses this text. `Serialize` does not validate: call
  `Validate()` first. It throws `InvalidOperationException` on a
  `default(JsonElement)` property value and `JsonException` past the depth
  limit; a valid graph never throws.
- The input of `Deserialize` must be valid UTF-16. A lone surrogate in the
  text is a `Validation` error, not a silent replacement.
- `Deserialize` returns a `Validation` error for:
  - text that is not valid UTF-16, or malformed JSON;
  - a missing required member;
  - an unknown top-level or node or edge member, which must go in
    `properties` instead;
  - a **duplicate member name in any JSON object**, including inside
    `properties` and nested property values, and including names that only
    match after unescaping;
  - nesting past `MaxDepth`;
  - a graph that fails `Validate()`.

  It never throws on bad input. `System.Text.Json` keeps the last value of a
  duplicate key and drops the rest by default, which is the same silent data
  loss that rejecting unknown members prevents. **Settled:** .NET 10's
  `AllowDuplicateProperties = false` on the source-generated context covers
  the graph objects, the `properties` dictionaries and `JsonElement` values,
  so no `Utf8JsonReader` pre-scan is needed. Tests pin each case.
- Error messages read "path: reason" in one of two path styles. Errors found
  while reading happen before a graph exists, so their path is a JSON path
  into the text, such as `$.nodes[0].colour`, or `$` when the reader has no
  position. Errors from `Validate()` use member paths on the graph, such as
  `Edges[0].To`. A property value one level too deep gets either style,
  depending on its innermost value: an innermost scalar parses and
  `Validate()` reports it, an innermost empty array or object exceeds the
  reader's depth and the reader reports it.
- Unknown members are rejected rather than ignored. Silently dropping
  data would make two different stored graphs hash the same.

### Equality: content hash

- `Result<string, MnemosyneError> ReasonletGraph.ComputeContentHash()` runs
  `Validate()` first and returns its failure. An invalid graph has no
  hash, so the store never persists a hash for an invalid graph. On success
  it returns lowercase hex SHA-256 over a **canonical** serialization:
  - `schemaVersion` is included, so the same content under a later schema
    version is a different procedure. Schema bumps are rare and deliberate.
  - nodes sorted by `Id`;
  - edges sorted by `From`, then `To`, then `Condition` (null first);
  - property keys sorted, at every level, including inside nested
    `JsonElement` objects;
  - arrays inside property values keep their order;
  - numbers written from their **raw JSON text**, so `1` and `1.0` differ.
    That is simple and stable, and writers are expected to be consistent;
  - strings and member names unescaped, then written with the **fixed
    RFC 8785 (JCS) escape set**: only `"`, `\` and U+0000 to U+001F are
    escaped, as `\b \f \n \r \t` where those exist and as lowercase
    `\u00xx` otherwise; everything else, including supplementary
    characters, is raw UTF-8. So escape differences such as `\u0041`
    versus `A` do not change the hash. `CanonicalGraphWriter` emits this by
    hand and consults no Unicode table and no culture, so a .NET upgrade
    cannot change a stored hash;
  - no whitespace.

  Sorting is ordinal, comparing UTF-16 code units. That is RFC 8785's own
  order, so a JCS implementation reproduces the canonical form apart from
  raw number text, which JCS would normalize.
- **Where hashes are computed.** Hashes are computed only in .NET, by
  `ComputeContentHash()`. SQL compares stored hashes and never recomputes
  them.
- Two graphs are the same procedure **if and only if** their content hashes
  are equal. Node IDs count: the same shape with different IDs is a
  different procedure, because IDs are how edges and callers refer to steps.
- `Name` counts too, so renaming a step is a new version. `Properties`
  count as well.
- The hash is what phase 1.4 stores and indexes, so the store can decide
  "equal to parent" in SQL inside the atomic remember.
- **Note for phase 1.4 and Daedalus:** build property values from stable
  .NET types. Raw number text depends on the source type, for example
  `1.0m` writes `1.0` while `1.0d` writes `1`, so the same intent built
  from different types hashes differently.
- No `Equals` override. Records holding collections still must not be
  compared with `==` (phase 1.2 rule). The hash is the comparison.

### Published schema

- `schemas/reasonlet-graph.v1.schema.json` is a JSON Schema (draft 2020-12)
  describing v1. It is committed, and the docsite in phase 1.7 links it.
- Its `$id` is an identifier, not a URL to fetch the schema from.
- Optional members accept an explicit `null`, which means absent.
- Non-blank strings use an explicit character class that mirrors .NET
  `char.IsWhiteSpace`, because ECMA-262 whitespace differs (U+0085,
  U+FEFF). A test checks the class against `char.IsWhiteSpace` for every
  UTF-16 code unit.
- The length limits are expressed with `maxLength`, which JSON Schema counts
  in code points, the same as `Validate()`. JsonSchema.Net 9.4.1, the test
  library, counts text elements instead, so the schema test probes only
  ASCII and supplementary text at the limits.
- The schema accepts some documents that `Deserialize` or `Validate()`
  reject, and its description lists them: `schemaVersion` written as
  anything but the integer literal `1` (such as `1.0` or `1e0`), duplicate
  node ids, unknown edge endpoints, duplicate edges, duplicate member names
  (including escaped ones), escapes that leave a lone surrogate, property
  depth and the canonical property size. Tests pin that each such document
  passes the schema and fails `Deserialize`.
- A test validates the serializer's output against it, using a JSON Schema
  library in the test project only.
- A test also checks that the schema rejects an unknown member.

## Tests

- **Round-trip:** for every valid sample graph, `Deserialize(Serialize(g))`
  succeeds and gives the same content hash.
- **Hash:**
  - Reordering nodes, edges or property keys gives the same hash.
  - Changing any node ID, name, tool, type, edge condition or property
    value gives a different hash.
  - A golden test pins the hash of one fixed graph, so an accidental change
    to canonicalization is caught.
- **Deserialize:** malformed JSON, a missing `nodes` member, an unknown
  member, `schemaVersion: 2`, a duplicate node ID and an edge to a missing
  node each give `Validation` with the right path, and none throws.
- **Limits:** 501 nodes fails, and properties of 64 KiB + 1 fails, also
  when filled with supplementary characters. Each string length limit
  passes at the boundary and fails one past it, with ASCII, supplementary
  and combining text.
- **Schema conformance:** the serializer's output validates against the
  published schema.
- **AOT:** the AOT gate stays green with the source-generated context.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Canonical hashing of nested `JsonElement` property values is subtle (number formats, unicode escapes) | Equal graphs hash differently, which creates spurious versions | Unescape strings and write them with the fixed RFC 8785 escape set, sort ordinally, reject duplicate member names and keys, and pin with a golden test plus reorder and escape-equivalence tests |
| A runtime upgrade changes escaping | Every stored hash splits | The canonical writer emits JSON by hand with a fixed escape set and consults no Unicode table; the size limit uses the same writer |
| Raw number text differs by source type (`1.0m` writes `1.0`) | The same intent hashes differently across writers | Documented for phase 1.4 and Daedalus: build property values from stable .NET types |
| The schema accepts documents that `Validate()` rejects | A non-.NET writer trusts the schema alone | The schema description lists every Validate-only rule, and tests pin each one |
| Invalid UTF-8 or UTF-16 is silently replaced with U+FFFD | Two different inputs store and hash the same | Every string and member name is checked for valid UTF-8 and UTF-16, and `Deserialize` rejects text that is not valid UTF-16 |
| Rejecting unknown members breaks a newer writer talking to an older reader | Interop across versions | `schemaVersion` gates it; a v2 adds members and bumps the version, so an old reader reports "unsupported schema version" clearly |
| Init-only conversion touches many tests | Churn in this phase | Mechanical, and `TestData` builders absorb most of it |
