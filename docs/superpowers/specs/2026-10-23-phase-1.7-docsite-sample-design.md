# Phase 1.7 Design: Docsite skeleton and first sample

**Date:** 2026-10-23
**Phase:** 1.7
**Surface:** Docs
**Stage:** phase (one phase, implementation-ready)

The user asked for a truly 1.0 release with a docsite, examples and CI benchmarks, and for docs and samples to grow with each milestone (**user**, from the roadmap). This phase builds the docsite skeleton and the first sample.

The user skipped the brainstorm questions, so every decision below is **my call** unless marked **user**. The setup copies Rag.NET's, as the user asked for the phase 1.1 scaffold (**user**).

## Goal

A developer who has never seen Mnemosyne can do three things:

1. Land on a published docs site.
2. Understand what a Reasonlet is.
3. In about ten minutes, run a sample that stores a procedure and recalls it, using only Docker and the .NET SDK. No API key is needed.

## Non-goals

- **Full guide coverage.** Milestone 4's "docs completeness" phase covers it. This phase is the skeleton plus the pages milestone 1 needs.
- **An API reference generated from XML docs.** That is milestone 4.
- **Benchmarks in CI.** That is milestone 4.
- **Samples for the integrations.** They come with milestone 3.
- **A custom domain or ZeroAlloc.Website integration.** The site lives at the GitHub Pages address.

## Approach

### Site

**Stack.** Docusaurus 3.10.2 with the classic preset and `@docusaurus/theme-mermaid`, the same versions as Rag.NET.
- The site lives at the repository root: `package.json`, `package-lock.json`, `docusaurus.config.ts`, `sidebars.ts`, `babel.config.js` and `tsconfig.json`, with `src/css/custom.css` as the one customisation point.
- `docs/` is the content, at `routeBasePath: '/'`. Rag.NET's layout keeps one convention across the user's repositories.

**What it excludes.** These stay readable in the repository but are not product docs:
- `superpowers/**`
- `planning/**`

**Address and links.**
- `url: https://marcelroozekrans.github.io` and `baseUrl: /Mnemosyne.NET/`.
- `organizationName: MarcelRoozekrans` and `projectName: Mnemosyne.NET`.
- `editUrl` points at this repository's `docs/`.

**Broken links.** `onBrokenLinks: 'throw'` is kept, never relaxed to `warn`, so a broken link fails the build.

**Logo.** The logo is the existing `assets/` icon, if there is one; otherwise none.

**Content rules:**
- Each page is new prose for a reader, built from the READMEs, XML docs and specs. It is never a copy of a spec or ledger.
- The package READMEs stay short. They link to the site for depth, so the same fact isn't maintained in two long places.
- Numbers and defaults are copied from the code, not paraphrased.
- **Install instructions** use a plain `dotnet add package`, because the first release is 0.1.0, not a prerelease (**my call**).
- **Package README links** to the site are absolute, because NuGet.org renders them. They resolve once GitHub Pages is enabled.
- **Samples:** `samples/Directory.Build.props` sets `IsPackable=false`.
- **Logo:** the repository has no `assets/` folder, so the site ships no logo or favicon for now.
- **Hashing:** the hashing generator uses a stable hash, not `string.GetHashCode`, because the ranking assertion runs in CI.

### Sample

**Location.** `samples/Mnemosyne.Samples.StoreAndRecall`, a console app in the solution.

**What it does:**
1. Starts from `AddMnemosynePostgreSql` and `AddMnemosyne`.
2. Migrates.
3. Remembers three procedures for one scope.
4. Records a few runs.
5. Captures a new version of one of them.
6. Recalls a question and prints the ranked matches with their score breakdown.
7. Erases the scope at the end.

The output shows a new version of a proven procedure ranking first, which is the brainstorm example from phase 1.6.

**PostgreSQL.** A `compose.yaml` next to the sample starts `pgvector/pgvector:pg17`. The connection string comes from `MNEMOSYNE_SAMPLE_PG`, with a default that matches the compose file.

**Embeddings.** No API key is needed. The sample ships a small `HashingEmbeddingGenerator`, an `IEmbeddingGenerator<string, Embedding<float>>`:
- It lowercases the text, splits it into words, hashes each word into one of 256 buckets, and L2-normalises the result.
- It is deterministic, offline, and good enough for word-overlap similarity.
- The sample README and the code comment say plainly that it is a stand-in, and show how to swap in a real model through Microsoft.Extensions.AI, for example Ollama or OpenAI.
- It lives only in the sample, never in a package.

**CI.**
- The sample builds with the solution.
- A CI step runs it against the pgvector service the AOT job already starts, in a database of its own that the step creates (**my call**), and fails on a non-zero exit. A separate database is needed because the AOT smoke migrates the schema with dimension 3, and the sample uses 256. The sample checks its own expected ranking and exits non-zero if the ranking differs, so the docs' claims are tested.

### CI and publishing

- **`.github/workflows/docs.yml`, copied from Rag.NET's.**
  - It builds on pull requests and pushes that touch site inputs.
  - It deploys to GitHub Pages only on a push to `main`, with `pages: write` and `id-token: write` at the job level.
  - Node 24, `npm ci` against the committed lockfile.
- **The `docs/` path filter** has to account for `docs/superpowers/**` and `docs/planning/**` edits. These are excluded from the site, but they would still trigger the build. That's harmless, so accept it and don't add a complicated filter.
- **The root `README.md`** gains the docs badge and a link to the site.
- **Repository settings (user-side):** GitHub Pages must be set to "GitHub Actions" as its source. The phase notes this for the user. It is not a code change.

## Tests and checks

- **Site build.** `npm run build` passes locally and in CI, with zero broken links.
- **Sample:**
  - The sample runs against pgvector and exits 0.
  - Its ranking assertion fails if the selector's order changes. Show this once by breaking it.
- **Hashing generator.** It gets a unit test in the sample, or in the test project if the sample can't host one cheaply. Same text gives the same vector. Shared words give a higher similarity than unrelated text. The output is unit-length.
- **Snippets.** Every code snippet in `getting-started.md` compiles. Compile-check it against the real packages, the same way the README snippets were checked in phase 1.6.
- **Coverage.** It stays at 100% for `src`. The sample is excluded from coverage, since it isn't a package.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Docs drift from code as later phases change behaviour | Readers follow wrong instructions | The sample runs in CI and asserts its output; snippets compile-checked; READMEs link rather than duplicate |
| Hashing embeddings mislead readers about recall quality | Users judge Mnemosyne by a toy | Stated plainly in the sample and on the samples page, with the swap-in for a real model |
| GitHub Pages not enabled | Deploy job fails on the first push to main | Called out as a user-side setting in the PR description |
