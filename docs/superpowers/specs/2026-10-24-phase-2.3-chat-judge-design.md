# Phase 2.3 Design: Chat-model evaluator

**Date:** 2026-10-24
**Phase:** 2.3
**Surface:** Backend
**Stage:** phase (one phase, implementation-ready)

This phase builds on the [phase 2.1 evaluator contract](2026-10-23-phase-2.1-evaluator-contract-design.md) and mirrors the [phase 2.2 Minos evaluator](2026-10-23-phase-2.2-minos-evaluator-design.md). Decisions are marked **user** or **my call**.

## Goal

Ship an `IReasonletEvaluator` that judges a run through an `IChatClient`. It is for hosts that already have a chat model, such as OpenAI, Azure OpenAI, Ollama or Anthropic, and no Minos.NET decision-model provider (**user**). Minos stays the default judge.

## Non-goals

- **Token logprobs.** Many providers and `IChatClient` adapters don't expose them.
- **A critique or reasons.** `ReasonletEvaluation` has no place for them, and it never stores reasoning because reasoning could quote the answer.
- **Retries.** A judge that fails is down; the facade already stores the run with the agent's verdict.
- **Choosing or configuring a model.** The host does that in its `IChatClient` pipeline.

## Approach

### Package (user)

The evaluator ships in the core `Mnemosyne.NET` package. That package already references `Microsoft.Extensions.AI.Abstractions`, where `IChatClient` lives, so the judge adds no dependency and no package. It is opt-in: nothing changes for a host that doesn't register it.

### What the judge asks

The judge asks the same question as Minos:

> Does the answer resolve the question by following the procedure?

**The prompt (user).** Mnemosyne owns the instructions and the reply format, so parsing stays reliable. A host may add judging criteria through `ChatEvaluatorOptions.Criteria`, such as "the answer must cite a source". The criteria go into the instructions; the reply format stays fixed. The host cannot replace the prompt.

**Two messages (my call):**
- A **system message** holds the instructions, the criteria if any, and the reply format spelled out.
- A **user message** holds the run as JSON. The run's text then can't pose as instructions, and the system message can say that the JSON is data to judge, not instructions to follow.

The exact instruction text is the implementer's to write, as long as it says all three of: the question to answer, that the user message is data, and the reply format.

### What the judge sees (my call)

The same four fields as the Minos judge, in this order: `question`, `intent`, `procedure` and `answer`. The procedure is the canonical graph JSON, `ReasonletGraphJson.Serialize`, nested as a JSON value rather than an escaped string. The judge never sees the agent's own outcome or the Reasonlet's name, for the reasons the phase 2.2 spec gives. The state is serialized with a source-generated `JsonSerializerContext`.

### The reply (user: the model states a confidence)

The reply is one JSON object:

```json
{ "worked": true, "confidence": 0.8 }
```

- `worked` is whether the answer resolves the question by following the procedure.
- `confidence` is how sure the model is of that verdict, in [0, 1].

**How it is requested (my call).** `ChatOptions.ResponseFormat` is set to `ChatResponseFormat.ForJsonSchema`, with a hand-written schema constant that requires both fields and allows no others. A provider that supports structured output then enforces the shape. A provider that ignores it still has the format spelled out in the system message. The reply is parsed with a source-generated `JsonTypeInfo`, so the judge is AOT-safe.

**Other chat options (my call).** The evaluator sets only `ResponseFormat`. The model, temperature and token limits come from the host's client pipeline, for example `ChatClientBuilder.ConfigureOptions`, because the right values depend on the model. Some reasoning models reject a temperature, for example.

**The verdict (my call):**
- `Success` is `worked`.
- `Score` is the probability that the run worked, so it means what Minos's score means: `confidence` when `worked` is true, `1 - confidence` when it is false.
- `Evaluator` is the configured `EvaluatorName`, default `llm-judge`. The phase 2.1 contract docs already use that name as their example.

### Failures (my call)

**The judge can't judge: `MnemosyneErrorCode.Unavailable`.** Phase 2.1 then stores the run with the agent's own verdict. These count:
- an empty reply, or no text in it;
- a reply that isn't one JSON object, including prose or a code fence around the JSON (**user**: strict parsing, chosen over extracting the first JSON object);
- a missing `worked` or `confidence`, or either of the wrong JSON type;
- a `confidence` outside [0, 1]. JSON has no NaN, so a NaN can't arrive.

**Unknown extra fields are ignored.** The schema forbids them, but a provider that ignores the schema may add one. Ignoring it costs nothing, and the two required fields still decide the verdict.

The error's message is fixed: "The chat judge could not judge the run." The detail names only the reason, for example `chat: InvalidReply` or `chat: EmptyReply`. It never quotes the reply, which could quote the answer.

**Exceptions and cancellation propagate.** The facade treats an exception as the judge being down and applies `EvaluationTimeout`.

There is no Validation case. Unlike Minos's InvalidQuestions, nothing the chat judge receives can reveal a bug in Mnemosyne's own request.

### Public API (my call)

In namespace `Mnemosyne.NET`:

- `ChatReasonletEvaluator : IReasonletEvaluator`. Its constructor takes `IChatClient` and `ChatEvaluatorOptions` and validates both.
- `ChatEvaluatorOptions`, with init properties:
  - `EvaluatorName`: non-blank, at most `EvaluationLimits.MaxEvaluatorLength` code points, default `llm-judge`;
  - `Criteria`: `string?`, default null. When set, it must not be blank, must be valid UTF-16 and must be at most 4,000 code points;
  - `ChatClientKey`: `object?`, default null. When set, it selects a keyed `IChatClient`, so the judge can have its own model;
  - `Validate()`, using the public `Check`.
- `ServiceCollectionExtensions.AddMnemosyneChatEvaluator(this IServiceCollection, ChatEvaluatorOptions? options = null)`.
  - It registers the evaluator as the singleton `IReasonletEvaluator`, resolving `IChatClient` keyed or not.
  - Invalid options throw `ArgumentException`.

The state, reply and JSON context types are internal.

### Privacy

The provider sees the run's question and answer, as with the Minos judge. That is inherent in judging with a remote model. Mnemosyne's own guarantee still holds: the answer is never stored, logged or sent to telemetry. The docs say not to put a logging middleware that records message content, such as `UseLogging` at a verbose level, on the judge's client unless that is acceptable.

### Telemetry

There are no new Mnemosyne signals. The phase 2.1 `mnemosyne.evaluate` activity wraps this judge, with the evaluator tag `llm-judge`. The client pipeline's own OpenTelemetry spans, from `UseOpenTelemetry`, nest inside it.

## Tests

- **The verdict:**
  - `{"worked": true, "confidence": 0.8}` gives (true, 0.8).
  - `{"worked": false, "confidence": 0.8}` gives (false, 0.2), exactly `1 - 0.8`.
  - Confidence 0 and 1 are accepted for both verdicts.
  - A custom evaluator name is passed through.
- **The request:**
  - Two messages: system, then user.
  - The user message parses to exactly the four fields, in order, with `procedure` an object deep-equal to the canonical graph JSON.
  - Sentinels in the agent's outcome and the Reasonlet's name never appear in either message.
  - The criteria appear in the system message when set and are absent when not.
  - `ResponseFormat` is a JSON schema format.
- **Failures,** each `Unavailable` with the fixed message and a detail free of the reply's text:
  - an empty reply, and a reply with no text;
  - prose around the JSON, a fenced reply, a JSON array, two objects;
  - a missing field, a field of the wrong type;
  - a confidence of -0.01 and of 1.01.
- **Extra fields** are ignored.
- **Propagation:** an exception propagates, and cancellation propagates.
- **Options:** every bad value fails validation: a blank or too-long name, blank or too-long criteria, criteria with a lone surrogate.
- **Registration:** the evaluator resolves; keyed resolution picks the keyed client over the default one; a missing client throws on resolve; invalid options throw.
- **End to end through the facade:** a recorded run with an answer is stored with source `Evaluator` and the judge's verdict. With an unparseable reply it is stored with source `Agent`. The `mnemosyne.evaluate` activity carries `mnemosyne.evaluator = llm-judge`.
- **AOT:** the smoke judges a run through the chat judge under Native AOT.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| A small model ignores the format | Every run is "judge down", so verdicts fall back to the agent | Structured output where the provider has it; telemetry shows the stream of `Unavailable`; the guide names this case and points to the Minos judge |
| A model's stated confidence is uncalibrated | Scores are less meaningful than Minos's | The guide says so; ranking uses `Success`, not `Score` |
| The run's text tries to steer the judge | A wrong verdict | The run goes in a separate user message as JSON, and the instructions call it data |
