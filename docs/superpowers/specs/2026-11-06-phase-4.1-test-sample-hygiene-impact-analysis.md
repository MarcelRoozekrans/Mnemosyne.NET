## Findings against the plan

1. **The five `ConstantEmbeddings` copies are the same vector.** Four are byte-identical; `TelemetryTests` is formatted differently but returns the same `[1f, 0.5f, -0.25f]`. Sharing is safe.
2. **The two `ScriptedModel` copies differ only in what they record** (`Requests` versus `Instructions`) and in the call id source (`Requests.Count` versus `Instructions.Count`). The merged class must take the call id from one list; both lists grow by one per call, so the ids match.
3. **The existing shared sample types are `public` in namespace `Mnemosyne.Samples`.** The plan said `internal`. Each sample's top-level `Program.cs` needs `using Mnemosyne.Samples;`, and its own `internal sealed class SampleFailure` must go, or the names clash.
4. **StoreAndRecall and Evaluation have no capture wait,** so "name the run or act on a capture timeout" applies to ChatPipeline and AgentFramework only, which already do. The plan's conditional step resolves to: nothing to add.
5. **Evaluation keeps `RequireVerdict`, `Check` and `Describe` locally;** they are sample-specific and stay. Only `Require`, `RequireSuccess`, `RequireEqual`, `TryErase`, `SampleFailure` move. StoreAndRecall and Evaluation gain `RequireEqual`, unused unless they call it.
6. **`Mnemosyne.NET.Tests` already references Abstractions,** which holds `Result<T, MnemosyneError>` and `IReasonletMemory`, so the shared file compiles there.
