# Phase 1.1 Design — Repo scaffold, CI and release pipeline

**Date:** 2026-10-21
**Phase:** 1.1
**Surface:** Infra
**Stage:** phase (one phase, implementation-ready)

## Goal

An empty but releasable Mnemosyne.NET: three packages that build, test, pack and
pass a Native AOT gate in CI, with versioning, release-please, Renovate and
Codecov wired the way Rag.NET does it.

## Approach

**Copy Rag.NET** (**user**), at `~/Projects/Prive/Rag.NET`, and cut it down to
what a three-package repo needs. Copy the files and adapt names, URLs and
tags. Drop what is Rag.NET-specific: its cassette issue template, its 66-package
lists, its LLM nightly, and the SDK-workaround comments whose upstream bug no
longer applies. Check each workaround before dropping it: keep one when the
pinned SDK still needs it.

What comes over:
- **Build settings:** `Directory.Build.props` (net10.0, nullable,
  warnings as errors, shared package metadata), `Directory.Build.targets`,
  `Directory.Packages.props` (central package management) and `global.json`.
- **Repo files:** `.editorconfig`, `.gitignore`, `.gitattributes` and
  `.commitlintrc.yml`.
- **Versioning:** `GitVersion.yml` with `next-version: 0.1.0`, and
  `.config/dotnet-tools.json` for GitVersion as a local tool.
- **Releases:** `release-please-config.json` with `bump-minor-pre-major`, plus
  `.release-please-manifest.json`.
- **Renovate:** `renovate.json` extending `local>MarcelRoozekrans/renovate-config`.
- **GitHub:** the PR template, the bug-report issue template and its config.

**Projects.** Three empty packages, so packing and the AOT gate have something
real to check from day one:
- `src/Mnemosyne.NET.Abstractions`
- `src/Mnemosyne.NET`
- `src/Mnemosyne.NET.PostgreSql`

Each has its own `Description` and sets `IsAotCompatible=true`, which turns on
the trim and AOT analyzers. Warnings are errors, so an AOT-unsafe call fails the
build. One unit test project, `tests/Mnemosyne.NET.Tests`, uses the same test
stack as Rag.NET (xunit v3 on Microsoft.Testing.Platform) and holds a smoke test.
The pgvector integration test project comes with the store in phase 1.4. All
projects are listed in `Mnemosyne.NET.slnx`.

**CI** (`.github/workflows/ci.yml`), modelled on Rag.NET's jobs:
- `build-test`: build and test, then upload coverage to Codecov.
- `commitlint`: on pull requests.
- `pack-validate`: pack with the GitVersion version and validate the packages.
- `aot-publish` (new, after AI.Sentinel's `aot-publish.yml`): publishes
  `tests/Mnemosyne.NET.AotSmoke` with `PublishAot=true` on linux-x64 and fails
  on any IL warning. That console app references all three packages and calls
  into each. It is a job in `ci.yml` rather than its own workflow, so it can be
  a required check on the Main ruleset. (**my call**)
- `publish-nuget`: on release. NuGet authentication works the same way as in
  Rag.NET.

`release-please.yml` is copied too. The docsite workflow (`docs.yml`) belongs to
phase 1.7. Nightly runs and benchmarks belong to milestone 4.

## Tests

- Locally, with one test suite running at a time on the shared VM:
  - `dotnet build`
  - `dotnet test`
  - `dotnet pack`
  - the AOT smoke publish
- Gate check: an AOT-unsafe call, such as unannotated reflection, added to a
  package temporarily must fail the build or the AOT job. Revert it before
  committing.
- CI: all jobs green on this phase's PR.

## Open Questions

None. Copying Rag.NET settles the rest.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Rag.NET's files carry workarounds for problems this repo doesn't have | Dead configuration nobody understands | Keep a workaround only when its reason still applies to the pinned SDK; otherwise drop it |
| An empty package gives the AOT gate nothing to catch | The gate passes without ever being proven | The temporary AOT-unsafe call in Tests proves it fails |
| NuGet publishing needs a secret or trusted-publishing setup on GitHub | First release fails | `publish-nuget` only runs on release; the GitHub-side setup is a manual step for the user, listed in the PR |

## Manual steps for the user, after the first CI run

These are GitHub settings, not code:
- Create the Main ruleset requiring PRs and the CI checks, with the Renovate
  app bypass, like the other repos.
- Add the Codecov token and badge.
- Set up NuGet authentication, the same way as Rag.NET.
