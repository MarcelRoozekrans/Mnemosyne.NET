# Phase 4.7 Subject Export Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A host reads everything a subject owns in a scope, page by page, through `IReasonletMemory` and `IReasonletStore`, and the export set equals the set `EraseAsync` removes (#69).

**Architecture:** Two paged reads shaped like `ListPendingAsync`: `ListSubjectReasonletsAsync` and `ListSubjectRunsAsync`, an id cursor, a limit of 1 to 100, ordered by id. The facade validates and delegates; the PostgreSQL store reads on the existing `(scope, subject_id)` indexes. Two new records carry the rows. Reads bypass the capture guard and the review gate.

**Tech Stack:** .NET 10, ZeroAlloc.ORM attribute queries (`[Query]`), ZeroAlloc.Results, xUnit, PostgreSQL + pgvector in Docker.

**Spec:** `docs/superpowers/specs/2026-11-06-phase-4.7-subject-export-design.md`

## Global Constraints

- Branch from the latest `main`, one feature branch and PR for the phase; push with an explicit `branch:branch` refspec.
- Commits are conventional, with no Claude signature or session link, no nested parentheses in bodies, and body and footer lines of at most 100 characters.
- New public API goes in `PublicAPI.Unshipped.txt` of the project that declares it; `PublicAPI.Shipped.txt` is not touched.
- Native AOT stays green: plain records, no reflection.
- Codecov aims for 100% patch coverage, so every new branch has a test. Record `with` copies need a test.
- The repo refuses `dotnet test --filter`: build first, then run the test exe with `-class <FQN>`.
- A fake credential fixture needs an inline `// gitleaks:allow`; this phase has none.
- Limit is 1 to 100 (the existing `MaxPendingLimit` in the facade and in the store); error texts follow `ListPendingAsync`'s (`limit: must be from 1 to 100`).

## Review Focus

- A subject whose only Reasonlets are `PendingReview`: they are exported (Task 3 test).
- A run by another subject on the subject's Reasonlet: exported with the Reasonlet's runs. A run by the subject on another owner's Reasonlet: exported, and that Reasonlet's definition is not (Task 4 test).
- The same subject id in two scopes: only the asked scope is read (Tasks 3 and 4 tests).
- A row count that is an exact multiple of the limit: the last page is full and the page after it is an empty success (Tasks 3 and 4 tests).
- A Reasonlet without a metrics row reads as zero runs with `LastExecutedAt` at its creation time, and a subject id differing only in case matches nothing (Task 3 tests).
