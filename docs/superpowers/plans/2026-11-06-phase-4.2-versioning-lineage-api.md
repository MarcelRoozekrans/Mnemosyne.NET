# Versioning and lineage API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A recall names the lineage of each match, and the selector-path types can grow, so variant selection in milestone 5 is an addition.

**Architecture:** `ReasonletCandidate`, `ReasonletMatch` and `ReasonletEvidence` become init-only records first, as a behaviour-neutral change. Then `LineageId`, the root of the version tree, is added to candidate and match; the PostgreSQL store resolves it with one extra recursive query after the nearest-neighbour search, and `ReasonletSelector` copies it. A test-only variant selector proves the seam.

**Tech Stack:** .NET 10, xunit v3 on Microsoft.Testing.Platform, ZeroAlloc.ORM source-generated queries, PostgreSQL with pgvector (Docker).

**Spec:** `docs/superpowers/specs/2026-11-06-phase-4.2-versioning-lineage-api-design.md`

## Global Constraints

- The repo refuses `dotnet test --filter`. Build first, then run a test exe with `-class <FQN>`; the exe sits under `<project>/bin/Release/net10.0/`.
- No Claude signature or session link in commits. No nested parentheses in commit bodies.
- The init-only conversion is a breaking change to a public type: its commit uses `refactor!:` and a `BREAKING CHANGE:` footer in plain words.
- `LineageId` is the id of the root of the version tree, reached by `ParentId` within the scope. A root's is its own id. A version whose parent was erased is its own root.
- Version labels stay `1.k` and are documented as opaque; no label code changes.
- Native AOT stays a CI gate: no reflection in new code.

## Review Focus

- A `parent_id` cycle that only hand-written SQL can create: the lineage query ends after one lap and the search still returns.
- A search that returns no rows: no lineage query runs, and the result is an empty success.
- Several candidates in one lineage, at different depths: all report the same `LineageId`.
- A lineage 200 versions deep: the search returns in the time of a shallow one, plus a linear walk.
- A version whose parent was erased by a subject erasure: its `LineageId` is its own id.

Later tasks and phase 4.4 use `LineageId` on both types.

- [ ] **Step 1: Write the failing unit tests** in `ReasonletSelectorTests`: `RankAsyncCopiesTheCandidatesLineageIdToTheMatch` (two candidates with different `LineageId`, assert each match carries its candidate's), and in `LeafRecordTests`: `ReasonletMatchValidateRejectsADefaultLineageId` and `ReasonletCandidateValidateRejectsADefaultLineageId` (assert a `Validation` error whose path is `LineageId`).
- [ ] **Step 2: Run** `dotnet test tests/Mnemosyne.NET.Tests -c Release`. Expected: FAIL to compile.
- [ ] **Step 3: Add `LineageId`** to both records as `required ReasonletId LineageId { get; init; }`, validated with `Check.NotDefault(LineageId, nameof(LineageId))`; `ReasonletSelector` sets it on each match.
- [ ] **Step 4: Add the query.** `ResolveLineageRootsAsync` is a `[Query]` on `ReasonletRepository`: a `WITH RECURSIVE up (start_id, id, parent_id)` seeded from the rows with `scope = @scope AND id = ANY(@ids)`, stepping with the `LATERAL ... LIMIT 1` form and `UNION` that `WalkUpAsync` uses, ending with `SELECT start_id, id FROM up WHERE parent_id IS NULL`. Document the cycle behaviour in its summary as `WalkUpAsync` does. A cycle has no row with a null parent, so those ids map to nothing; the store then uses the candidate's own id as its lineage.
- [ ] **Step 5: Map it.** In `SearchCoreAsync`, after `SearchAsync` and before the commit, when `rows.Count > 0` call `ResolveLineageRootsAsync(scope.Value, [.. rows.Select(r => r.Id)], transaction, ct)`, build a dictionary from start id to root id, and set `LineageId = new ReasonletId(root ?? row.Id)` on each candidate., using `new ReasonletId(guid)`.
- [ ] **Step 6: Fix every Task 1 site** by adding `LineageId`, the unit-test value being any non-default id.
- [ ] **Step 7: Build and run the unit project.** Expected: all pass.
- [ ] **Step 8: Commit** `feat: report the lineage of each recalled Reasonlet`, body `Adds LineageId to the candidate and the match, resolved by one recursive query after the nearest-neighbour search.`
