# Phase 2.5 Evaluation Docs and Sample Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An offline evaluation sample that CI runs and checks, a concept page for the evaluation loop, a guide for writing your own `IReasonletEvaluator`, and links from the existing pages.

**Architecture:** A new console sample, `samples/Mnemosyne.Samples.Evaluation`, built like StoreAndRecall: PostgreSQL + pgvector, the offline hashing embedding generator, and a rule-based evaluator of its own. It walks three acts and exits 1 when its output differs from what the docs publish. Two new Docusaurus pages link out to `concepts/ranking.md` for the maths instead of restating it.

**Tech Stack:** .NET 10, Mnemosyne.NET, Mnemosyne.NET.PostgreSql, Npgsql, Docusaurus 3 with an autogenerated sidebar and `onBrokenLinks`/`onBrokenAnchors: 'throw'`.

**Spec:** `docs/superpowers/specs/2026-10-28-phase-2.5-evaluation-docs-design.md`

## Global Constraints

- No library code in `src/` changes, unless writing the docs exposes a defect or a misleading API. Fix that here, per the review-loop rule, but add no features.
- The new pages restate no ranking formula. They link to `concepts/ranking.md` (`#success-rate`, `#judged-and-agent-only-runs`, `#the-evidence-on-each-match`, `#when-recall-fails`, `#settings`).
- The sample's evaluator never prints, logs or puts in an error the question or the answer. It returns `Unavailable` only for a backend failure; it has no backend, so it never fails.
- `ReasonletEvaluation` is `(bool Success, double Score, string Evaluator)`. There is no reason field, and no page may describe one.
- Commit messages are conventional, with no nested parentheses in bodies, footer lines of at most 100 characters, and no Claude trailer or session link.
- Docs house style: short sentences, plain words, tables for fields and settings, and code snippets that compile against the shipped API.

## Review Focus

1. **The judged procedure doesn't actually outrank the agent-only one in act 1.** The offline embedding gives the two questions different similarities, so the success rate alone may not decide. Task 1 asserts the order and the totals, and prints the similarity column, so a reviewer can see the cause.
2. **A run recorded without an answer still reaches the evaluator.** Task 1 checks every agent-only receipt says `Source = Agent`, and every judged one says `Evaluator`.
3. **The numbers published in `docs/samples.md` drift from a real run.** Task 4 copies them from the sample's actual output, and the sample asserts the same numbers.
4. **A link or anchor in a new page breaks.** Every task that touches `docs/` runs `npm run build`, which throws on a broken link or anchor.
5. **Running both samples' compose files at once clashes on port 5432.** Task 1 uses host port 5433 and a matching default connection string.

- Modify: `.github/workflows/ci.yml` (two steps after "Run the store-and-recall sample")

**Interfaces:**
- Produces: `internal sealed class ChecklistEvaluator : IReasonletEvaluator`, in namespace `Mnemosyne.Samples.Evaluation`.
  - `public const string Id = "sample-checklist"`.
  - `EvaluateAsync(ReasonletEvaluationRequest request, CancellationToken ct)` calls `ct.ThrowIfCancellationRequested()` first.
  - The rule: an answer works when it contains a refund reference matching `REF-\d+` **and** the word `notified`, case-insensitive.
  - It returns `new ReasonletEvaluation(Success: met, Score: met ? 1.0 : 0.0, Evaluator: Id)`.
  - It ignores `request.Outcome`, which is the point of act 2.
  - Its XML doc comment states the rule. Tasks 3 and 4 quote this class.
- Produces: the sample's printed final table and totals, which Task 4 copies into `docs/samples.md`.

**The walkthrough.** Use one fresh scope, erased in `finally`, as StoreAndRecall does. The default connection string is `Host=localhost;Port=5433;...;Database=mnemosyne_evaluation_sample`, and `MNEMOSYNE_SAMPLE_PG` overrides it. Register `services.AddSingleton<IReasonletEvaluator, ChecklistEvaluator>()` before `AddMnemosyne()`. The two procedures answer near-identical questions, so similarity is close and the success rate decides. Pick the wording, and check the similarities in the printed output.

- **Procedure A, "refund by hand".** Remember it without an answer, then record 7 runs without a question or answer, all with the agent's success. That makes 8 agent-only runs.
- **Procedure B, "refund through the API".** Remember it with a question and an answer that meets the rule, then record 5 runs with a question and a passing answer. That makes 6 judged successes.
- **Act 1.** Recall, and print the rank, name, similarity, success rate, total, `Evidence.Runs` and `Evidence.JudgedRuns`. Expect B above A: rates of about 0.773 against 0.722.
- **Act 2.** Record one run on B where the agent reports success, with an answer that lacks `notified`. Assert the receipt is `Source = Evaluator, Success = false`, and print the receipt. Recall: expect A above B, at a rate of about 0.708. Keep that run's `ExecutionId`.
- **Act 3.** Call `RecordFeedbackAsync(scope, thatExecution, new ReasonletFeedback(1, 1, 1, Worked: true), ct)`. This is a person saying the customer was in fact notified. Recall: expect B above A again, at a rate of about 0.792.
- **Printing the why.** Print the rule once at the start, and before each act say in one line which answers meet it. Describe the answers in words; never echo their text from inside the evaluator.

  - **Reading the evidence.**
  - **Choosing a judge.** A table of Minos, the chat model and your own, with links.

### Task 3: `docs/guides/custom-evaluator.md`

**Files:**

**Interfaces:**
- Consumes: `ChecklistEvaluator` (Task 1) as the worked example. Paste it as it is in the repo.

- [ ] **Step 1:** Write the page. It has these sections:
  - **The request.** The fields of `ReasonletEvaluationRequest`. It arrives valid.
  - **The verdict.** `Success`, `Score` within 0 to 1, and `Evaluator`, which must not be blank, must be valid UTF-16 and must be at most `EvaluationLimits.MaxEvaluatorLength` (read the value off the code). Say what the facade does with a verdict that fails `Validate`. Say there is no reason field, and why.
  - **Errors.** `MnemosyneErrorCode.Unavailable` makes the agent's verdict count. Any other error is a bug, and the facade throws for it. Never quote the question or the answer.
  - **Cancellation.** Throw, don't return. `EvaluationTimeout` stops the wait even for a judge that ignores the token.
  - **Register it.** Register it as a singleton before or after `AddMnemosyne`, and say which works: `AddMnemosyne` picks up the registered `IReasonletEvaluator`.
  - **Test it.** Call `EvaluateAsync` directly with a built request.
  - **Telemetry.** The evaluate activity, with a link to `telemetry.md`.
