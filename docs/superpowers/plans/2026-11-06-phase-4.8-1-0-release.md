# 1.0.0 release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Mnemosyne.NET 1.0.0 through release-please and `publish-nuget`, then enable `EnablePackageValidation` against baseline 1.0.0.

**Architecture:** Two stages. Stage A proves the `Release-As` trigger, prepares the packages and puts the footer on the final phase PR, then Marcel merges the release PR. Stage B runs after 1.0.0 is on nuget.org and adds package validation in its own small PR.

**Tech Stack:** release-please action v5, GitHub Actions, GitVersion, NuGet, MSBuild package validation.

**Spec:** `docs/superpowers/specs/2026-11-06-phase-4.8-1-0-release-design.md`

## Global Constraints

- Never tag by hand and never push a package by hand. release-please makes the tag and the release; `publish-nuget` publishes. A failure is fixed in the pipeline.
- The agent prepares and verifies. Marcel merges the phase PRs and the release PR. Tasks 3, 4 and 6 stop and ask him to merge.
- A `Release-As: 1.0.0` footer is the last paragraph of the commit message. Commitlint must pass on it. No Claude signature or session link in any commit, and no nested parentheses in a commit body.
- `EnablePackageValidation` is added only after `https://api.nuget.org/v3-flatcontainer/mnemosyne.net/index.json` lists 1.0.0. Before that, the baseline restore fails.
- Push with an explicit `branch:branch` refspec, because `push.default` is `upstream`.
- Phases 4.1 to 4.6 are merged before Task 4.

## Review Focus

- The trigger is proven before the final PR, not assumed (Task 1).
- The footer survives the repository's squash-merge message setting (Task 1).
- Step B's check proves package validation fails on a real breaking change (Task 7).

- Stage A: package READMEs (1.0 note), the `GitVersion.yml` comment, the final PR's commit message.
