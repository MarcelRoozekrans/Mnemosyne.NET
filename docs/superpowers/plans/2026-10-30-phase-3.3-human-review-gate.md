# Phase 3.3 Human Review Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** With `MnemosyneOptions.RequireReview` on, new Reasonlets and new versions are stored as `PendingReview` and kept out of recall. A reviewer lists them with their metrics, approves them into recall, or rejects them, which deletes them.

**Architecture:** The facade copies the option onto a new `ReasonletStoreEntry.ReviewRequired` flag. The PostgreSQL store applies it inside its existing atomic remember, to the rows it inserts. `ApproveAsync`, `RejectAsync` and `ListPendingAsync` are added to `IReasonletStore` and `IReasonletMemory`. The facade validates and delegates. The store runs each through `StoreTelemetry.RunAsync`. Migration `0004_review.sql` adds a partial index and moves the schema to version 4.

**Tech Stack:**
- .NET 10
- ZeroAlloc.Results
- ZeroAlloc.ORM, using source-generated `[Query]` and `[Command]`
- Npgsql
- PostgreSQL + pgvector
- xunit v3
- System.Diagnostics, for activities and metrics

## Global Constraints

**Types and signatures:**
- `MnemosyneOptions.RequireReview` is a `bool`, default `false`. It is validated like nothing else, because any value is valid.
- `ReasonletStoreEntry` gains `bool ReviewRequired = false` as its last positional parameter.
- `ReasonletReview` is `public sealed record ReasonletReview(ReasonletDefinition Definition, ReasonletMetrics Metrics)` in namespace `Mnemosyne.NET.Abstractions`, at `src/Mnemosyne.NET.Abstractions/Records/ReasonletReview.cs`. Its `Validate()` nests `Definition` under `Definition` and `Metrics` under `Metrics`, and checks that `Definition` is not null.
- The new members are identical on `IReasonletStore` and `IReasonletMemory`:
  - `ValueTask<UnitResult<MnemosyneError>> ApproveAsync(ReasonletScope scope, ReasonletId id, CancellationToken ct)`
  - `ValueTask<UnitResult<MnemosyneError>> RejectAsync(ReasonletScope scope, ReasonletId id, CancellationToken ct)`
  - `ValueTask<Result<IReadOnlyList<ReasonletReview>, MnemosyneError>> ListPendingAsync(ReasonletScope scope, int limit, ReasonletId? after, CancellationToken ct)`

**Behaviour:**
- With `ReviewRequired`, a `NewReasonlet` or a `NewVersion` is inserted with status `PendingReview` (2), and its receipt says so. An `ExecutionOnly` capture never changes the parent's status.
- Approve sets status 1. It succeeds on an `Active` Reasonlet without changing it.
- Reject deletes only a `PendingReview` Reasonlet that has no child in its scope.
- The list call orders by `id`, returns rows with `id > after`, and accepts a `limit` from 1 to 100.

**Error texts (pinned):**
- Missing Reasonlet: `NotFound`, "The Reasonlet does not exist in the scope." This is the existing text.
- Rejecting an active Reasonlet: `Conflict`, "Only a Reasonlet pending review can be rejected."
- Rejecting a Reasonlet with a child: `Conflict`, "The Reasonlet has versions below it; approve or reject them first."
- Bad limit: `Validation`, "limit: must be from 1 to 100".
- A `default` `after`: `Validation` with path `after`, through `Check.NotDefault`.

**Schema:**
- `0004_review.sql` creates `CREATE INDEX reasonlets_pending ON mnemosyne.reasonlets (scope, id) WHERE status = 2`.
- It sets `schema_version` to `'4'` and leaves `min_binary_schema` at `'3'`, because an older binary works against the extra index.
- The store's `SchemaVersion` becomes 4.

**Telemetry:**
- The store operations are named `approve`, `reject` and `list_pending`.
- Approve and reject tag `mnemosyne.reasonlet.id` before they run.
- List tags `mnemosyne.list.limit` before it runs and `mnemosyne.list.returned` on success.
- A successful remember adds `mnemosyne.reasonlet.status`, `active` or `pending_review`.
- No signal carries a name, intent, graph, question or provenance value.

**Rules that apply to every task:**
- Everything stays Native AOT and trim clean.
- Focused test runs: `dotnet build tests/<project>`, then `tests/<project>/bin/Debug/net10.0/<project> -class <FQN>`. The repo refuses `dotnet test --filter`. The PostgreSQL tests need Docker for their pgvector fixture.
- Commits are conventional (`feat:`, `test:`, `docs:`). No Claude trailer and no session link. No nested parentheses in commit bodies. Footer lines are at most 100 characters.

## Review Focus

1. **A reject racing a remember that adds a version below the pending Reasonlet.**
   - Expected: either the reject answers `Conflict` and the child keeps its `parent_id`, or the remember answers `NotFound`. A version must never be orphaned.
   - Covered in Task 3 by `RejectRacingAVersionNeverOrphansIt`.
2. **A reject racing an approve.**
   - Expected: either the approve answers `NotFound`, or the reject answers `Conflict`. An approved Reasonlet must never be deleted.
   - Covered in Task 3 by `RejectRacingApproveNeverDeletesAnApprovedReasonlet`.
3. **The gate turned on for a scope that already holds active Reasonlets.**
   - Expected: they stay recallable, and a rerun of one, which is `ExecutionOnly`, keeps it active.
   - Covered in Task 2 by `AnExecutionOfAnActiveParentKeepsItActiveUnderTheGate`.
4. **Approve or reject with an id that exists only in another scope.**
   - Expected: `NotFound`, with nothing changed in either scope.
   - Covered in Task 3 by `ApproveAndRejectInAnotherScopeAreNotFound`.
5. **A pending Reasonlet with runs recorded against it shows up in the list.**
   - Expected: the item's metrics count those runs, and an item without runs reads as zero counts with `LastExecutedAt` equal to `CreatedAt`.
   - Covered in Task 4 by `ListedMetricsCountRunsOnThePendingReasonlet`.

- Produces: `ReasonletPostgreSqlStore.ApproveAsync` and `RejectAsync`, with the Global Constraints signatures.
- New repository members:
  - `Task<Guid?> ApproveAsync(string scope, Guid id, CancellationToken ct)`. This is `UPDATE mnemosyne.reasonlets SET status = 1 WHERE scope = @scope AND id = @id RETURNING id`; null means not found.
  - `Task<RejectTargetRow?> LockForRejectAsync(string scope, Guid id, IAsyncDbTransaction transaction, CancellationToken ct)`. It runs `SELECT status, EXISTS (SELECT 1 FROM mnemosyne.reasonlets c WHERE c.scope = @scope AND c.parent_id = @id) AS has_children ... FOR UPDATE`, with `RejectTargetRow(short Status, bool HasChildren)` in `Rows/`.
  - The `EXISTS` must run after the lock is granted. If one statement does not guarantee that under READ COMMITTED, because the subquery's snapshot is taken before the wait, lock in one statement and check the children in a second one. A comment must say why.

- [x] **Step 1: Write the failing tests in `ReviewTests`.**
  - `ApproveMakesAPendingReasonletRecallable`: after approve, search finds it and `GetAsync` returns `Active`.
  - `ApprovingAnActiveReasonletSucceeds`.
  - `RejectDeletesThePendingReasonletAndItsRuns`:
    - setup: record a run with feedback against the pending Reasonlet;
    - after the reject, `GetAsync` is `NotFound`, and the `reasonlet_executions`, `reasonlet_feedback` and `reasonlet_metrics` rows for that id are gone, checked with raw SQL counts;
    - other Reasonlets in the scope are untouched.
  - `RejectingAnActiveReasonletIsAConflict`: pinned text, and the row is still there.
  - `RejectingAReasonletWithAVersionIsAConflict`: pinned text, and both rows are still there.

  - `RejectRacingAVersionNeverOrphansIt`:
    - open a transaction that runs `SELECT ... FOR NO KEY UPDATE` on the pending parent, as the remember's lock does;
    - start the reject, insert a child through raw SQL in that transaction, then commit;
    - the reject answers `Conflict`, and the child's `parent_id` is still the parent's id;
    - then the reverse order: hold a `FOR UPDATE` in a transaction that deletes the parent, and `RememberAsync` with that parent answers `NotFound`.
  - `RejectRacingApproveNeverDeletesAnApprovedReasonlet`: run approve and reject concurrently 20 times on fresh pending Reasonlets. Every outcome is either approve OK with reject `Conflict`, or reject OK with approve `NotFound`. An approved Reasonlet is never missing afterwards.
  - Telemetry: the activities `mnemosyne.approve` and `mnemosyne.reject` carry `mnemosyne.reasonlet.id` and the shared outcome. `Conflict` maps to its error name.
