# Phase 3.2 Redaction Hook Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `RememberAsync` asks an optional `ICaptureGuard` about every valid capture before anything else. A blocked capture answers `MnemosyneErrorCode.Blocked`, and a guard that is down answers `Unavailable`. Both drop the capture, and both leave telemetry with no content in it.

**Architecture:** There is a new port and verdict in `Mnemosyne.NET.Abstractions`. The guard is injected into `ReasonletMemory` as a last optional constructor parameter and resolved by `AddMnemosyne`. The guard call mirrors the judge call in `ReasonletMemory.EvaluateAsync`: a linked timeout, a hard stop, and abandoning a guard that ignores its token. A new internal `GuardTelemetry`, shaped like `EvaluationTelemetry`, records each call.

**Tech Stack:**
- .NET 10
- ZeroAlloc.Results
- Microsoft.Extensions.DependencyInjection
- System.Diagnostics (Activity and Metrics)
- xunit v3
- PostgreSQL + pgvector for the round trip

**Spec:** `docs/superpowers/specs/2026-10-30-phase-3.2-redaction-hook-design.md`

## Global Constraints

- `MnemosyneErrorCode.Blocked = 5`. Values 1 to 4 are unchanged, and 0 stays undefined.
- The port and the verdict live in namespace `Mnemosyne.NET.Abstractions`, at `src/Mnemosyne.NET.Abstractions/Ports/ICaptureGuard.cs` and `src/Mnemosyne.NET.Abstractions/Records/CaptureVerdict.cs`.
- `CaptureVerdict.Guard` and `CaptureVerdict.Detector` follow the rule for `ReasonletEvaluation.Evaluator`: not blank, valid UTF-16, at most `EvaluationLimits.MaxEvaluatorLength` (100). `Detector` is non-null exactly when `IsBlocked`.
- `MnemosyneOptions.GuardTimeout` defaults to 30 seconds. It has the same range and the same validation message as `EvaluationTimeout`.
- The constructor becomes `ReasonletMemory(store, selector, embeddings, extractor, evaluator, options, TimeProvider? timeProvider = null, ICaptureGuard? guard = null)`. No existing caller changes.
- The guard runs only after `capture.Validate()` succeeds, and before intent resolution, the embedding and the judge.
- Error texts are pinned:
  - Blocked: `Message = "A capture guard blocked the capture."`, `Detail = $"{verdict.Guard}/{verdict.Detector}"`.
  - Guard down: `Message = "The capture guard failed."`. On an exception or a timeout, `Detail` is the exception's full type name, through the existing `DependencyFailed`. On an `Unavailable` result, `Detail` is null.
- Telemetry names are pinned. The activity is `mnemosyne.guard`, with these tags:
  - `mnemosyne.guard`: the guard's name;
  - `mnemosyne.guard.blocked`: a bool;
  - `mnemosyne.guard.detector`: only when blocked.
- A blocked call also adds the event `mnemosyne.capture.blocked`, carrying the tags `mnemosyne.guard` and `mnemosyne.guard.detector`.
- The counter is `mnemosyne.guard.inspections`, with unit `{inspection}` and description "Capture guard calls, by guard and outcome.", tagged `mnemosyne.guard` (only from a valid verdict) and `mnemosyne.outcome`. The outcome is one of `allowed`, `blocked`, an error code's name, or `exception`.
- The histogram is `mnemosyne.guard.duration`, in seconds, with description "How long capture guard calls take, by guard.", tagged `mnemosyne.guard` (only from a valid verdict).
- The shared `mnemosyne.operations` and `mnemosyne.operation.duration` record operation `guard`. Its outcome is `ok` for any valid verdict, an error code's name for an error, and `exception` for an exception.
- No signal, error or exception message carries the question, the answer, the intent, the name, the graph, or a guard's error text.
- Everything stays Native AOT and trim clean.
- Focused test runs: `dotnet build tests/Mnemosyne.NET.Tests`, then `tests/Mnemosyne.NET.Tests/bin/Debug/net10.0/Mnemosyne.NET.Tests -class <FQN>`. The repo refuses `dotnet test --filter`. PostgreSQL tests run the same way from `tests/Mnemosyne.NET.PostgreSql.Tests/bin/Debug/net10.0/Mnemosyne.NET.PostgreSql.Tests`.
- Commits are conventional: `feat:`, `test:`, `docs:`. No Claude trailer and no session link. No nested parentheses in commit bodies. Footer lines are at most 100 characters.

## Review Focus

1. **A guard that ignores its cancellation token and never returns.** The facade must still answer `Unavailable` after `GuardTimeout`, and must not hang. Covered in Task 4: `AGuardThatIgnoresItsTokenTimesOut`.
2. **A guard whose verdict is `default`.** It must throw `InvalidOperationException` and must never be read as an allow. Covered in Task 4: `ADefaultVerdictIsAnAdapterBug`.
3. **A guard that returns an error carrying the question in its message.** That text must not reach the returned error or any signal. Covered in Task 5: `NoSignalOrErrorCarriesCaptureText`, which uses canary text and a guard error that quotes it.
4. **The caller's token already cancelled before `RememberAsync`.** It must throw `OperationCanceledException`, not return `Unavailable`. Covered in Task 4: `TheCallersCancellationPropagates`.
5. **The guard blocks a capture that has a `ParentId`, which would have been an execution or a new version.** Nothing reaches the store, so no execution is recorded either. Covered in Task 4: `ABlockedRerunRecordsNoExecution`.
