# Phase 1.4 PostgreSQL + pgvector Store Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `Mnemosyne.NET.PostgreSql` implements `IReasonletStore` on PostgreSQL + pgvector with ZeroAlloc.ORM. It covers atomic remember, get, executions, feedback, scoped vector search and erasure. The schema comes from migrations the host runs, and the package is Native-AOT-clean.

**Architecture:** `ReasonletPostgreSqlStore` takes an `NpgsqlDataSource` and `MnemosynePostgreSqlOptions`, and opens one connection per operation as `IAsyncDbConnection` (`connection.AsAsync()`). Internal `partial` repository classes hold the generated `[Query]`/`[Command]` methods. SQL names every table under the fixed `mnemosyne` schema. Embeddings bind as `float[]` (binary `real[]`) and are cast with `::vector`. `RememberAsync` and `EraseAsync` each run in one `IAsyncDbTransaction` at READ COMMITTED, with `FOR UPDATE` locks.

**Tech Stack:**
- .NET 10.
- ZeroAlloc.ORM 2.7.0 and ZeroAlloc.ORM.Generator 2.7.0. 2.7.0 is the release with float arrays; it must be on NuGet before Task 1.
- AdoNet.Async and AdoNet.Async.Adapters 1.4.0.
- Npgsql 10.0.3.

## Global Constraints

- Every type is in namespace `Mnemosyne.NET.PostgreSql`. Public API is limited to `ReasonletPostgreSqlStore`, `MnemosynePostgreSqlOptions` and `ServiceCollectionExtensions`, and everything else is `internal`. Every public type and member has XML docs, and warnings are errors.
- The house style comes from phase 1.2:
  - members return `ValueTask<Result<T, MnemosyneError>>`;
  - `ct` comes last and has no default;
  - cancellation throws;
  - expected failures come back as results, and bugs throw.
- **Error mapping** (from the spec's Errors table):
  - `40001`, `40P01` and `23503` map to `Conflict`;
  - a connection failure (`08*`, `57P*`, or an `NpgsqlException` with no `SqlState`) maps to `Unavailable`;
  - anything else propagates.
- **Scope.** Every statement that reads or writes user data filters on `scope`. An id in another scope answers `NotFound`.
- **Options.**
  - `Dimensions` is in `[1, 2000]`. Outside that range the store throws `ArgumentOutOfRangeException` in its constructor, and the message names the HNSW limit of 2000.
  - `HnswM` defaults to 16 and must be in `[2, 100]`.
  - `HnswEfConstruction` defaults to 64 and must be in `[4, 1000]`.
- **Search.** `limit` is in `[1, 200]`. The embedding length must equal `Dimensions`. Only `status = 1` (Active) rows are returned. `Similarity = greatest(0, 1 - (embedding <=> @e::vector))`. Columns are named explicitly; never use `r.*`.
- **Versions.** A new Reasonlet is `1.0` with `root_id` null. A child gets `root_id = coalesce(parent.root_id, parent.id)` and version `1.<max minor in lineage + 1>`, with the root row locked `FOR UPDATE`.
- **Graph.** The `graph` column is `text`. It stores `ReasonletGraphJson.Serialize(graph)` exactly, and `content_hash` stores `graph.ComputeContentHash()` at insert. Neither is ever recomputed from stored text.
- **Erasure.**
  - By scope, delete the scope's Reasonlets; executions and feedback cascade.
  - By subject, delete the subject's Reasonlets in the scope. Their executions and feedback cascade, including other subjects' executions, and children's `parent_id` and `root_id` are set to NULL. Then delete the subject's executions on Reasonlets that are kept.
  - Both cases run in one transaction and count every Reasonlet and execution removed.
- **Feedback.** Recording feedback again on the same execution is an upsert.
- **Commits.** Use conventional commits: `feat:` for new store behaviour, `test:`, `build:`, `ci:` and `docs:` where they fit, and never `fix:` for unshipped code. End each commit with a blank line followed by `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Don't nest parentheses in a commit body.
- **Coverage.** Coverage stays at 100% line and branch, which the Codecov gate requires. Check it locally before reporting.

## Review Focus

1. **Concurrent children.** 20 parallel `RememberAsync` calls with the same parent and different graphs must produce 20 distinct versions with no gap in the minor sequence. Task 3 tests this.
2. **Stored graph round-trip.** A graph read back by `GetAsync`, then sent again with the same `ParentId`, must come back `ExecutionOnly`, not as a spurious version. Task 3 tests this.
3. **Lineage cut on erasure.** After subject A's root is erased, B's child must survive with a null parent, and B's next child of it must get a version that continues its own lineage without a crash. Task 6 tests this.
4. **Scope leaks.** Get, execution, feedback, search and remember-with-parent must each return `NotFound` or nothing for an id that exists only in another scope. Tasks 3 to 6 test this.
5. **Dimension mismatch.** Reopening a migrated database with different `Dimensions` must fail `MigrateAsync` with both numbers in the message, and must never alter the column. Task 2 tests this.
