# Phase 1.7 Docsite and First Sample Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A newcomer can reach a published Docusaurus site, learn what a Reasonlet is, and run a store-and-recall sample with only Docker and the .NET SDK.

**Architecture:**
- **Site:** Docusaurus at the repository root, copied from Rag.NET. Content lives in `docs/`, excluding `superpowers/` and `planning/`.
- **Publishing:** a `docs.yml` workflow builds the site on pull requests and deploys it to GitHub Pages from `main`.
- **Sample:** a console app with an offline hashing embedding generator. CI runs it and it asserts its own ranking.

**Tech Stack:**
- Docusaurus 3.10.2, with the classic preset and theme-mermaid.
- Node 24 and npm.
- .NET 10.
- `pgvector/pgvector:pg17` running in Docker Compose.

**Spec:** `docs/superpowers/specs/2026-10-23-phase-1.7-docsite-sample-design.md`

- **`docs.yml`:**
  - Mirror Rag.NET's `.github/workflows/docs.yml`: the triggers, the path filters adapted to this repo's files, concurrency, top-level `permissions: contents: read`, job-level `pages: write` and `id-token: write` on deploy, Node 24, and `npm ci`.
  - The upload and deploy steps run only on a push to `main`.
  - Keep its comments' reasoning, but rewrite any Rag.NET history that doesn't apply here.
- **Sample:**
  - The project is `samples/Mnemosyne.Samples.StoreAndRecall`, `IsPackable=false`, added to the slnx under a `/samples/` folder.
  - It is excluded from coverage by a `ModulePath` exclude for `.*Samples.*\.dll$`.
  - The connection comes from `MNEMOSYNE_SAMPLE_PG`, defaulting to `Host=localhost;Port=5432;Username=postgres;Password=postgres;Database=mnemosyne_sample`.
  - The embedding dimension is 256.
- **`HashingEmbeddingGenerator`:**
  - Lowercase the text.
  - Split on characters that are not letters or digits.
  - Hash each word with a stable FNV-1a 32-bit hash over its UTF-8 bytes, then take the result mod 256 as the bucket and add 1 to it.
  - L2-normalise the vector.
  - Empty input, or input with no words, gives a vector with a 1 in bucket 0, so the norm is never zero.
- **Exit codes:** the sample exits 0 on success, and non-zero with a message on stderr when its ranking or any step differs from what it expects.
- **Commits:**
  - Use conventional commits: `docs:`, `ci:`, `feat:` for the sample, and `test:`. Never use `fix:`.
  - End each commit with a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
  - No nested parentheses in a commit body.
- **Coverage:** `src` stays at 100% line and branch, merged across both test projects.

### Task 2: Store-and-recall sample

**Files:**
- **Create:**
  - `samples/Directory.Build.props`, which sets `IsPackable=false` and imports the root props.
  - `samples/Mnemosyne.Samples.StoreAndRecall/Mnemosyne.Samples.StoreAndRecall.csproj`
  - `Program.cs`, `HashingEmbeddingGenerator.cs`, `compose.yaml` and `README.md`
  - `tests/Mnemosyne.NET.Tests/Samples/HashingEmbeddingGeneratorTests.cs`
- **Modify:**
  - `Mnemosyne.NET.slnx`
  - `coverage.config.xml`
  - `tests/Mnemosyne.NET.Tests/Mnemosyne.NET.Tests.csproj`: add a project reference to the sample.
  - `.github/workflows/ci.yml`: add the run step in the `aot-publish` job.
  - `RepoConventionsTests`, if it pins the project list or the packable set.

**Interfaces:**
- **Consumes:** `AddMnemosynePostgreSql`, `AddMnemosyne` and the `IReasonletMemory` members.
- **Produces:**
  - `public sealed class HashingEmbeddingGenerator : IEmbeddingGenerator<string, Embedding<float>>`, with `public const int Dimensions = 256`.
  - The sample flow, which Task 3's getting-started page and samples page describe.

- [ ] **Step 1: Write the failing generator tests.**
  - The same text gives an identical vector.
  - Every output has a norm of 1 within 1e-6.
  - "How do I refund an order" against "refund an order quickly" scores a higher cosine than against "plan a team offsite".
  - Empty input and "!!!" each return bucket 0 equal to 1.
  - The output length is 256.
- [ ] **Step 2:** Run `dotnet test tests/Mnemosyne.NET.Tests -c Release`. Expected: the new tests fail.
- [ ] **Step 3: Implement the generator and the sample.** `Program.cs`:
  1. Build the host with the store options, `Dimensions` 256, the generator and `AddMnemosyne()`. Migrate, in a scope named `sample-<guid>`.
  2. Remember these procedures, each with a small graph:
     - "refund an order", which becomes proven: it gets 20 successful executions recorded;
     - "refund a partial order", a close match, with a 50% record;
     - a new version of "refund an order", with a different graph, `ParentId` set, and one successful run.
  3. Recall "How do I refund an order?", with `Top` 3, and print a table of version, similarity, success rate, freshness and total.
  4. Assert that the new version ranks first and the proven original second. On a mismatch, print what differed and exit 1.
  5. Erase the scope and print the counts.

  Each step prints one line saying what it did, so the console output reads as a walkthrough.
- [ ] **Step 4: Add the CI step.** After the native-binary step in `aot-publish`, add:
  1. `psql` or `docker exec` to run `CREATE DATABASE mnemosyne_sample`. The service has the `postgres` user, so you can use the runner's `psql` with `PGPASSWORD`.
  2. `dotnet run --project samples/Mnemosyne.Samples.StoreAndRecall -c Release`, with `MNEMOSYNE_SAMPLE_PG` pointing at that database.
- [ ] **Step 5: Verify.**
  - Run `docker compose -f samples/Mnemosyne.Samples.StoreAndRecall/compose.yaml up -d`, then `dotnet run`. Expected: exit 0 and the table, with the new version first.
  - Temporarily swap the expected order in the assertion and run again. Expected: exit 1. Then revert.
  - Run `docker compose down`.
- [ ] **Step 6:** Run both test projects and check coverage. Expected: everything passes, `src` stays at 100%, and the sample is excluded.
- [ ] **Step 7:** Commit with `feat: add the store-and-recall sample` and `ci: run the sample against pgvector`.
