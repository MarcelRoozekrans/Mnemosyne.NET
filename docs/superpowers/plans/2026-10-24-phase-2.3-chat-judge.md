# Phase 2.3 Chat-Model Evaluator Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `ChatReasonletEvaluator`, in the core `Mnemosyne.NET` package, judges a run through an `IChatClient` and replies with a strict JSON verdict.

**Architecture:**
- **The request.** The evaluator sends two messages: a system message with fixed instructions and optional host criteria, and a user message holding the run as source-generated JSON. It asks for a JSON-schema response format.
- **The reply.** It parses the reply strictly into `{worked, confidence}` and maps it to a `ReasonletEvaluation` whose score is the probability that the run worked.
- **Registration.** `AddMnemosyneChatEvaluator` registers it against the host's `IChatClient`, keyed or not.

**Tech Stack:**
- .NET 10.
- Microsoft.Extensions.AI.Abstractions 10.10.1, already referenced by the core package.
- ZeroAlloc.Results.
- xunit v3.

**Spec:** `docs/superpowers/specs/2026-10-24-phase-2.3-chat-judge-design.md`

## Global Constraints

- **The question:** "Does the answer resolve the question by following the procedure?"
- **The reply:** exactly one JSON object with `worked` (a bool) and `confidence` (a number in [0, 1]). Unknown extra fields are ignored.
- **The verdict:**
  - `Success = worked`.
  - `Score = worked ? confidence : 1 - confidence`.
  - `Evaluator = EvaluatorName`.
- **`ChatEvaluatorOptions`:**
  - `EvaluatorName`: non-blank, valid UTF-16, at most `EvaluationLimits.MaxEvaluatorLength` code points, default `llm-judge`.
  - `Criteria`: `string?`, default null. When set, it is non-blank, valid UTF-16 and at most 4,000 code points.
  - `ChatClientKey`: `object?`, default null.
  - `Validate()` uses the public `Check`.
- **The state:**
  - JSON properties in this order: `question`, `intent`, `procedure`, `answer`.
  - `procedure` is a nested `JsonElement` parsed from `ReasonletGraphJson.Serialize(graph)`.
  - A source-generated `JsonSerializerContext` produces it.
  - It never includes the agent's outcome or the Reasonlet's name.
- **Chat options:** set only `ResponseFormat = ChatResponseFormat.ForJsonSchema(...)`, using a hand-written schema constant that requires both fields and sets `additionalProperties: false`.
- **Errors:**
  - Every reply failure is `MnemosyneErrorCode.Unavailable`.
  - The message is fixed: "The chat judge could not judge the run."
  - The detail is `chat: EmptyReply` when the reply has no text, and `chat: InvalidReply` for everything else.
  - The detail never contains reply text.
- **Exceptions and cancellation:** propagate both. The facade handles them.
- **Public API,** in namespace `Mnemosyne.NET`:
  - `ChatReasonletEvaluator(IChatClient client, ChatEvaluatorOptions options)`
  - `ChatEvaluatorOptions`
  - `AddMnemosyneChatEvaluator(this IServiceCollection, ChatEvaluatorOptions? options = null)` in the existing `ServiceCollectionExtensions`

  The state, reply and JSON context types are internal.
- **Commits:**
  - conventional, never `fix:`;
  - end with a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`;
  - no nested parentheses in a commit body.
- **Coverage:** 100% line and branch, merged across both test projects.

## Review Focus

1. **Strict parsing.** Leading or trailing prose, a code fence, an array, two concatenated objects or trailing commas all fail, and a lone object surrounded by whitespace passes. Task 1.
2. **Duplicate and null keys.** A duplicate `worked` key, or `"worked": null`, fails as `InvalidReply` rather than throwing or taking either value. Task 1.
3. **No reply text escapes.** A sentinel in an invalid reply reaches neither the `MnemosyneError` nor the facade's telemetry. Tasks 1 and 2.
4. **The run stays data.** The user message is the JSON state and nothing else. The criteria only ever appear in the system message. Task 1.
5. **Keyed resolution.** Registration picks the keyed client and never the default one. Task 2.

- [ ] **Step 1: Write the failing tests.**
  - **Verdict:**
    - `{"worked":true,"confidence":0.8}` gives (true, 0.8, "llm-judge").
    - `{"worked":false,"confidence":0.8}` gives (false, 1 - 0.8).
    - confidence 0 and 1 are accepted with both verdicts;
    - a custom name is passed through;
    - an extra unknown field is ignored;
    - surrounding whitespace is accepted.
  - **Request:**
    - exactly two messages, `ChatRole.System` then `ChatRole.User`;
    - the user text parses to exactly the four fields, in order, with `procedure` an object deep-equal to the parsed canonical JSON;
    - sentinels in the outcome and the name appear in neither message;
    - a criteria sentinel is in the system text when set, and in neither message when not;
    - the system text contains the question;
    - `options.ResponseFormat` is a `ChatResponseFormatJson` with a non-null schema.
  - **Failures:** a theory over replies, each giving `Unavailable`, the fixed message and the expected detail, with a sentinel absent from the detail and the message:
    - **`EmptyReply`:** no messages; an empty string; whitespace only.
    - **`InvalidReply`:**
      - prose before the JSON, prose after it, and a ```` ```json ```` fence;
      - `[]`, `[{...}]`, two concatenated objects, a trailing comma;
      - a missing `worked`, a missing `confidence`;
      - `"worked":"true"`, `"confidence":"0.8"`;
      - `"worked":null`, `"confidence":null`;
      - a duplicate `worked` key;
      - confidence -0.01 and 1.01;
      - invalid JSON.
  - **Propagation:** a thrown exception propagates, and cancellation propagates.
  - **Options:** each of these fails validation with its property as the path:
    - a blank name, a name over the limit, a name with a lone surrogate;
    - blank criteria, criteria over 4,000 code points, criteria with a lone surrogate.

    A surrogate pair counts as one code point at the limit.
- [ ] **Step 2:** Run the tests. Expect them to fail.
- [ ] **Step 3: Implement.**
  - **Parsing.** Use `Utf8JsonReader` or `JsonDocument` with the default options, which reject trailing commas and comments, and require that the whole text is consumed. Detect duplicate keys yourself: System.Text.Json's source-generated deserializer takes the last duplicate silently. One way that passes Review Focus 1 and 2 is to read the object with `JsonDocument.Parse`, check that the root is an object, enumerate its properties once while recording `worked` and `confidence`, and fail on a second occurrence or a wrong `ValueKind`.
  - **Shared code.** Share code-point counting with `MinosEvaluatorOptions` only if it already lives somewhere both packages reference. Otherwise use `Check.MaxLength` and `Check.ValidUtf16` as `ReasonletEvaluation.Validate` does.
