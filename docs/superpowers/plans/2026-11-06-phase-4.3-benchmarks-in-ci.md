# Benchmarks in CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A BenchmarkDotNet suite for ranking, middleware overhead and PostgreSQL search runs in CI on code changes and publishes its table, with no pass or fail threshold on numbers.

**Architecture:** A non-packable executable project under `benchmarks/` with three benchmark classes and a `Program` that leaves the database class out when no connection string is set. A workflow runs it with a pgvector service container and writes the markdown reports to the job summary.

**Tech Stack:** .NET 10, BenchmarkDotNet, PostgreSQL with pgvector, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-06-phase-4.3-benchmarks-in-ci-design.md`

## Global Constraints

- The repo refuses `dotnet test --filter`; this phase adds no test project, so it does not matter here, but do not add one.
- No Claude signature or session link in commits. No nested parentheses in commit bodies.
- The benchmark project is `IsPackable` false and is never added to `TrimmerRootAssembly` or the AOT smoke.
- The workflow has `permissions: contents: read` only and no threshold on any number.
- Candidate and match construction uses object initialisers with `LineageId` set, as phase 4.2 fixes.
- Package versions live in `Directory.Packages.props`.

## Review Focus

- `MNEMOSYNE_BENCH_PG` unset: the program runs the other two classes and prints a note, and exits 0.
- A benchmark class that throws in setup: the workflow job fails, and the summary step still runs.
- The pull request touches only docs: the workflow does not start.
- `dotnet pack Mnemosyne.NET.slnx` still yields one package per source project.

### Task 1: The project, the data helpers and the ranking benchmark

- Produces: `internal static class BenchmarkData` with `ReasonletDefinition Reasonlet(int index)`, `IReadOnlyList<ReasonletCandidate> Candidates(int count)`, `float[] Embedding(int seed, int dimensions)`; used by Tasks 2 and 3.

- [ ] **Step 1: Add `BenchmarkDotNet`** to `Directory.Packages.props` at the latest stable version, and the project to `Mnemosyne.NET.slnx` under a new `<Folder Name="/benchmarks/">`.
- [ ] **Step 2: Create the csproj** as an `Exe`, `IsPackable` false, with `BenchmarkDotNet` and project references to Abstractions, `Mnemosyne.NET` and `Mnemosyne.NET.PostgreSql`.
- [ ] **Step 3: Write `BenchmarkData`.** `Embedding` uses `new Random(seed)` and normalises. `Reasonlet(index)` and `Candidates(count)` build valid definitions and candidates from the shapes in `tests/Mnemosyne.NET.Tests/Core/ReasonletSelectorTests.cs`, with a fixed spread of similarity, runs and last-executed times and a distinct `LineageId` per candidate. - [ ] **Step 4: Write `RankingBenchmarks`** with `[MemoryDiagnoser]`, `[Params(10, 100, 1000)] public int Candidates`, `GlobalSetup` building the selector (default `ReasonletRankingOptions`, a fixed `FakeTimeProvider`-style `TimeProvider` subclass) and the candidates, and `[Benchmark] public ValueTask<...> Rank()` calling `RankAsync` with a query whose `Top` is 5.
- [ ] **Step 5: Write `Program.Main`** using `BenchmarkSwitcher.FromTypes([...]).Run(args)`. The type list holds the ranking class now; Tasks 2 and 3 add theirs.
- [ ] **Step 6: Verify.** `dotnet build Mnemosyne.NET.slnx -c Release` succeeds, then `dotnet run -c Release --project benchmarks/Mnemosyne.NET.Benchmarks -- --job dry --filter '*Ranking*'` prints a table with three rows.

### Task 2: The middleware benchmark

**Files:**
- Create: `benchmarks/Mnemosyne.NET.Benchmarks/MiddlewareBenchmarks.cs`
- Modify: `benchmarks/Mnemosyne.NET.Benchmarks/Program.cs`

**Interfaces:**
- Consumes: `ReasonletChatClient(IChatClient inner, IReasonletMemory memory, IReasonletCaptureSink? queue, ReasonletChatOptions options, TimeProvider time)`, `IReasonletMemory.RecallAsync`, `ReasonletMatch` with `LineageId`, `BenchmarkData` from Task 1.
- Produces: `MiddlewareBenchmarks` with `Direct` as the baseline and `Wrapped` and `WrappedWithRecall` as the measured cases.

- [ ] **Step 1: Write the file.** A private `NoOpChatClient : IChatClient` that returns one fixed `ChatResponse`; a private `StubMemory : IReasonletMemory` whose `RecallAsync` returns an empty list or a fixed two-match list by a flag and whose other members throw `NotSupportedException`. `GlobalSetup` builds two `ReasonletChatClient` instances over the no-op client, one per stub, with `ReasonletChatOptions` defaults, no queue, and `TimeProvider.System`.
- [ ] **Step 2: Benchmarks.** `[Benchmark(Baseline = true)] Direct` calls the no-op client; `Wrapped` calls the client with the empty-recall stub; `WrappedWithRecall` calls the one with matches. Each uses one user message and awaits `GetResponseAsync`.
- [ ] **Step 3: Register the class in `Program`.**
- [ ] **Step 4: Verify.** `dotnet run -c Release --project benchmarks/Mnemosyne.NET.Benchmarks -- --job dry --filter '*Middleware*'` prints three rows with a ratio column.
- [ ] **Step 5: Commit** `feat: benchmark the chat middleware overhead`.

### Task 3: The PostgreSQL search benchmark

**Files:**
- Create: `benchmarks/Mnemosyne.NET.Benchmarks/SearchBenchmarks.cs`
- Modify: `benchmarks/Mnemosyne.NET.Benchmarks/Program.cs`

**Interfaces:**
- Consumes: `ReasonletPostgreSqlStore(NpgsqlDataSource, MnemosynePostgreSqlOptions)`, `MigrateAsync`, `RememberAsync(ReasonletStoreEntry, CancellationToken)`, `SearchAsync(ReasonletScope, ReadOnlyMemory<float>, string?, int, CancellationToken)` returning candidates with `LineageId`, `BenchmarkData.Embedding`.
- Produces: `SearchBenchmarks` and `internal const string ConnectionVariable = "MNEMOSYNE_BENCH_PG"`.

- [ ] **Step 1: Seed in `GlobalSetup`.** Build a data source from `MNEMOSYNE_BENCH_PG`, a store with `Dimensions = 256`, run `MigrateAsync`, and `RememberAsync` 1000 entries in one scope. `[Params(1, 20)] public int LineageDepth`: when 20, the entries form chains of 20 by passing the previous receipt's id as the parent, the way `ReasonletStoreEntry` carries a parent; read the entry shape from `tests/Mnemosyne.NET.PostgreSql.Tests/Entries.cs` and reuse it.
- [ ] **Step 2: Benchmark.** `[Benchmark] SearchAsync` runs `store.SearchAsync(scope, queryEmbedding, null, 10, ct)`.
- [ ] **Step 3: Gate the class in `Program`.** Add it to the switcher list only when `Environment.GetEnvironmentVariable(SearchBenchmarks.ConnectionVariable)` is not empty; otherwise print `Skipping SearchBenchmarks: MNEMOSYNE_BENCH_PG is not set.`.
- [ ] **Step 4: Verify without a database.** `dotnet run -c Release --project benchmarks/Mnemosyne.NET.Benchmarks -- --job dry --filter '*Ranking*'` prints the skip note and exits 0. With Docker, start pgvector, set the variable and run `--filter '*Search*'`; without Docker say so, CI runs it.
- [ ] **Step 5: Commit** `feat: benchmark the PostgreSQL search with lineage resolution`.

### Task 4: The workflow and the readme

**Files:**
- Create: `.github/workflows/benchmarks.yml`, `benchmarks/README.md`
- Modify: `tests/Mnemosyne.NET.Tests/RepoConventionsTests.cs` only if it asserts the workflow set

**Interfaces:**
- Consumes: the project path and `MNEMOSYNE_BENCH_PG`.

- [ ] **Step 1: Write the workflow.** Triggers: `pull_request` on `src/**`, `benchmarks/**`, `Directory.Packages.props`, `.github/workflows/benchmarks.yml`; `workflow_dispatch`. A `concurrency` group that cancels in progress. One job on `ubuntu-latest`, `timeout-minutes: 45`, `permissions: contents: read`, with the `pgvector/pgvector:pg17` service and health check copied from `aot-publish`. Steps: checkout with the repo's pinned action versions, setup .NET 10.0.x, create the benchmark database with `psql`, run `dotnet run -c Release --project benchmarks/Mnemosyne.NET.Benchmarks -- --job short --exporters github json --artifacts benchmarks/results` with `MNEMOSYNE_BENCH_PG` set, then an `if: always()` step that appends every `*-report-github.md` to `$GITHUB_STEP_SUMMARY` after a line saying the runner is shared and numbers compare within one run, then an `if: always()` `actions/upload-artifact` of `benchmarks/results`.
- [ ] **Step 2: Write `benchmarks/README.md`:** how to run each class locally, what each measures, the environment variable, why CI reports and does not gate, and that comparing two runs means running both on the same machine.
- [ ] **Step 3: Verify.** `grep -c "permissions" .github/workflows/benchmarks.yml` shows it is declared; run `dotnet test tests/Mnemosyne.NET.Tests -c Release` and expect all pass; run `dotnet pack Mnemosyne.NET.slnx -c Release -o /tmp/mnemo-pack` and expect one package per source project.
- [ ] **Step 4: Commit** `ci: run the benchmarks and publish their report`.
