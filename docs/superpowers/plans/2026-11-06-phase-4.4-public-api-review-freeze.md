# Public API review and freeze Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close #58, make the growing result and entry records init-only, lock the reviewed public surface with PublicApiAnalyzers baselines, and publish the graph schema compatibility policy.

**Architecture:** The AI.Sentinel fix lands first, in two commits, because it changes shipped behaviour. The four records then convert in one atomic change. The analyzers come last, so the baselines record the final surface. The schema policy is documentation plus a golden-document test.

**Tech Stack:** .NET 10, xunit v3 on Microsoft.Testing.Platform, Microsoft.CodeAnalysis.PublicApiAnalyzers, AI.Sentinel 5.x, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-06-phase-4.4-public-api-review-freeze-design.md`, with the impact analysis `docs/superpowers/specs/2026-11-06-phase-4.4-public-api-review-freeze-impact-analysis.md`

## Global Constraints

- The repo refuses `dotnet test --filter`. Build first, then run a test exe with `-class <FQN>`; the exe sits under `<project>/bin/Release/net10.0/`.
- No Claude signature or session link in commits. No nested parentheses in commit bodies.
- The record conversion is a breaking change: its commit uses `refactor!:` and a `BREAKING CHANGE:` footer in plain words. The operator approved this change and the API gate in the design on 2026-11-06, so an unattended run builds them. The PR is merged only by the operator.
- `ReasonletSuggestion`, `ReasonletAgentScope`, `ReasonletCallScope` and `ReasonletErasure` stay positional.
- Native AOT stays a CI gate; `ReasonletReceipt` and `ReasonletStoreEntry` are built by the AOT smoke app.
- `benchmarks/Mnemosyne.NET.Benchmarks` (phase 4.3) is in the solution and must keep compiling. Every task ends with `dotnet build Mnemosyne.NET.slnx -c Release`, which covers it.
- Phase 4.2 has to be built first: this plan uses `LineageId` and the init-only candidate, match and evidence.

## Review Focus

- A detector throws and another detects at block severity: the capture is blocked, not `Unavailable`.
- A detector throws and none detects: `Unavailable`, with a detail that holds the failure count and no detector message.
- A scan that is complete and clean: unchanged, allowed.
- A public member added without a baseline line: the build fails with an RS error, not a warning.
- A graph document valid under v1 today: still deserializes and round-trips after any later change.
