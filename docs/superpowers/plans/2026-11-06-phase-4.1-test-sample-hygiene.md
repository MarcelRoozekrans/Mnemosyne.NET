# Test and sample hygiene Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One shared copy of the PostgreSQL test stubs (#55) and one shared copy of the sample self-check runner (#57).

**Architecture:** A `Stubs.cs` in the PostgreSQL test project replaces five private copies. A `samples/Shared/SampleRunner.cs`, linked into each sample like `ScriptedChatClient`, replaces four copies of the runner block and is unit-tested from `tests/Mnemosyne.NET.Tests`, which already compiles the other shared sample files in.

**Tech Stack:** .NET 10, xunit v3 on Microsoft.Testing.Platform, Microsoft.Extensions.AI, PostgreSQL with pgvector (Docker).

**Spec:** `docs/superpowers/specs/2026-11-06-phase-4.1-test-sample-hygiene-design.md`
**Impact analysis:** `docs/superpowers/specs/2026-11-06-phase-4.1-test-sample-hygiene-impact-analysis.md`

## Global Constraints

- The repo refuses `dotnet test --filter`. Build first, then run a test exe with `-class <FQN>`; the exe sits under `<project>/bin/Release/net10.0/`.
- No Claude signature or session link in commits. No nested parentheses in commit bodies.
- Commit type `refactor` or `test`, scope free; the PR needs no release note, so use `refactor`.
- Test behaviour does not change in Task 1. Sample behaviour changes only where the spec says: a database or other unexpected exception ends as `FAILED:` with exit 1, and a capture timeout names the run or act in all four samples.
- Each sample keeps its own exit-code logic and checks; only the runner block moves.

## Review Focus

- A sample body that throws an exception other than `SampleFailure`, `TimeoutException` or cancellation: expect `FAILED: <type>: <message>` and exit 1, not a crash.
- An erase that throws or returns a failure after a body failure: the body's failure is still the one reported, and the exit code stays 1.
- A cancelled run still erases, because the erase does not take the run's token.
- A body that returns 0 while the erase fails: exit code 1.
- A body that returns 0 with a clean erase: exit code 0 and no `FAILED:` output.

- Produces, namespace `Mnemosyne.Samples`, all `public` like the other shared sample types, so each sample adds `using Mnemosyne.Samples;` and deletes its own `SampleFailure`:

  - `static class SampleRunner` with

    - `Task<bool> TryEraseAsync(IReasonletMemory memory, ReasonletScope scope)`: the existing `TryErase`, using `CancellationToken.None`, never throwing.
    - `T Require<T>(Result<T, MnemosyneError> result, string what)`, `void RequireSuccess(UnitResult<MnemosyneError> result, string what)`, `void RequireEqual<T>(T actual, T expected, string what)`, with the messages the samples use now.
