# Phase 1.3 Graph JSON Schema v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the minimal graph types into Mnemosyne's v1 procedure format. That means init-only extended records, strict validation, an AOT-safe JSON serializer that rejects unknown or duplicate members, a canonical SHA-256 content hash, and a published JSON Schema.

**Architecture:**
- **Records:** all graph types live in `Mnemosyne.NET.Abstractions/Graph/`.
- **Validation:** extends the existing `Check`-based `Validate()`.
- **Serialization:** uses an internal source-generated `System.Text.Json` context behind a public static `ReasonletGraphJson`.
- **Hashing:** `ComputeContentHash()` writes a canonical form with a `Utf8JsonWriter` (amended: by hand, with the fixed RFC 8785 escape set), sorting nodes, edges and every property key ordinally and writing numbers from their raw text, then hashes it with `SHA256`.

**Tech Stack:** .NET 10, `System.Text.Json` (in-box), `System.Security.Cryptography.SHA256`, xunit v3. The test project only uses `JsonSchema.Net` for schema conformance.

**Spec:** `docs/superpowers/specs/2026-10-22-phase-1.3-graph-schema-design.md`

> **Amended during execution, 2026-10-22.** The tasks below are kept as
> planned, with corrections marked inline. Execution and the whole-branch
> review changed these points; the spec is the current reference:
> - The serializer's `MaxDepth` is 36, not 32: `MaxPropertyDepth` (32) plus
>   the 4 structural levels a property value sits under.
> - The canonical writer does not use `Utf8JsonWriter` or a
>   `JavaScriptEncoder`. It emits JSON by hand with the fixed RFC 8785 escape
>   set, so a runtime upgrade cannot change a hash. Numbers are written from
>   their raw UTF-8 text. Only the serializer uses the relaxed encoder.
> - The property size limit is measured with the canonical writer, not as a
>   compact relaxed-encoder serialization. `PropertyChecks.SerializedSize`
>   was replaced by `CanonicalGraphWriter.PropertiesSize`.
> - New limits `MaxIdentifierLength = 256` and `MaxTextLength = 1024`, in
>   code points, mirrored as `maxLength` in the schema.
> - The validation order became: nulls, version, at least one node, counts,
>   per-element checks (including the `Condition` non-blank check, moved
>   into `ReasonletEdge.Validate`, and the lengths), unique ids, endpoints,
>   duplicate edges, properties, property size.
> - Property values must also be valid UTF-8 and UTF-16, have no duplicate
>   member names, and not repeat a dictionary key.

## Global Constraints

- Keep the member names `Nodes`, `Edges` and `SchemaVersion`. `ReasonletNode`, `ReasonletEdge` and `ReasonletGraph` become `sealed record`s with `required` init members, the same as the phase 1.2 init-only records.
- Supported schema versions: exactly `{ 1 }`. Expose this as `ReasonletGraph.CurrentSchemaVersion = 1`.
- Limits, defined as `public const int` on `public static class ReasonletGraphLimits`:
  - `MaxNodes = 500`
  - `MaxEdges = 2000`
  - `MaxPropertiesBytes = 65536`, the sum over every `Properties` dictionary of its compact UTF-8 JSON byte length (amended: measured as the canonical JSON object, with the RFC 8785 escape set)
  - `MaxPropertyDepth = 32`
- Property key grammar: two or more non-empty segments separated by dots, matched ordinally. `"."`, `"a."`, `".a"` and `"a"` are all invalid.
- Validation order (the first failure wins; amended, see the note at the top for the order as built):
  1. the phase 1.2 checks;
  2. supported version;
  3. at least one node;
  4. unique node IDs;
  5. edge endpoints exist;
  6. a non-blank condition when present;
  7. no duplicate edges with the same From, To and Condition;
  8. property keys and values;
  9. the limits.
- Paths use the established format: `Nodes[i].Id`, `Edges[i].From`, `Properties["k"]`, `Nodes[i].Properties["k"]`, with the phase 1.2 key escaping.
- JSON uses camelCase names and omits null optional members. `Properties` that are null or empty are omitted. Unknown members are rejected. A duplicate member name in any object is rejected. `MaxDepth = 32` (amended: `MaxDepth = 36`, which is `MaxPropertyDepth` 32 plus 4 structural levels).
- `Deserialize` and `ComputeContentHash` never throw on bad input. They return `Validation` errors.
- The hash covers `schemaVersion`. Numbers are written from their raw text. Strings are re-encoded through one writer (amended: with the fixed RFC 8785 escape set). The output is lowercase hex.
- No reflection-based serialization and no `Equals` override. The AOT gate stays green. Abstractions still references only `ZeroAlloc.Results`; System.Text.Json is in-box.
- Commit types: this changes unreleased public API, so use `feat:` for the new capabilities (serializer, hash, schema) and `refactor:` for reshaping existing types. Never use `fix:`.

## Review Focus

1. **Escape-equivalent strings hash the same.** A property value `"A"` and `"A"` must hash the same. Task 4 tests this.
2. **Deep or huge input does not crash.** JSON nested 1,000 levels deep, or a 10 MB string, must come back from `Deserialize` as a `Validation` error and never as a `StackOverflow` or an unhandled `JsonException`. Task 3 tests this.
3. **Duplicate keys inside nested property values** (`{"a.b": {"x":1,"x":2}}`) must be rejected, not reduced to their last value. Task 3 tests this.
4. **A `default(JsonElement)` value built in code** must give `Validation` from both `Validate()` and `ComputeContentHash()`, and must not throw `InvalidOperationException`. Task 2 tests the first, Task 4 the second.
5. **Hash stability across runtimes.** The golden hash must not depend on culture or on the platform's line endings. Task 4 runs the golden test under a non-invariant culture, such as `tr-TR`.

### Task 4: Canonical content hash

**Files:**
- Modify: `src/Mnemosyne.NET.Abstractions/Graph/ReasonletGraph.cs` (add `ComputeContentHash`)
- Create: `src/Mnemosyne.NET.Abstractions/Graph/CanonicalGraphWriter.cs` (internal)
- Test: `tests/Mnemosyne.NET.Tests/Abstractions/GraphHashTests.cs`

**Interfaces:**
- Consumes: Tasks 1-3.
- Produces: `Result<string, MnemosyneError> ReasonletGraph.ComputeContentHash()`. It calls `Validate()` first. On success it returns 64 lowercase hex characters.
- The canonical form:
  - an object with members in ordinal order: `edges`, `nodes`, `properties` (if non-empty), `schemaVersion`;
  - nodes sorted by `Id`;
  - edges sorted by `From`, then `To`, then `Condition` (null first);
  - every object's members, including nested `JsonElement` objects, sorted ordinally;
  - arrays inside property values kept in order;
  - numbers written raw via `WriteRawValue(element.GetRawText())` (amended: written from `JsonMarshal.GetRawUtf8Value`, since there is no `Utf8JsonWriter`);
  - strings written through `Utf8JsonWriter` with one fixed `JavaScriptEncoder` (amended: strings are unescaped and written by hand with the fixed RFC 8785 escape set, because every `JavaScriptEncoder` follows the runtime's Unicode tables);
  - no indentation.

- [ ] **Step 1: Write the failing tests.**
  - Reordering nodes, edges or property keys (at the top level and nested) gives the same hash.
  - Changing a node's id, name, tool or type, an edge's condition, a property value, or `schemaVersion` each gives a different hash. For `schemaVersion`, construct a version-2 graph directly in the test's canonical writer helper, or skip this case if validation forbids it, and document why in a comment.
  - `"A"` and `"A"` property values hash the same.
  - `1` and `1.0` hash differently.
  - Null `Properties` and empty `Properties` hash the same.
  - An invalid graph returns `Validation`, not a hash.
  - A `default(JsonElement)` value returns `Validation`.
  - Golden test: one fixed graph hashes to a pinned literal. Compute it once from the implementation and paste it in. Then run the test again under `CultureInfo.CurrentCulture = new("tr-TR")` and expect the same value.
