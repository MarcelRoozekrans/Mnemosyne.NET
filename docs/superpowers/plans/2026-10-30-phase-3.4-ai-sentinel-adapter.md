# Phase 3.4 AI.Sentinel Adapter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new package, `Mnemosyne.NET.Sentinel`, whose `SentinelCaptureGuard` runs AI.Sentinel's detection pipeline over a capture's question, intent and name, and blocks the capture when a detection reaches `BlockAtSeverity`. `AddMnemosyneSentinel()` registers it as the host's `ICaptureGuard`.

**Architecture:** The guard implements phase 3.2's `ICaptureGuard`. It builds one `SentinelContext` with one user message per non-blank stored text field and calls `IDetectionPipeline.RunAsync` once. Then it maps the highest detection at or above the threshold to `CaptureVerdict.Block`, and anything else to `Allow`. The host registers AI.Sentinel itself. The guard resolves the unkeyed pipeline and `SentinelOptions`, or the keyed pair for `PipelineName`. Core packages are untouched.

**Tech Stack:**
- .NET 10
- AI.Sentinel 4.1.1
- Microsoft.Extensions.AI.Abstractions 10.11.0

**Names, all in namespace `Mnemosyne.NET.Sentinel`:**
- `public sealed class SentinelCaptureGuardOptions`:
  - `Severity BlockAtSeverity { get; init; } = Severity.High`;
  - `string? PipelineName { get; init; }`;
  - `string GuardName { get; init; } = "ai-sentinel"`;

- `public sealed class SentinelCaptureGuard : ICaptureGuard`, with constructor `(IDetectionPipeline pipeline, SentinelOptions sentinelOptions, SentinelCaptureGuardOptions? options = null)`.
- `public static class ServiceCollectionExtensions`, with `AddMnemosyneSentinel(this IServiceCollection services, SentinelCaptureGuardOptions? options = null)`.
- AI.Sentinel types:
  - `AI.Sentinel.Detection.Severity`, `IDetectionPipeline`, `SentinelContext`, `PipelineResult` and `DetectionResult`;
  - `AI.Sentinel.Domain.DetectorId`, `SessionId` and `AgentId`;
  - `AI.Sentinel.SentinelOptions`.

**Behaviour:**
- **Messages:** `ChatRole.User`, one each for `Question`, `Intent` and `Name`, in that order, skipping null or blank values. The guard never sends `Answer`, the graph or `Provenance.Tags`.
- **`SessionId`:** `Provenance.RunId` when it is not null or blank, else `mnemosyne-capture`.
- **Sender and receiver:** `sentinelOptions.DefaultSenderId` and `DefaultReceiverId`. `History` is empty, and `LlmId` and `systemPrompt` are null.
- **Blocking:** a detection blocks when `Severity >= BlockAtSeverity`. The verdict names the blocking detection with the highest severity. On a tie, the first in `Detections` order wins.
- **Detector id:**
  - It is truncated to `EvaluationLimits.MaxEvaluatorLength` code points without splitting a surrogate pair.
  - A blank id, or one that fails `Check.ValidUtf16`, becomes `invalid-detector-id`.
- **`DetectionResult.Reason`:** never read.
- **Pipeline exceptions:** they propagate. The guard never returns an error result.
- **Options validation:** `Check.All` with property-name paths.
  - `BlockAtSeverity` must be `Enum.IsDefined` and not `Severity.None`, with path `BlockAtSeverity` and reason `"must be Low, Medium, High or Critical"`.
  - A non-null `PipelineName` must pass `Check.NotBlank`.
  - `GuardName` gets the three checks `MinosEvaluatorOptions.EvaluatorName` gets.
- **Invalid options:** `AddMnemosyneSentinel` and the guard's constructor throw `ArgumentException` with the validation message, as `AddMnemosyneMinosEvaluator` does.

**Repo rules:**
- **Tests:** the repo refuses `dotnet test --filter`. Build first, then run `tests/Mnemosyne.NET.Tests/bin/Debug/net10.0/Mnemosyne.NET.Tests -class <FQN>`. Run the full suite as the exe with no arguments.
- **Commits:** conventional commits, no nested parentheses in bodies, footer lines of 100 characters or fewer, no Claude trailers or session links.
- **Warnings:** `TreatWarningsAsErrors` is on. Never suppress a warning to go green.

## Review Focus

1. **A capture with a real email or IBAN in its question, under the default pipeline.** Expect `Blocked`, naming the PII detector. The end-to-end test in Task 4 uses SEC-02. Task 4 also adds an IBAN case, since PII is the likeliest real hit.
2. **A host that registers only a named pipeline and no unnamed one, and sets `PipelineName`.** Expect it to work, because the keyed `SentinelOptions` and `IDetectionPipeline` exist. Task 4 tests this with a host that calls only `AddAISentinel("capture", …)`.
3. **A detection with severity `None` in `Detections` while the threshold is `Low`.** Expect an allow, because `None` never blocks. This is tested in Task 3.
4. **A `RunId` that is whitespace.** Expect the fallback session id, not an `ArgumentException` from `SessionId`. This is tested in Task 3.
5. **A detector id of 101 emoji.** Expect a truncation that validates, with no split surrogate. This is tested in Task 3.
