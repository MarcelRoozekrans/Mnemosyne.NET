# Phase 5.3 Docs and Sample Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A reader learns what variant selection does and how to switch it on, and a self-checking sample proves a new version gets tried and overtakes the incumbent.

**Architecture:** A console sample without Docker drives `VariantSelector` over hand-built candidates and checks its own receipts; the docs are rewritten around what 5.1 and 5.2 shipped.

**Tech Stack:** .NET 10, Docusaurus docs, `SampleRunner` from `samples/Shared`.

**Spec:** `docs/superpowers/specs/2026-11-07-phase-5.3-variant-docs-sample-design.md`

## Global Constraints

- Branch from the latest `main` after 5.2 is merged; explicit refspec; conventional commits without signature, session link or nested parentheses; lines of at most 100 characters in bodies.
- Read `src/Mnemosyne.NET/PublicAPI.Unshipped.txt` and the shipped types before writing docs; document only names that exist.
- The sample needs no database, no model and no key, and exits 1 on a wrong receipt.
- The docs build used by CI must pass, links included.
- Docs follow the surrounding pages in tone and structure; no marketing words.

## Review Focus

- Every code snippet in the docs compiles against the shipped API.
- The sample's thresholds have margin, a fixed seed and no clock.
- The CI step for the sample has no database step.
- The telemetry page lists all three tags with their meaning and says they carry counts only.

**Files:**
- Create: `samples/Mnemosyne.Samples.Variants/Mnemosyne.Samples.Variants.csproj`, `Program.cs`, `README.md`

- [x] **Step 1: Project.** Copy the csproj shape of `Mnemosyne.Samples.Evaluation`, referencing only Abstractions and Mnemosyne.NET and linking `../Shared/SampleRunner.cs`. Add it to the solution next to the others.
- [x] **Step 2: Program.** `SampleRunner.RunAsync` with a one-minute limit. Build candidates by hand with the public record types: an incumbent root (200 runs, 70% successes) and a child (no runs) of one lineage, plus an unrelated procedure. Three acts, printed as a walkthrough: (1) `ReasonletSelector` alone over 300 rounds, outcomes drawn at the true rates 0.7 and 0.9 with a fixed-seed `Random`, metrics updated each round: the child's pick count is checked to be 0 or tiny; (2) `VariantSelector` without exploration: one variant per lineage, the unrelated procedure still present; (3) `VariantSelector` with Thompson and a seed: the child is chosen in the first 20 rounds and in at least 60 of the last 100. Each check throws `SampleFailure` with a message that names the receipt.
- [x] **Step 3: README** in the pattern of the other samples (what it shows, how to run, no Docker).

- [x] **Step 5: Run it** and see it exit 0, then break one threshold temporarily to see it exit 1, and restore.
