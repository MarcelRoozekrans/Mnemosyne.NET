# Phase 3.1 Capture Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `ReasonletTranscript.ToCapture` turns a list of M.E.AI `ChatMessage`s into a `ReasonletCapture` whose graph is the tool shape of the last question's run, and `RememberAsync` stores it as a new Reasonlet, a new version or an execution.

**Architecture:** A pure static builder in the core `Mnemosyne.NET` package, with no DI and no storage call. `ToGraph` holds the shape rules. `ToCapture` adds the question, the answer and the caller's details. The skip reason is its own enum, not a `MnemosyneError`.

**Tech Stack:**
- .NET 10
- Microsoft.Extensions.AI.Abstractions 10.10.1
- ZeroAlloc.Results
- xunit v3
- PostgreSQL + pgvector for the integration test

**Spec:** `docs/superpowers/specs/2026-10-30-phase-3.1-capture-design.md`

## Global Constraints

- Namespace `Mnemosyne.NET`, in project `src/Mnemosyne.NET`. `Mnemosyne.NET.Abstractions` gains no reference to M.E.AI.
- `TranscriptSkipReason { NoQuestion = 1, NoToolCalls = 2 }`; 0 stays undefined.
- Node shape: `Id = "step-<n>"` (n from 1), `Type = "tool"`, `Tool = FunctionCallContent.Name`, `Name = null`, `Properties = { "mnemosyne.arguments": <JSON array of the sorted argument names> }`. The array is always present, and empty when a call has no arguments.
- Edges `step-n → step-n+1`, with no condition and no properties. `SchemaVersion = ReasonletGraph.CurrentSchemaVersion`, no graph properties.
- All string sorting and comparison is ordinal (`StringComparer.Ordinal`).
- Argument values, call ids, message ids and timestamps never reach the graph.
- Null `messages`, `details` or message element throws `ArgumentNullException`. The builder does not call `Validate()`.
- Must stay Native AOT and trim clean. Build the JSON array without reflection: `JsonSerializer` with a source-generated context, or parse a string built by hand with `JsonDocument`. Do not use the reflection-based `JsonSerializer.SerializeToElement(object)`.
- Commits: conventional, `feat:`/`test:`/`docs:`. No Claude trailer or session link. No nested parentheses in commit bodies. Footer lines no longer than 100 characters.

## Review Focus

1. **A tool message holding results for calls from an earlier turn, before the question.** Only calls in the run count, so such a result must not satisfy a call. Covered in Task 1: `CallsBeforeTheQuestionAreIgnored`.
2. **A user message with non-text content only, such as an image, after a text question.** `Text` is blank, so the earlier text message stays the question. Covered in Task 2: `AUserMessageWithoutTextIsNotTheQuestion`.
3. **A tool name that differs only in case** (`Search` and `search`). With ordinal comparison these are different tools and must not collapse. Covered in Task 1: `ToolNamesDifferingInCaseStaySeparate`.
4. **More than 500 successful distinct steps.** The builder returns the graph, and `RememberAsync` rejects it with `Validation`; nothing throws. Covered in Task 1: `AnOversizedRunStillBuildsAndFailsValidation`.
5. **A multi-modal assistant message holding both text and calls.** The calls count, and the text is a candidate answer. Covered in Task 2: `AnAssistantMessageWithTextAndCallsGivesBoth`.

### Task 1: Types and the tool-shape graph

**Files:**
- Create: `src/Mnemosyne.NET/TranscriptSkipReason.cs`
- Create: `src/Mnemosyne.NET/ReasonletTranscript.cs`, with `ToGraph` only in this task
- Test: `tests/Mnemosyne.NET.Tests/Core/ReasonletTranscriptGraphTests.cs`

**Interfaces:**
- Produces: `public enum TranscriptSkipReason { NoQuestion = 1, NoToolCalls = 2 }` and `public static class ReasonletTranscript { public static Result<ReasonletGraph, TranscriptSkipReason> ToGraph(IEnumerable<ChatMessage> messages); }`.
- Also produces an `internal` helper that Task 2 reuses. It finds the index of the question message: the last `ChatRole.User` message whose `Text` is not blank, or -1 when there is none.

- [ ] **Step 1: Write the failing tests.** Build the messages with these helpers in the test class:
  - `User(text)` gives `new ChatMessage(ChatRole.User, text)`.
  - `Calls(params (string id, string name, string[] args)[])` gives an assistant message of `FunctionCallContent`s. Each argument value is a fresh `Guid`, so values differ per run.
  - `Results(params string[] ids)` gives a `ChatRole.Tool` message of `FunctionResultContent(id, "ok")`.
  - `Failed(id)` gives a tool message holding a `FunctionResultContent(id, null) { Exception = new InvalidOperationException() }`.

  The tests:
  - `ASingleCallBecomesOneToolStep`: user + call `orders.get(id)` + result. Asserts one node `{ Id = "step-1", Type = "tool", Tool = "orders.get", Name = null }`, its `mnemosyne.arguments` names `["id"]`, no edges, and `SchemaVersion == 1`.
  - `StepsChainInOrder`: A then B then C in three turns. Asserts the node ids are `step-1`..`step-3` with tools A, B, C, and the edges are exactly `step-1→step-2` and `step-2→step-3`, with null `Condition`.
  - `ArgumentNamesAreSortedAndValuesIgnored`: a call with args `{ "b", "a", "é" }` gives `["a","b","é"]`. Two transcripts with different values have equal `ComputeContentHash()`.
  - `NullArgumentsGiveAnEmptyArray`: `Arguments = null` gives `[]`.
  - `ParallelCallsAreSortedByToolThenArguments`: one assistant message `[z(x), a(y), a(x)]` gives tools `a, a, z` with arguments `[x], [y], [x]`. The hash equals the hash of the same calls listed in another order.
  - `ConsecutiveEqualStepsCollapse`: `search(q)` in three successive turns gives one node.
  - `CollapseHappensAfterTheParallelSort`: one message `[b(), a(), a()]` gives two nodes, `a` then `b`.
  - `NonConsecutiveRepeatsStaySeparate`: A, B, A gives three nodes.
  - `DifferentArgumentNamesStaySeparate`: `search(q)` then `search(q, page)` gives two nodes.
  - `ToolNamesDifferingInCaseStaySeparate`: `Search(q)` then `search(q)` gives two nodes.
  - `FailedAndUnansweredCallsAreLeftOut`: one call answered with an exception, one call never answered, one OK. The graph has only the OK call. A retry that failed and then succeeded hashes the same as a clean run.
  - `TheFirstResultForACallIdCounts`: the first result OK and a later one with an exception means the call counts. The first with an exception and a later OK means it does not.
  - `CallsBeforeTheQuestionAreIgnored`: call A and its result, then user Q2, then call B and its result. The graph has B only. Also: call A, then user Q2, then a result for A. The call is not in the run, so the run gives `NoToolCalls`.
  - `NoUserTextGivesNoQuestion`: an empty list, only assistant messages, or a user message with `"  "` gives `NoQuestion`.
  - `NoSuccessfulCallGivesNoToolCalls`: a user message alone, or a user message followed by text answers only, gives `NoToolCalls`.
  - `CallIdsAndMessageIdsDoNotReachTheHash`: two equal shapes with different call ids, `MessageId`s and `CreatedAt` have equal hashes. Changing one tool name changes the hash.
  - `AnOversizedRunStillBuildsAndFailsValidation`: 501 calls with distinct names `t0`..`t500` give a successful `ToGraph` with 501 nodes, and `graph.Validate()` is a failure. Neither call throws.
  - `NullArgumentsThrow`: a null `messages`, or a list containing null, throws `ArgumentNullException`.

- [ ] **Step 3: Implement `TranscriptSkipReason` and `ReasonletTranscript.ToGraph`.** Follow the spec's "Transcript rules":
  - Materialize the messages once. Find the question index, then scan only the messages after it.
  - Record the first `FunctionResultContent` per `CallId` from any message in the run, and treat it as OK when `Exception` is null.
  - Collect each assistant message's successful calls as `(name, sortedArgs)`. Sort them within the message by name, then by the args compared element by element (ordinal, a shorter prefix first), and append them.
  - Collapse consecutive equal steps, then number the nodes and chain the edges.
  - Write XML docs for every public member: the rules, that values are never read, and that `RememberAsync` does the validation.

- Produces: `public sealed record TranscriptCaptureDetails { required ReasonletScope Scope; required ReasonletProvenance Provenance; required ReasonletOutcome Outcome; ReasonletId? ParentId; string? Intent; string? Name; }`. All members are init-only, with XML docs, and the record is marked init-only so later phases can add members, like `ReasonletProvenance`. Also produces `public static Result<ReasonletCapture, TranscriptSkipReason> ToCapture(IEnumerable<ChatMessage> messages, TranscriptCaptureDetails details)`.

- [ ] **Step 1: Write the failing tests.**
  - `TheCaptureCarriesTheQuestionAnswerGraphAndDetails`: the transcript is user `"Refund order 7"`, a call with its result, then assistant `"Refunded."`. The details set every member, including `ParentId`, `Intent` and `Name`. Asserts:
    - `Question == "Refund order 7"` and `Answer == "Refunded."`;
    - `Graph` hashes equal to `ToGraph(sameMessages).Value`;
    - `Scope`, `Provenance`, `Outcome`, `ParentId`, `Intent` and `Name` all equal the details;
    - `capture.Validate().IsSuccess`.
  - `TheAnswerIsTheLastNonBlankAssistantTextOfTheRun`: in the run, assistant `"thinking"`, then a call, then a result, then assistant `"done"`, then assistant `"  "`. The answer is `"done"`.
  - `WithoutAssistantTextTheAnswerIsNull`: the run has calls and results only.
  - `AssistantTextBeforeTheQuestionIsNotTheAnswer`: assistant `"old"`, then the user question, then calls with no text. The answer is null.
  - `AUserMessageWithoutTextIsNotTheQuestion`: user `"Q"`, then a call with its result, then a user message holding only `DataContent` (an image). The question is `"Q"` and the graph has the call.
  - `AnAssistantMessageWithTextAndCallsGivesBoth`: one assistant message with `TextContent("on it")` plus a call, then a result. The graph has the call and the answer is `"on it"`.
  - `SkipsPassThrough`: `NoQuestion` and `NoToolCalls` transcripts give `ToCapture` failures with the same reasons.
  - `TheAnswerStaysRedactedInToString`: `capture.ToString()` does not contain the answer text.
  - `NullDetailsThrow`: `ArgumentNullException`.
