# Phase 1.2 Abstractions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `Mnemosyne.NET.Abstractions` holds the public contract: typed IDs, errors, every record with recursive validation, the minimal graph types, the `IReasonletMemory` facade, and the `IReasonletStore`, `IReasonletSelector` and `IIntentExtractor` ports.

**Architecture:** This phase adds types only. Records validate themselves through an instance method `Validate()` that returns `UnitResult<MnemosyneError>`. A small internal helper builds `Validation` errors that carry a field path, such as `Outcome.Score`, so nested records report where they failed. There is no implementation behind the interfaces yet, and no JSON.

**Tech Stack:** .NET 10, C# records, `ZeroAlloc.Results` 1.4.4 (`Result<T, E>`, `UnitResult<E>`, `.Success(...)`, `.Failure(e)`, `IsSuccess`, `IsFailure`, `Error`, and implicit conversion from `E`), xunit v3.

**Spec:** `docs/superpowers/specs/2026-10-22-phase-1.2-abstractions-design.md`

## Global Constraints

- Namespace: `Mnemosyne.NET.Abstractions`. Folders `Ids/`, `Records/`, `Graph/` and `Ports/` hold the files, but **one namespace** holds the types; folders are for organisation only.
- One public type per file. Every public type and member has an XML doc comment. Set `GenerateDocumentationFile=true` on the Abstractions project so a missing comment fails the build, since warnings are errors.
- Async members return `ValueTask<Result<T, MnemosyneError>>` or `ValueTask<UnitResult<MnemosyneError>>`. Every async member ends with `CancellationToken ct`, with no default value.
- `MnemosyneErrorCode` is exactly `Validation`, `NotFound`, `Conflict`, `Unavailable`. Its doc comments use the spec's definitions. `NotFound` includes "exists in another scope".
- Ranges: `Score`, feedback values, intent confidence and every `ReasonletScore` component are in `[0, 1]`. `ReasonletQuery.Top` is in `[1, 50]` with default `3`. `Duration` is at least zero. `SchemaVersion` is at least 1.
- Abstractions references `ZeroAlloc.Results` only. It has **no** `Microsoft.Extensions.AI` reference, and embeddings are `ReadOnlyMemory<float>`.
- No `==` reliance on records that hold collections. No JSON in this phase.
- The AOT gate from phase 1.1 must stay green.

## Review Focus

1. **NaN and infinity:** a `double` range check written as `x < 0 || x > 1` lets `NaN` through. Every range check must reject `NaN` and infinities. Task 2 tests this.
2. **`default` structs slipping through:** `default(ReasonletScope)` has a null `Value`, and `default(ReasonletId)` is `Guid.Empty`. Validation must reject both without throwing. Tasks 1 and 2 test this.
3. **Null where non-nullable is declared:** a caller using `!` or deserialization can pass null into a non-nullable `string` or list. `Validate()` must return a `Validation` error, never throw `NullReferenceException`. Tasks 2 to 4 test this.
4. **Error paths:** a nested failure must name its full path, such as `Outcome.Score`, not just `Score`, so a caller can find it. Task 4 tests this through `ReasonletCapture`.
5. **First error only:** `Validate()` returns the first failure in declaration order. Tests assert which field is reported when two are wrong, so the order is stable. Task 4 tests this.

### Task 5: Facade and ports

**Files:**
- Create: `src/Mnemosyne.NET.Abstractions/IReasonletMemory.cs`, `Ports/IReasonletStore.cs`, `Ports/IReasonletSelector.cs`, `Ports/IIntentExtractor.cs`, `Ports/ReasonletStoreEntry.cs`
- Modify: `src/Mnemosyne.NET.Abstractions/README.md`
- Test: `tests/Mnemosyne.NET.Tests/Abstractions/ContractShapeTests.cs`

**Interfaces:**
- Consumes: all the earlier types.
- Produces:
  - `IReasonletMemory`, with the five members exactly as listed in the spec's "caller-facing facade" code block. Each member's doc comment states:
    - its error codes;
    - for `RememberAsync`, the three-way `ParentId` table;
    - for `EraseAsync`, that it returns the number of Reasonlets removed.
  - `sealed record ReasonletStoreEntry(ReasonletCapture Capture, string Intent, string Name, ReadOnlyMemory<float> Embedding)` is the store's input for an atomic remember: the capture plus the resolved intent, the resolved name and the embedding.
  - `IReasonletStore` has these members:
    - `RememberAsync(ReasonletStoreEntry entry, CancellationToken ct)` returns `Result<ReasonletReceipt, MnemosyneError>`. Its doc comment says the store makes the three-way decision atomically.
    - `GetAsync(ReasonletScope scope, ReasonletId id, CancellationToken ct)` returns `Result<ReasonletDefinition, MnemosyneError>`.
    - `AppendExecutionAsync(ReasonletScope scope, ReasonletId id, ReasonletOutcome outcome, ReasonletProvenance provenance, CancellationToken ct)` returns `Result<ExecutionId, MnemosyneError>`.
    - `AppendFeedbackAsync(ReasonletScope scope, ExecutionId execution, ReasonletFeedback feedback, CancellationToken ct)` returns `UnitResult<MnemosyneError>`.
    - `SearchAsync(ReasonletScope scope, ReadOnlyMemory<float> embedding, string? intent, int limit, CancellationToken ct)` returns `Result<IReadOnlyList<ReasonletCandidate>, MnemosyneError>`.
    - `EraseAsync(ReasonletErasure erasure, CancellationToken ct)` returns `Result<int, MnemosyneError>`.
  - `IReasonletSelector`: `RankAsync(ReasonletQuery query, IReadOnlyList<ReasonletCandidate> candidates, CancellationToken ct)` returns `Result<IReadOnlyList<ReasonletMatch>, MnemosyneError>`.
  - `IIntentExtractor`: `ExtractAsync(string question, CancellationToken ct)` returns `Result<ReasonletIntent, MnemosyneError>`.
