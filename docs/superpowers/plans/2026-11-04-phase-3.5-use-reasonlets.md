# Phase 3.5 UseReasonlets Middleware and find_procedure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `builder.UseReasonlets()` recalls the best procedure for a new question and injects it as a system message, and hands every finished call to a background queue that captures its tool shape with `RememberAsync`. `find_procedure` is an `AIFunction` the model calls to look procedures up.

**Architecture:** `ReasonletChatClient : DelegatingChatClient` coordinates. Separate internal types do the rest: `ReasonletPromptFormatter` renders, `FindProcedureFunction` looks up, `ReasonletCaptureProcessor` turns one queued call into a capture, and `ReasonletCaptureQueue` with `ReasonletCaptureHostedService` runs the processor in the background. Everything lives in the core `Mnemosyne.NET` package.

### Task 2: Prompt formatter

**Files:**
- Create: `src/Mnemosyne.NET/ReasonletPromptFormatter.cs`
- Test: `tests/Mnemosyne.NET.Tests/Chat/ReasonletPromptFormatterTests.cs`

**Interfaces:**

- Produces:
  - `ReasonletPromptFormatter.Format(ReasonletMatch) : string`;

  - `internal readonly record struct Step(string Label, IReadOnlyList<string>? Arguments)`.
- Task 3 reuses `Steps` for the tool's JSON.

The fixed text is three header lines, then one line per step. `{similarity}` is formatted `F2` and `{rate}` `P0`, both under `CultureInfo.InvariantCulture`:

```text
A procedure that worked for a similar question before. It is a suggestion: follow it only where it fits.
Name: {Name} · match {similarity} · success {rate} over {runs} runs
{n}. {label} ({arg1}, {arg2})
```

- **Label:** a step's label is `Tool ?? Name ?? Type`.
- **Arguments:** they come from the `mnemosyne.arguments` property when it is a JSON array of strings. With that property missing or of another kind, the step line has no parenthesised part. With an empty array, it ends in `()`.
- **Order:** take nodes in topological order. Of the nodes that are ready, take the one with the smallest id first, by ordinal comparison.
- **Cycles:** a graph with a cycle never passes `ReasonletGraph.Validate`, so it never reaches the formatter. `Steps` throws `InvalidOperationException` if it sees one.

### Task 3: find_procedure

**Files:**
- Create: `src/Mnemosyne.NET/FindProcedureFunction.cs`, `src/Mnemosyne.NET/ReasonletTools.cs`, `src/Mnemosyne.NET/FindProcedureJsonContext.cs`
- Test: `tests/Mnemosyne.NET.Tests/Chat/FindProcedureFunctionTests.cs`, with a hand-written `FakeReasonletMemory : IReasonletMemory` in `tests/Mnemosyne.NET.Tests/Chat/FakeReasonletMemory.cs`. The fake records every `ReasonletQuery` and `ReasonletCapture`, and replies with configured results or a configured exception. Later tasks reuse it.

**Interfaces:**
- Consumes: `ReasonletPromptFormatter.Steps` (Task 2), `IReasonletMemory.RecallAsync`.
- Produces:
  - `internal sealed class FindProcedureFunction : AIFunction`, with constructor `(IReasonletMemory memory, ReasonletScope scope)`;
  - `internal IReadOnlyList<IReadOnlyList<ReasonletMatch>> Lookups`, a snapshot in call order, backed by a `ConcurrentQueue`;
  - `ReasonletTools.CreateFindProcedure`, which returns a new `FindProcedureFunction`.

The schema is a literal `JsonElement`, parsed once into a static field:

```json
{"type":"object","properties":{"question":{"type":"string","description":"The question or task to find a procedure for."},"top":{"type":"integer","minimum":1,"maximum":5,"description":"How many procedures to return. Defaults to 3."}},"required":["question"],"additionalProperties":false}
```

**Behaviour:**
- **Description:** "Looks up procedures that worked before for a similar question. Each has the tools it called, in order, with their argument names."
- **Recall query:** `InvokeCoreAsync` reads `question` and `top` from `AIFunctionArguments`. A value may arrive as a `JsonElement` or as a CLR value. It calls `RecallAsync(new ReasonletQuery { Scope, Question, Top })`.
- **Result:** a `JsonElement` array serialized with `FindProcedureJsonContext`. Each item is `{ id, name, intent, version, similarity, successRate, runs, steps: [{ tool, arguments }] }`. `tool` is the step label, and `arguments` is `[]` when the step has none.
- **Bad arguments:** a missing or blank `question`, or a `top` outside 1 to 5 or not an integer, returns `{"error":"invalid_arguments"}`. Nothing is recalled.
- **Failures:** an error result or an exception other than `OperationCanceledException` returns `{"error":"unavailable"}`. Cancellation propagates.
- **Recording:** each successful recall appends its matches to `Lookups`, including empty lists.

### Task 5: Capture queue, hosted service and registration

**Model:** opus. The reader lifecycle, drain-on-stop and drain-on-dispose race each other.

**Files:**
- Create: `src/Mnemosyne.NET/ReasonletCaptureQueue.cs`, `src/Mnemosyne.NET/ReasonletCaptureHostedService.cs`
- Modify: `src/Mnemosyne.NET/ServiceCollectionExtensions.cs`
- Test: `tests/Mnemosyne.NET.Tests/Chat/ReasonletCaptureQueueTests.cs`, `tests/Mnemosyne.NET.Tests/Chat/CaptureRegistrationTests.cs`

**Interfaces:**
- Consumes: `ReasonletCaptureProcessor` and `ReasonletCaptureItem` (Task 4), `ReasonletCaptureOptions` (Task 1), `CaptureTelemetry.Queue` (Task 4).
- Produces:
  - `internal sealed class ReasonletCaptureQueue : IAsyncDisposable`, with constructor `(ReasonletCaptureProcessor processor, ReasonletCaptureOptions options)`;
  - `bool TryEnqueue(ReasonletCaptureItem item)`;
  - `Task DrainAsync(CancellationToken ct)`;
  - `ValueTask DisposeAsync()`;
  - `internal sealed class ReasonletCaptureHostedService(ReasonletCaptureQueue queue) : IHostedService`.

**Behaviour:**
- **Channel:** `Channel.CreateBounded<ReasonletCaptureItem>` with `Capacity`, `SingleReader = true` and `FullMode = Wait`.
- **Enqueue:** `TryEnqueue` uses `Writer.TryWrite`.
  - A full channel returns false and counts `dropped_full`.
  - A completed writer returns false and counts `dropped_shutdown`.
  - A successful write counts `enqueued`.
- **Reader:** the reader task starts on the first successful `TryEnqueue`, at most once, guarded by `Interlocked`. It calls `ProcessAsync` for one item at a time with the queue's own stop token.
- **Drain:** `DrainAsync` completes the writer and waits for the reader.
  - When `ct` fires first, it cancels the reader's token.
  - Items left unprocessed are counted `dropped_shutdown`.
  - An item already in `ProcessAsync` is cancelled.
- **Stop and dispose:** `StartAsync` does nothing. `StopAsync(ct)` calls `DrainAsync(ct)`. `DisposeAsync` calls `DrainAsync` with a token that `DrainTimeout` cancels.
- **Idempotence:** a second drain, from either path, returns at once.
- **Registration:** `AddReasonletCapture` validates the options and throws `ArgumentException` like `AddMnemosyne`. It then registers:
  - the options, as a singleton;
  - the processor, as a singleton built from `IReasonletMemory` and the options;
  - the queue, as a singleton;
  - `AddHostedService<ReasonletCaptureHostedService>()`, through `TryAddEnumerable`, so a second call does not add a second hosted service.

### Task 6: ReasonletChatClient and UseReasonlets

**Model:** opus. This task coordinates recall, the tool, cloning and the hand-off, and its many skip paths must each leave the chat call untouched.

**Files:**
- Create: `src/Mnemosyne.NET/ReasonletChatClient.cs`, `src/Mnemosyne.NET/ReasonletChatClientBuilderExtensions.cs`, `src/Mnemosyne.NET/ChatTelemetry.cs`
- Test: `tests/Mnemosyne.NET.Tests/Chat/ReasonletChatClientTests.cs`, `tests/Mnemosyne.NET.Tests/Chat/ChatTelemetryTests.cs`, `tests/Mnemosyne.NET.Tests/Chat/UseReasonletsTests.cs`

**Interfaces:**
- Consumes:
  - Task 1: `ReasonletChatOptions` and `GetReasonletScope`;
  - Task 2: `ReasonletPromptFormatter.Format`;
  - Task 3: `FindProcedureFunction` and `Lookups`;
  - Task 4: `ReasonletCaptureItem`;
  - Task 5: `ReasonletCaptureQueue.TryEnqueue`;
  - `TimeProvider`.
- Produces: `internal sealed class ReasonletChatClient(IChatClient inner, IReasonletMemory memory, ReasonletCaptureQueue? queue, ReasonletChatOptions options, TimeProvider time) : DelegatingChatClient`, with `GetResponseAsync`. Task 7 adds streaming. `UseReasonlets` comes from Global Constraints.

**Behaviour, from the spec's call steps 1 to 7:**
- **New question:** the last request message is `ChatRole.User` with non-blank `Text`.
- **Recall:**
  - The query is `new ReasonletQuery { Scope, Question = last.Text, Top = 1, MinSimilarity = options.MinSimilarity }`.
  - It runs under a linked token that `RecallTimeout` cancels, on the `TimeProvider`.
  - The caller's own cancellation rethrows.
  - A timeout is counted `timeout`. An error result is counted by its code name, an exception as `exception`, and an empty result as `no_match`.
- **Inject:**
  - The text is `options.Formatter ?? ReasonletPromptFormatter.Format`. A formatter that throws, or returns a blank string, is counted `formatter_failed`, and nothing is injected.
  - The system message goes at the index of the first message that is not `System`, in a new list.
  - A successful inject is counted `injected`.
- **Tool:** when `ExposeFindProcedure` is on, add `new FindProcedureFunction(memory, scope)` to a new tool list on the clone. Skip this when a tool named `find_procedure` is already there.
- **Hand-off:**
  - It happens when `Capture` is on and the inner call returned.
  - `Messages` are the caller's messages without the inject, then `response.Messages`.
  - `InjectedParent` is the injected match's id. `Lookups` are the per-call function's lookups, or empty.
  - `Duration` comes from `time.GetElapsedTime`. `ResponseId` is `response.ResponseId`, and `FinishReason` is `response.FinishReason`.
  - A false return from `TryEnqueue` is already counted by the queue.
