# Phase 1.5 Telemetry and Retention Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The PostgreSQL store emits OpenTelemetry signals for every operation, and gets a host-run `PruneAsync`. It deletes old run records and fully idle lineages, and leaves the run counters exact.

**Architecture:**
- **Metrics.** `reasonlet_metrics` gains `last_executed_at`, and erase subtracts the runs it removes instead of recounting them.
- **Pruning.** `PruneAsync` reads the database clock once, then works in batches of at most 1,000 rows, one READ COMMITTED transaction each:
  - first the old run records;
  - then the runs of idle Reasonlets;
  - then the idle Reasonlets themselves, deepest first, re-checked after their locks.
- **Telemetry.** An internal `StoreTelemetry` holds one `ActivitySource` and one `Meter` named `Mnemosyne.NET`, and wraps each public store member.

**Tech Stack:**
- .NET 10.
- `System.Diagnostics.DiagnosticSource`, which is in-box, so there's no new package.
- ZeroAlloc.ORM 2.7.0, AdoNet.Async 1.4.0 and Npgsql 10.0.3.
- Testcontainers with `pgvector/pgvector:pg17`.
- xunit v3.

**Spec:** `docs/superpowers/specs/2026-10-22-phase-1.5-telemetry-retention-design.md`

## Global Constraints

- **House style is unchanged from phase 1.4:**
  - members return `ValueTask<Result<T, MnemosyneError>>`;
  - `ct` comes last and has no default;
  - cancellation throws;
  - expected failures come back as results, and bugs throw;
  - every public type and member has XML docs, and warnings are errors.
- **Public API added by this phase, and nothing else:**
  - `MnemosyneTelemetry`, holding `ActivitySourceName` and `MeterName`, both `"Mnemosyne.NET"`;
  - `ReasonletRetention`;
  - `ReasonletPruneResult`;
  - `IReasonletStore.PruneAsync`.

  All of these are in namespace `Mnemosyne.NET.Abstractions`. Everything new in PostgreSql is `internal`.
- **Times** come from the database clock only. A prune reads `now()` once, and every cutoff of that prune is derived from it.
- **Batch bound:** the internal constant `PruneBatchSize = 1000`. No prune transaction deletes more than 1,000 executions or more than 1,000 Reasonlets.
- **Prune retries:** a batch that throws `40001` or `40P01` is retried up to 3 times. After that, and on any other mapped failure, the prune returns the error.
- **Telemetry names** are copied verbatim from the spec's Activities and Metrics tables. No signal carries scope, subject, question, intent, name, graph, tags or run id.
- **Tests that prune every scope** must use `PgVectorFixture.CreateEmptyDatabaseAsync`. The shared database holds other tests' scopes, which run in parallel.
- **Commits:**
  - conventional commits, with `feat:`, `test:` and `docs:` as they fit;
  - never `fix:` for unshipped code;
  - each ends with a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`;
  - no nested parentheses in a commit body.
- **Coverage** stays at 100% line and branch for both test projects. Check it locally before reporting:

  ```
  dotnet test tests/Mnemosyne.NET.Tests -c Release -- --coverage --coverage-output-format cobertura --coverage-settings $PWD/coverage.config.xml
  ```

  Run the same command for `tests/Mnemosyne.NET.PostgreSql.Tests`.

## Review Focus

1. **The prune re-check race.** A Reasonlet executed, or given a new version, after the idle select but before the batch's locks must survive, and must not be counted. Task 3 tests this, with a hand-held lock that holds the batch between its select and its lock.
2. **Counters after pruning, then erasing.**
   - Setup: prune old runs, then subject-erase on a kept Reasonlet.
   - Expect: `runs` equals the original total minus the erased runs. `last_executed_at` stays non-null even when no run is left.
   - Task 1 tests the erase side. Task 2 tests the prune-then-erase sequence.
3. **A large idle lineage.** A chain of 2,500 idle versions prunes completely across batches. Every intermediate state has no row whose parent was deleted. Task 3 tests this.
4. **An all-scope prune leaves a live lineage alone.** One branch of a tree is idle and the other is used. Only the idle branch goes, and the shared ancestor stays. Task 3 tests this.
5. **Telemetry when nothing listens.** With no listener attached, every operation still works and no activity is created. Task 4 tests this.

### Task 3: Idle-lineage pruning

**Files:**
- Modify:
  - `Repositories/RetentionRepository.cs`;
  - `ReasonletPostgreSqlStore.cs`;
  - `tests/Mnemosyne.NET.PostgreSql.Tests/PruneTests.cs`.

**Interfaces:**
- Consumes:
  - `RunPruneBatchAsync`, `PruneProgress` and `PruneBatchSizeOverride` from Task 2;
  - the indexes from Task 1.
- Produces (on `RetentionRepository`):
  - `DeleteIdleExecutionsAsync(string? scope, DateTime cutoff, int batchSize, IAsyncDbTransaction, CancellationToken) : Task<int>`. It deletes up to `batchSize` executions of idle Reasonlets, in id order `FOR UPDATE`, without touching metrics.
  - `LockIdleReasonletsAsync(string? scope, DateTime cutoff, int batchSize, IAsyncDbTransaction, CancellationToken) : Task<Guid[]>`. It locks up to `batchSize` idle Reasonlets `FOR UPDATE`, ordered by depth below their lineage top descending, then `(scope, id)`. Then, in the same statement, it locks their metrics rows ordered by `reasonlet_id`. It answers the locked ids.
  - `DeleteStillIdleAsync(Guid[] lockedIds, DateTime cutoff, IAsyncDbTransaction, CancellationToken) : Task<IdlePruneRow?>`. It re-evaluates "idle" in a fresh statement and deletes only the still-idle locked rows, together with their executions. It answers `(int Reasonlets, int Executions)`.
  - `internal sealed record IdlePruneRow(int Reasonlets, int Executions)` in `Rows/`.

**What "idle" means in SQL.** The tests don't determine this, so here it is spelled out:
- A Reasonlet is **used** when its `created_at >= @cutoff`, or its metrics row's `last_executed_at >= @cutoff`.
- **Used closure:** the used rows, plus every ancestor of a used row. This is a walk up `parent_id` with `UNION`, in the `LATERAL … LIMIT 1` probe form of phase 1.4's walks, so it stays linear.
- **Idle:** the rows of the scope, or of every scope when `@scope` is null, that are not in the used closure.
- **Why one batch never orphans a child:** every child of an idle row is idle. Ordering every idle row by depth descending, across lineages, means a batch that includes a row at depth k includes every idle row deeper than k. So it includes that row's children.
- **Depth** is depth below the lineage top, computed as in `LockForErasureAsync`, so prune and erase lock in the same direction.

**How `PruneAsync` uses them.**
- `cutoff = now - ReasonletsUnusedFor`.
- Run-record pruning from Task 2 happens first.
- Then, in batches:
  1. loop `DeleteIdleExecutionsAsync` until a batch deletes nothing;
  2. loop a batch of `LockIdleReasonletsAsync` followed by `DeleteStillIdleAsync`, until the lock answers no ids;
  3. add every committed batch to `PruneProgress`.
- If the re-check drops some rows from a batch, the loop still continues by the lock count. A dropped row is used now, so the next select won't return it.

### Task 4: Store telemetry

**Files:**
- Create:
  - `src/Mnemosyne.NET.Abstractions/MnemosyneTelemetry.cs`;

- Modify: `ReasonletPostgreSqlStore.cs`.

**Interfaces:**
- Consumes: `PruneProgress` from Task 2.
- Produces:
  - `public static class MnemosyneTelemetry { public const string ActivitySourceName = "Mnemosyne.NET"; public const string MeterName = "Mnemosyne.NET"; }`
  - `internal static class StoreTelemetry`. It holds a static `ActivitySource`, a `Meter` and the instruments named in the spec, plus this helper:

    ```csharp
    static async ValueTask<TResult> RunAsync<TResult>(
        string operation,
        Func<Activity?, ValueTask<TResult>> body,
        Func<TResult, MnemosyneErrorCode?> errorOf)
    ```

    The helper starts `mnemosyne.<operation>` and times the call with `Stopwatch.GetTimestamp`. Then:
    - on a failure result, it sets `error.type` and status Error;
    - on an exception, it calls `activity.AddException(ex)`, sets status Error, records outcome `exception` and rethrows;
    - it always records `mnemosyne.operations` and `mnemosyne.operation.duration`.

    `UnitResult` members are adapted with a `Func` that returns `IsFailure ? Error.Code : null`. The operation names are `migrate`, `remember`, `get`, `execution.append`, `feedback.append`, `search`, `erase` and `prune`.
- Every public store member's body becomes `StoreTelemetry.RunAsync(...)` around the existing code. Operation-specific tags and counters are set inside the body from the result:
  - remember: `mnemosyne.capture_kind`, the id, the version, and `mnemosyne.reasonlets.remembered`;
  - search: limit, returned and top similarity, plus the `mnemosyne.search.returned` histogram;
  - erase: `mnemosyne.erase.by` and the counts, plus the `erased` counters;
  - prune: the counts and the `pruned` counters, read from `PruneProgress` on success and on failure, so committed batches are always counted.
