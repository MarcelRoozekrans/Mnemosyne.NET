# Phase 2.1 Evaluator Contract and Feedback API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every run is judged by an optional `IReasonletEvaluator` inside the record call, a human's explicit `Worked` verdict overrides it, and the success counters always follow `feedback_worked ?? evaluated_success ?? agent_success`, enforced by the database.

**Architecture:**
- **Abstractions:** new contracts.
- **PostgreSQL:**
  - migration `0002` adds the verdict columns, the CHECK constraints and `schema_version`;
  - insert and feedback statements maintain the effective `success`;
  - feedback takes the lock order Reasonlet, execution, metrics.
- **Facade:** judges before storing, strips the answer, falls back to the agent's flag when the judge is unavailable, and emits `mnemosyne.evaluate`.

**Tech Stack:** .NET 10, ZeroAlloc.ORM 2.7.0, Npgsql 10.0.3, pgvector pg17, xunit v3.

**Spec:** `docs/superpowers/specs/2026-10-23-phase-2.1-evaluator-contract-design.md`

## Global Constraints

- **House style is unchanged:**
  - `ValueTask<Result<T, MnemosyneError>>`;
  - `ct` last, with no default;
  - cancellation throws;
  - expected failures are results, and bugs throw;
  - XML docs on every public member;
  - warnings are errors;
  - AOT-compatible.
- **Verdict rule:** effective success is `feedback_worked ?? evaluated_success ?? agent_success`. The source is `feedback`, `evaluator` or `agent`, in that precedence.
- **`ReasonletEvaluation(bool Success, double Score, string Evaluator)`:**
  - `Score` is in [0, 1];
  - `Evaluator` is non-blank, at most 100 characters.
- **Run text:** `ReasonletRun.Question` and `Answer`, and `ReasonletCapture.Answer`, are given together or not at all. Each is non-blank and at most 32,000 code points (`Check.MaxLength`).
- **The answer is never stored, never in an error, never in a signal.** `ReasonletStoreEntry.Validate` requires `Capture.Answer == null`.
- **Judge failures:**
  - Judge `Unavailable`, or a non-caller cancellation, which is a timeout: store with source `agent`.
  - Any other judge error code, or an invalid evaluation: throw `InvalidOperationException`.
  - Caller cancellation: propagates.
- **Feedback:**
  - `Worked = null` keeps an earlier verdict.
  - Feedback on an execution that is missing after the locks answers `NotFound`.
- **Lock order** for every writer: Reasonlets, then executions, then metrics.
- **Migration:** `0002_evaluation.sql` (new; never edit `0001`) records `schema_version = 2`. A database below version 2 answers `Unavailable` "schema not migrated: call MigrateAsync".
- **Commits:**
  - conventional commits, never `fix:`;
  - end with a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`;
  - no nested parentheses in a commit body.
- **Coverage:** 100% line and branch, merged across both test projects.

## Review Focus

1. **Counter exactness across every mutation kind.** Apply append, feedback flip, feedback replace, subject erase and prune in sequence on one Reasonlet. `successes` and `last_success_at` must match a model that keeps pruned history. Task 2.
2. **Feedback racing append, erase and prune.** No deadlock and exact counters. Task 2.
3. **Upgrading a phase 1.7 database.** Existing runs keep their success, and counters are unchanged. A new binary before migration answers `Unavailable`. Task 2.
4. **An answer sentinel never appears** in any column, error or signal. Tasks 3 and 4.
5. **A judge that is down never loses a run** or fails the agent's call. Task 3.
