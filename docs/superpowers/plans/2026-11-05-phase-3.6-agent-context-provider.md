# Phase 3.6 Agent Framework Context Provider Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Microsoft Agent Framework agent recalls, injects and captures Reasonlets through a `ReasonletContextProvider` in a new `Mnemosyne.NET.AgentFramework` package. On the way, #45 (parentless duplicates) and #47 (intent in `find_procedure` output) are fixed.

**Architecture:** The core package gets a small public API: a recall step (`ReasonletSuggestions`), a capture record and sink (`ReasonletRun`, `IReasonletCaptureSink`), and a public `find_procedure` function that reports its lookups. `UseReasonlets` is rebuilt on that API with no change in behaviour. The new package's provider is a thin `AIContextProvider` over the same API. The PostgreSQL store deduplicates parentless captures by content hash.

**Tech Stack:** .NET 10, Microsoft.Extensions.AI 10.11, Microsoft.Agents.AI.Abstractions 1.24.0 (floor), xunit.v3, Testcontainers PostgreSQL + pgvector, ZeroAlloc.ORM, native AOT.

**Spec:** `docs/superpowers/specs/2026-11-05-phase-3.6-agent-context-provider-design.md`

## Global Constraints

- Every `src/` project: `IsAotCompatible=true`, its own `<Description>`, in `Mnemosyne.NET.slnx`, rooted in the AOT smoke. `RepoConventionsTests` enforces all four.
- Targets net10.0 only, as `Directory.Build.props` sets.
- `Mnemosyne.NET.AgentFramework` references `Mnemosyne.NET` (project) and `Microsoft.Agents.AI.Abstractions` **1.24.0** only. No `Microsoft.Agents.AI` in `src/`. Tests may reference `Microsoft.Agents.AI` 1.24.0.
- Memory never breaks or slows a run. A recall failure, missing scope, full queue or failed capture is counted and the run goes on. Only the caller's own cancellation propagates.
- The suggestion goes in `AIContext.Instructions`, never in `AIContext.Messages`.
- No signal carries scope, subject, question, injected text, tool or argument names, or exception messages.
- Default `Source` values: `"mnemosyne.chat"` (existing `ReasonletCaptureOptions.Source`) and `"mnemosyne.agent"` (`ReasonletAgentOptions.Source`).
- Integration tag values: `mnemosyne.integration` = `"chat"` or `"agent"`.
- Default options: `Recall = true`, `Capture = true`, `ExposeFindProcedure = false`, `RecallTimeout = 5 s`, `MinSimilarity = null`.
- Tests: the repo refuses `dotnet test --filter`. Build, then run the test exe: `dotnet build tests/Mnemosyne.NET.Tests -c Debug && tests/Mnemosyne.NET.Tests/bin/Debug/net10.0/Mnemosyne.NET.Tests -class <FQN>`. The PostgreSQL tests are the same with `Mnemosyne.NET.PostgreSql.Tests` and need Docker.
- Commits are conventional and need no scope. Do not put nested parentheses in commit bodies.
- Push with an explicit refspec, because `push.default` is `upstream`: `git push origin feat/phase-3.6-agent-framework-context-provider:feat/phase-3.6-agent-framework-context-provider`.

## Review Focus

1. **A user message with no text.** An agent run whose last user message has only an image or a function-approval response must not recall. It counts `continuation` and is still captured. Owner: Task 6, test `RunWithoutUserTextIsNotRecalledForButIsCaptured`.
2. **Concurrent runs of one agent on different sessions.** Each run must get its own parent and its own `find_procedure` lookups, never the other run's. Owner: Task 7, test `ConcurrentRunsOnTwoSessionsKeepTheirOwnParents`.
3. **A host tool already named `find_procedure`.** The provider must not add a second tool with that name. Owner: Task 6, test `FindProcedureIsNotAddedWhenTheAgentHasOne`.
4. **Two parentless captures of one new shape at the same moment.** Exactly one row is inserted, and the other capture becomes an execution. Owner: Task 4, test `ConcurrentParentlessCapturesOfOneShapeInsertOnce`.
5. **A scope resolver that throws.** The run goes on as if there were no scope: counted as `exception`, not thrown. Owner: Task 6, test `ThrowingScopeResolverSkipsTheRun`.
